# 协作部署与跨端联调

> 2026-10-27 按当前客户端配置、Compose 与正式发布流程核对。任意两台可运行客户端的设备即可联调，不要求四台设备、同一账号或个人电脑和平板分工。本文替代早期 Windows 后端经 frp 转发的专用拓扑。

## 选择测试环境

| 环境 | API | 分享页面 | 注意事项 |
| --- | --- | --- | --- |
| 正式环境 | `https://api.flowmuse.cloud` | `https://app.flowmuse.cloud` | 使用独立测试笔记，不在生产库做迁移或故障注入 |
| 本机 Web | `http://127.0.0.1:48931` | `http://localhost:8080` | 固定端口，浏览器 origin 必须进入 allowed origins |
| 局域网设备 | 开发机可达的 LAN 地址与后端端口 | 可达的 Web 地址 | 将所有 loopback 地址替换为实际可达地址；扫码/麦克风等还受安全上下文限制 |

HTTPS 页面须连接 HTTPS API/WSS。生产环境使用受控反向代理，不把数据库、对象存储控制台、邮件测试箱或转发控制端口开放到公网。

## 后端

按 [服务端说明](../../FlowMuse-Server/README.md) 准备独立环境；首次复制 `.env.example`，已有配置不得覆盖。运行 `docker compose up -d --build` 后检查容器及 `/health`；HTTP 健康只证明进程可达，还需验证登录、存储与协作。

- `FLOWMUSE_ALLOWED_ORIGINS` 包含实际 Web origin（含协议、端口，无路径）。
- `FLOWMUSE_PUBLIC_APP_URL` 使用 Web 根地址，供验证邮件与分享回跳。
- 保留 Socket.IO WebSocket Upgrade 和必要的请求体/超时配置。
- 只有服务端或其配置变化才重建对应服务；纯客户端发布不重启 Go、PostgreSQL 或 MinIO，不清数据卷。

## 客户端

构建配置优先级为 dart-define → `assets/config/app.env` → 内置默认地址。每端都要核对 API 和分享地址；湿墨分层与实时墨迹 V2 默认开启，测试时显式写出便于对照。

```sh
cd FlowMuse-App
flutter run -d chrome --web-port=8080 --dart-define=FLOWMUSE_COLLAB_SERVER_URL=http://127.0.0.1:48931 --dart-define=FLOWMUSE_SHARE_ORIGIN=http://localhost:8080 --dart-define=FLOWMUSE_LAYERED_WET_INK=true --dart-define=FLOWMUSE_LIVE_INK_V2=true
```

真机把两个地址换成设备可达地址。发布构建使用 [客户端配方](../../FlowMuse-App/README.md#web-发布)，完整上传 Web 目录并保留路径路由回退与房间 fragment。原生包使用同组参数；覆盖安装前保存并退出笔记，保持包名、签名和原有数据，不用卸载或清数据规避安装失败。

## 固定验收步骤

1. 记录两端构建来源、系统/设备/笔型、网络及墨迹模式；区分本地卡顿与远端可见延迟。
2. 用新建空白笔记建房，另一端分别通过链接、二维码或邀请加入；核对分页、纸张与初始元素。系统相机打开 Web，App 内扫码留在当前支持的 App 流程。
3. 两端连续书写、长笔、擦除、撤销与重做，观察落笔中预览和终笔最终一致性；光标流畅不代表正文链路正常。
4. 验证不同尺寸的查看位置、跟随、手动退出与“一起看这里”；不改正文或强制拉动接收者。
5. 在独立测试环境验证断线重连、切房、房主移出/结束、后台恢复、快照失败与本地保存失败。旧房事件不能污染新会话，失败不丢草稿。
6. 对多页 PDF、大量笔迹及图片重复测试；关闭后重新进入核对内容。保留两端最终版本对照与可复现步骤。

## 排障与发布证据

依次检查版本/编译参数 → 账号会话 → API、CORS 与 WSS → 实时预览/可靠终笔 → 快照与本地保存。出现 unauthorized 先核对登录会话，出现确认超时先核对可靠消息与房间状态；不得因光标正常直接判定后端无问题。

重启后的短时改善不等于找到根因。使用同设备、网络与样本对照，记录实际延迟和积压；不把节流窗口、CPU 空闲率、构建成功或单元测试当作端到端性能。

发布记录应包含源提交、参数、产物哈希、已验证流程和未覆盖范围。保留必要的可核验回退版本，清除临时上传包，发布之后再确认公网资源与浏览器行为。文档维护本身不执行部署或实机验收。
