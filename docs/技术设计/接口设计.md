# 接口说明

后端服务地址按以下优先级读取：`--dart-define=FLOWMUSE_COLLAB_SERVER_URL` > `assets/config/app.env` > `CollaborationConfig.defaultServerUrl`。部署和测试不应在文档或代码中继续硬编码个人公网 IP；具体启动参数见根目录 README 和《四设备协作部署指南》。

## 账户认证

所有接口前缀 `/api/auth`,JSON body,需要登录的带 `Authorization: Bearer <token>`,超时 20 秒。

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/register` | 否 | body `{email, password, displayName}`,返回 `{user}` |
| POST | `/login` | 否 | body `{email, password}`,返回 `{token, user}` |
| POST | `/verify-email` | 否 | body `{token}`,返回 `{token, user}` |
| POST | `/resend-verification` | 否 | body `{email}` |
| GET | `/me` | 是 | 返回 `{user}`;401/403 时客户端清 token |
| PATCH | `/me` | 是 | body `{displayName}` |
| POST | `/me/avatar` | 是 | **原始字节**,Content-Type 是图片 mimeType,不是 JSON |
| POST | `/change-password` | 是 | body `{oldPassword, newPassword}`,成功后清 token |
| POST | `/request-password-reset` | 否 | body `{email}` |
| POST | `/reset-password` | 否 | body `{token, newPassword}`,成功后清 token |
| POST | `/logout` | 是 | 空 body,无论响应都清 token |

`user` 对象:`{id, email, displayName, avatarUrl, registeredAt, emailVerified, emailVerifiedAt, updatedAt}`。时间字段是毫秒时间戳。`avatarUrl` 不是 http 开头时客户端会拼成绝对地址。

token 存在 `flutter_secure_storage`,key `flowmuse.auth.token`。

## 协作房间 REST

鉴权同上。快照接口 15 秒超时,文件接口 20 秒。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/rooms` | 创建房间,body `{roomId, ownerKeyHash}` |
| POST | `/api/rooms/{roomId}/scene` | 创建加密快照,body `{sceneVersion, sceneHash, ownerKeyHash, encryptedBuffer, iv}`(base64) |
| GET | `/api/rooms/{roomId}/scene` | 取快照,返回同上结构 |
| PUT | `/api/rooms/{roomId}/scene` | 存快照,带乐观锁 `{baseSceneVersion, baseSceneHash, ...}`,冲突返回 **409** |
| GET | `/api/rooms/{roomId}/access` | 房间元信息 |
| POST | `/api/rooms/{roomId}/join` | 加入 |
| POST | `/api/rooms/{roomId}/end` | 结束(仅房主),body `{ownerKey}`,401/403 鉴权失败 |
| PUT | `/api/rooms/{roomId}/files/{fileId}` | 上传图片,`application/octet-stream`,单文件 10MB |
| GET | `/api/rooms/{roomId}/files/{fileId}` | 下载图片 |

HTTP 状态码:410 房间已结束,404 不存在,409 版本冲突。

## 协作 Socket.IO 协议

websocket 优先,polling 降级,自动重连。已登录用户用 `Authorization` header + auth token;游客用 query 带 guestName / guestAvatarUrl。

客户端发:

| 事件 | 载荷 |
|------|------|
| `join-room` | roomId(重连自动重发) |
| `server-broadcast` | `[roomId, {encryptedBuffer, iv}]` 持久化消息 |
| `server-volatile-broadcast` | `[roomId, {encryptedBuffer, iv}]` 易失(光标/在线状态,可丢) |
| `leave-room` | roomId |
| `end-room` | `{roomId, ownerKey}` |

客户端收:`init-room`、`first-in-room`、`new-user`、`room-user-change`、`room-error`、`room-ended`、`client-broadcast`(其他人的协作消息)。

业务消息解密后是 JSON `{type, payload}`:

| type | 用途 |
|------|------|
| `SCENE_INIT` | 全量场景(新成员加入时) |
| `SCENE_UPDATE` | 增量元素 |
| `MOUSE_LOCATION` | 光标和选区(易失) |
| `IDLE_STATUS` | 在线状态(易失) |
| `USER_VISIBLE_SCENE_BOUNDS` | 可视区域(易失) |

`elements` 是 Excalidraw 元素 JSON 数组。

三类易失消息(MOUSE_LOCATION / IDLE_STATUS / USER_VISIBLE_SCENE_BOUNDS)的解密正文带可选 `creatorKey`,客户端据此把光标、在线状态与远端湿墨关联到稳定创建者;旧客户端忽略该字段,服务端零改动。

SCENE_INIT / SCENE_UPDATE 的元素可在 `customData.flowMuse.collaborationOwner` 携带创建者元数据(v1:version/creatorKey/displayName/isGuest),仅用于显示,不参与权限与冲突仲裁。该字段只在协作密文与本地存储中保留,客户端导出外部 `.markdraw`/`.excalidraw`/`.json`、PNG/SVG 或分享文件时会剥离。

创建者聚焦不是 Socket.IO 协议字段：它由客户端页面本地维护，不写入 Scene、History、SQLite、快照或任何网络消息。聚焦渲染沿全局 z 序单遍执行，系统底图、网格、光标、选择框和本地编辑反馈不变淡；缺失 `creatorKey` 时客户端应禁用按作者聚焦或让远端湿墨全亮，不能按昵称猜测身份。

## 手写识别

POST `{serverUrl}/api/ink/recognize`,body 是 `{sessionId, hint:"auto", strokes:[{id, points:[{x,y,t?}]}], bounds:{x,y,width,height}}`。返回 `{elements:[{type, text?, latex?, x, y, width, height, points?}]}`。鸿蒙用 NativeHttpClient(8s 连接 / 15s 读取),其他平台用标准 http。无 token 可匿名调用。

## 智能排版 v3（独立识别 + 整页结构理解 + 确定性排版）

当前生产入口走 `RecognitionPipeline` → `RecognitionSemanticAdapter` →
`SmartLayoutRealCandidateChain.runFromSemanticAssembly`。旧版（V1/V2 模板卡片制）
链路已于 2026-09-21 整体删除：客户端模板引擎/草稿态与服务端
`/api/ink/smart-layout`、`/block`、`/compose`、`/vision`、`/transcribe` 端点
不复存在，工具栏智能排版按钮直接打开 V3 会话面板。

POST `/api/ink/smart-layout/recognize/v3`，服务端生产实现为 `internal/layoutrecognitionv3`。
外壳为 `schemaVersion: "recognition-v3/1"`、`stage: "read|verify|structure"`、
`operationId`、`requestId`、`pageId`、`sceneRevision`、`contentFingerprint`、`generation`；
响应身份与版本由服务端回填，客户端比对，取消或旧代次结果不应用。

1. **read/verify**：纯笔迹区域分批转写与必要复核；原生文字直接读取，图片不被转写成正文。
   沿用区域图片、逐源账本、同操作总调用预算与超时；未能安全识别的内容原样保留。
2. **structure**：请求携带 `units`、`textFingerprint` 及可选 `overviewPngBase64`。
   多段文字/图文页使用同轮内容概览（不含纸张/PDF 底图），数字 `[n]` 对应 `units[n-1]`；
   包含实际图片像素与完整已识别文本，正文不再截断到 80 字。概览长边 ≤2048px、总像素 ≤2MP、
   base64 ≤3MiB；沿用 units ≤128、单元 text ≤2000 字的准入上限，超限明确降级、不静默截文。
   单一文本/纯图片无额外结构请求，明确单列表可走本地快路径。
3. **结构响应**：`readingOrder`、`roles`、`listGroups`、`captions`、`warnings` 与 `textFingerprint`，
   只描述已有单元的角色、阅读顺序和关系，不返回或改写正文。图文语义关联按下面的可选能力协商。
4. **排版与应用**：完整文本与结构进入 `LayoutBlockAssembler`、现有组合/测量/放置与候选评分链；
   高置信图文关系变为 keepWith 原子组，正文不冒充图注；列表关联携带完整子树。
   审阅使用真实候选，用户确认才修改原稿；源守恒、compare-and-commit、单次撤销仍生效。

### 可选图文关联（2026-09-20）

structure 请求新增 `includeFigureTextLinks: true`，要求同时提供有效 `overviewPngBase64`。
响应可附加（空集可省略）：

```json
{"figureTextLinks":[{"textUnitId":"native:paragraph-1","figureUnitId":"native:image-1","confidence":0.95}]}
```

`textUnitId` 必须是 body/listItem 的文本单元，`figureUnitId` 必须是 figure；一文至多一图，
可一图多文，不能与 captions 重复。两端拒绝错误端点、重复、角色冲突、非 0–1 置信度和正文注入。
客户端只采用 confidence ≥0.8 的关联；该值是模型自评，**不代表实测准确率**。
关联到保留/锁定/缺失图片时不强制成组或换绑其他图片；无明确语义证据允许不关联。

旧客户端不发送该能力标记时，服务端不输出新字段，保持旧响应键集。部署顺序为**后端先、客户端后**；
当前仍是单页、已有块粒度，不增加图片内 OCR、跨页配对或块内拆分。structure 至多一个逻辑请求，
必要的网络重试仍计入原总预算；缺图时仅分析文本结构，失败/预算用尽时本地回退并说明降级。

### 可选整页构图提示（2026-09-21）

同一 structure 请求可发送 `includeCompositionHints: true`，与 `includeFigureTextLinks` 互斥；
响应必须含 `compositionHints`，不得再附旧 `figureTextLinks`。未协商客户端仍收到原键集。
双端 DTO/校验已支持，生产消费接线按语义构图计划 C 包推进。

```json
{"compositionHints":{"version":"composition-hints/1","pageIntent":"comparison","sections":[],"mediaGroups":[{"groupId":"m1","figureUnitIds":["f1","f2"],"textUnitIds":["t1"],"confidence":0.95}],"softLineBreaks":[{"unitId":"t1","newlineIndexes":[0],"confidence":0.95}]}}
```

- `pageIntent` 为 reading/comparison/mixed/unknown；仅候选优先提示，不给模型坐标控制权。
- `sections` 为一层 `{sectionId, headingUnitId, memberUnitIds}`，标题角色必须 title，成员有序且不交叉。
- mediaGroup 至少一图一正文/listItem，可多图共用一次正文；图注仍只由 captions 表达。成组后连同图注必须在阅读序中连续、不跨章节、不拆列表子树。一单元不得重复归组。
- 软换行只引用 ink 标题/普通正文/短图注中从 0 起的换行编号，不返回正文；原生 typed、空行分段、列表等不合并。编号递增、唯一、在原文范围内，客户端只消费高置信提示。
- 三个提示数组及原结构数组都必须存在，无值为 `[]`，`null`、正文偷渡、未知键、非法引用/置信度均拒绝。无概览时只能恢复文字结构，mediaGroups 必须为空。
- 不新增请求：旧服务端拒绝能力或结构非法时，本轮走本地结构降级，不另发旧模式结构请求。部署仍服务端先行。

`POST /api/ink/smart-layout/analyze/v3` 与 `internal/recognition/smart_layout_v3*.go`
仍是旧实验/协议代码，不是当前生产识别实现；`WithV3Analyzer` 未注入时实验路由不注册。

## AI 笔记助手

客户端直接 POST 用户配置的 OpenAI 兼容 `{baseUrl}/chat/completions`，请求携带 `Authorization: Bearer <apiKey>`、`model`、`messages`、`tools` 和 `tool_choice: auto`。使用 `auto` 是为了兼容不接受强制工具调用的思考模型，但提示词仍要求模型分类意图并据此返回动作：**生成型指令**（总结/待办/大纲/思维导图/整理/续写等）必须产出内容并返回 `insert_text`/`generate_mindmap`/`smart_layout`/`rename_note` 动作 draft（应用前用户确认）；**问答型指令**（解释/比较/点评等）只写 `message`，禁止调用任何工具；**无内容可生成时**（如笔记无待办可提取）只回复说明（"当前没有可生成待办的内容"），禁止返回任何动作，也不得把说明文案当作插入内容。用户填写完整 Chat Completions URL 时不再追加路径，模型必须返回标准 `choices[0].message.tool_calls`。

`tool` 仅允许 `rename_note`、`insert_text`、`generate_mindmap` 和 `smart_layout`。客户端限制指令 1000 字符、标题 100 字符、单段文本 5000 字符、上下文总量 30000 字符、动作数 5；未知动作、额外参数、空值和超长值均拒绝，动作必须经用户预览确认后才应用。面板还会对动作做一次"净化"（`sanitizeAiAgentActions`）：丢弃空值、与回复 message 同文的说明（防把致歉/说明误当内容）、与当前标题相同的重命名、空根导图；净化后动作为空则视为纯回复，不显示确认区。各端复用 `NativeHttpClient`，因此鸿蒙继续走原生 HTTP Platform Channel，其他端走标准 HTTP；Web 端还要求目标服务允许 CORS。

多模态请求：框选含笔迹/图片/PDF 页面时，选区经 `PngExporter` 渲染为 PNG（scale=2，最长边 ≤2048 等比缩放），以 `AiVisualAttachment` 携带（最多 3 张、单张 ≤4MiB、仅 image/png|jpeg）。user message 的 `content` 从字符串变为 `[{type:"text",...},{type:"image_url",image_url:{url:"data:image/png;base64,..."}}]` 数组；无附件时保持纯字符串不变。带附件遇 HTTP 400 时提示"模型可能不支持图片输入"。Repository 通过 `AiAgentHttpPost` typedef 注入 HTTP 实现，便于测试替换。

FlowMuse 实验室的“测试连接”会保存当前配置并发送一次最小 `insert_text` 工具调用，用于同时验证 URL、API Key、模型名称和 Function Calling 响应格式。

## 数据层接口

这层不逐个列了,代码里有完整定义。几个要点:

`LibraryRepository`(`features/library/repositories/library_repository.dart`)是资料库的接口,SQLite 实现。`loadIndex()` 一次性读全部,其余是 CRUD。对应的 `LibraryIndexNotifier`(provider `libraryIndexProvider`)是 AsyncNotifier,每个写方法调完 repository 会 `refresh()`。

`WhiteboardSceneRepository` 读写 `note_scenes` 表,内容是 Excalidraw JSON 字符串。

`CollaborationRepository` 是协作层的外观,组合了 transport + 加密 + 场景存储 + reconciler。对外暴露 `startNewRoom` / `joinRoom` / `broadcastScene` / `stopCollaboration` / `endRoom`,以及一堆 Stream(消息、成员变化、连接状态、错误)。

`LocalSettingsRepository` 是 `local_settings` 表的 key-value 包装,`readString` / `writeString` / `readBool` / `writeBool`。`RecentCoversRepository` 复用同一张表,key 形如 `recent_covers_notebooks`,value 是 JSON 数组。

## 通用约定

时间是毫秒时间戳。ID 生成:笔记本 `notebook-{uuid}`、标签 `tag-{uuid}`、房间 10 字节随机 hex、房间密钥 base64url 16 字节、PDF 图片 fileId `pdf-{sha1[:12]}`。颜色在 SQLite 里是 ARGB32 整数,在 JSON 里是 `#RRGGBB`。枚举存 `.name` 字符串。HTTP 非 2xx 抛 `StateError`。
