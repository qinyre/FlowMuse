# 数据模型

本地数据库 `flowmuse_local.db`,schema 版本 5,开 `PRAGMA foreign_keys = ON`。时间字段都是毫秒时间戳,枚举存 `.name` 字符串,颜色存 ARGB32 整数。

## 表结构

### notes

笔记主表。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | |
| title | TEXT NOT NULL | |
| updated_at | INTEGER NOT NULL | 毫秒 |
| kind | TEXT NOT NULL | `notes` / `pdf` |
| cover_color | INTEGER NOT NULL | ARGB32 |
| note_type | TEXT NOT NULL | `paged` / `unbounded` |
| page_template | TEXT NOT NULL | `blank` / `narrowLine` / `wideLine` / `grid` / `dotGrid` / `tianGrid` / `miGrid` / `narrowVerticalLine` / `wideVerticalLine` / `fourLineGrid` / `ancientBook` |
| page_flow | TEXT NOT NULL | `topToBottom` / `rightToLeft` |
| notebook_id | TEXT | FK → notebooks(id),ON DELETE SET NULL |
| subtitle | TEXT | |
| cover_thumbnail | BLOB | 封面缩略图 |
| deleted_at | INTEGER | 软删除,null = 未删除 |

索引:`notes_notebook_id_index`、`notes_deleted_at_index`。

### notebooks / tags

结构一样。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | `notebook-{uuid}` 或 `tag-{uuid}` |
| name | TEXT NOT NULL | |
| cover_color | INTEGER NOT NULL | |
| cover_image | TEXT | 封面图片路径 |
| created_at | INTEGER NOT NULL | |
| updated_at | INTEGER NOT NULL | |
| sort_order | INTEGER NOT NULL | |

### note_tags

多对多关联。

| 字段 | 说明 |
|------|------|
| note_id | FK → notes,ON DELETE CASCADE |
| tag_id | FK → tags,ON DELETE CASCADE |

复合主键 `(note_id, tag_id)`。索引 `note_tags_tag_id_index`。

### note_scenes

白板场景内容,Excalidraw JSON 字符串。由 `WhiteboardSceneRepository` 读写(`LibraryRepository` 不碰它)。

| 字段 | 类型 | 说明 |
|------|------|------|
| note_id | TEXT PK | FK → notes,ON DELETE CASCADE |
| content | TEXT NOT NULL | Excalidraw JSON |
| updated_at | INTEGER NOT NULL | |

### local_settings

通用 key-value。

| 字段 | 类型 |
|------|------|
| key | TEXT PK |
| value | TEXT NOT NULL |
| updated_at | INTEGER NOT NULL |

布尔值存 `'true'` / `'false'`,列表存 JSON 字符串。已用的 key:`theme_preset`、`shell_sidebar_collapsed`、`flowmuse.guest.username.v3`、`whiteboard.inkRecognitionMode.<noteId>`、`recent_covers_<category>`。

## 级联规则

- 删笔记本 → 其下 notes 的 notebook_id 置 NULL
- 删标签 → 关联 note_tags 级联删
- 删笔记 → note_tags、note_scenes 级联删

## 迁移

`onCreate` / `onUpgrade` / `onOpen` 都调 `_ensureSchema`(全用 `CREATE TABLE IF NOT EXISTS`,幂等)。新增列必须用 `_safeAddColumn`(列已存在则 catch 跳过),**不能**裸 `ALTER TABLE ADD COLUMN`——之前因为这个导致老用户升级时白屏崩过。改 schema 要 bump `databaseVersion` 并在 `onUpgrade` 加 `if (oldVersion < N)` 分支。

## 领域模型

`NoteItem`(`library/models/note_item.dart`)是普通可变类,字段对应 notes 表加 `tagIds: List<String>`(从 note_tags join 来)。有 `isDeleted` getter 和带 `clearNotebook` / `clearDeletedAt` / `clearCoverThumbnail` 清零开关的 copyWith。

`LibraryNotebook` 和 `LibraryTag`(`library_collection.dart`)是 `@immutable`,字段就是上面那七个,结构完全一样。

`LibraryIndex`(`library_index.dart`)是聚合根,持有 notes / notebooks / tags 三个列表。`notesForQuery(query)` 在内存里按条件过滤排序——这是搜索的实际实现,不是 SQL。

## 编辑器元素

`editor_core` 里的 Element 基类(`core/elements/element.dart`)字段多,但关键的是这几个版本控制字段:`version`(每次更新 +1)、`versionNonce`(随机数,version 相同时做次级仲裁)、`seed`(手绘抖动种子,从 id 派生)、`index`(fractional index,z 序)、`updated`(毫秒)。

子类按 type 分:`rectangle` / `ellipse` / `diamond` / `line` / `arrow` / `text` / `freedraw` / `image` / `frame`。line 系列带 points 和箭头,arrow 额外有端点绑定,freedraw 带 pressures(text 有字体和对齐,image 有 fileId 和状态)。具体字段看代码,改的时候注意 Excalidraw 编解码要一致。

freedraw 的渲染语义存在 `customData.flowMuse.pressureEncoding = "1"` 标记(ADR-020):带标记的笔迹点序列压感已按创建时笔盒灵敏度烘焙(`MarkdrawController._encodeStrokePressure`),渲染端按全灵敏度重放;无标记的旧笔迹按各笔刷出厂默认灵敏度确定性渲染,不受客户端设置影响。该标记与 `brushType`/`pageId` 一样属 flowMuse 渲染元数据,随 Excalidraw 编解码往返,内部与协作数据保留(外部导出只剥 collaborationOwner)。freedraw 的 `points` 相对元素原点 `(x,y)`,渲染与 SVG 导出按 `points + (x,y)` 还原绝对坐标,可视边界经 `elementVisualBounds` 统一计算。

freedraw 另有渲染算法版本 `customData.flowMuse.brushRenderVersion = 2`(自然介质笔刷计划 T1):缺失或非法值一律按 v1(`classicV1`)解释,数值按 `value is num && value == 1/2` 判定以兼容 dart2js;v2 仅对 `pencil`/`brushPen` 有效,非法组合安全回退 v1(`effectiveBrushRenderVersion`)。新建 pencil/brushPen 笔迹默认写 2,其余笔不落字段;copy/duplicate 保留版本,导入旧数据不补写,修改已有元素不改版本。`.markdraw` 文本语法新增 `pressure-encoded`(仅 pressureEncoding==1 时写)与 `render=v2`(仅 v2 时写),缺失分别按 legacy/v1;解析遇到未知 `render=` 值经 ParseWarning 回退 v1 不抛整文档异常。协作 live ink 的 `LiveInkStyle` 新增可选 `renderVersion`(缺失=1,非法值拒绝该 chunk,v2+非自然介质笔形回退 1),不改 protocolVersion 外层结构,旧客户端忽略未知字段按 v1 预览。

Scene 持有不可变元素列表和图片文件 map,所有变更返回新 Scene。

## 协作相关

`CollaborationRoom {roomId, roomKey}`,链接格式 `{origin}{path}#room={roomId},{roomKey}`。`EncryptedPayload {encryptedBuffer, iv}`,AES-GCM 密文 + 12 字节 nonce。`CollaborationMessage` 解密后的明文,见 [接口设计](接口设计.md)。

元素归属是纯显示元数据:新建元素在 `customData.flowMuse.collaborationOwner` 下写 `{version, creatorKey, displayName, isGuest}`(登录用户 creatorKey 由 userId 哈希派生,游客为房间内会话 key),更新元素不改原作者,customData 深合并走 copy-on-write。值对象是 `CollaborationCreator`(`editor_core/src/core/elements/collaboration_element_owner.dart`),外部导出经 `core/serialization/external_export_sanitizer.dart` 剥离该字段,协作密文与本地存储保留。

聚焦目标(`creator(<creatorKey>)` 或 `history`)不属于领域模型，不写入 Scene、History、SQLite、快照或协作消息。它只由白板页面和 painter 持有；系统底图、网格、光标、选择框、本地活动笔迹及正在编辑的 overlay 不参与归属变淡。绑定文字继承父元素归属，缺少 creatorKey 的旧 presence 只允许降级显示，不按昵称猜测。

## 安全存储

安全存储使用鸿蒙兼容门面，保存 `flowmuse.auth.token`（账户 token）、`flowmuse.collaboration.ownerKey.{roomId}`（房主密钥）及 `flowmuse.social.v1.{SHA256([origin,userId])}.*`（当前设备索引、X25519 私钥、经手动核验的好友公钥）。这些不进 SQLite、备份导出或云端私聊。退出账号仅清理社交内存；显式撤销本机设备才删除其私钥。


## 服务端账号（PostgreSQL）

`users.id` 是邮箱和华为登录共享的业务身份。`email`（唯一）、`password_hash` 可空；新增 `huawei_union_id TEXT`，对非空值建唯一索引 `users_huawei_union_id_key`，由服务端核验授权码后写入。原邮箱账号的 ID、密码哈希、会话、房间归属不变；不生成虚假邮箱或默认密码。

`auth_email_tokens` 延续 `token_hash/user_id/purpose/expires_at/used_at/created_at`，新增 `target_email TEXT`、`verified_at TIMESTAMPTZ`、`session_id TEXT REFERENCES auth_sessions(id) ON DELETE CASCADE`。`purpose=bind_email` 与注册验证、密码重置分离。邮件仅标记申请已验证，最终完成时锁定用户、原会话和申请，在一个事务内写入邮箱、bcrypt 哈希并消费申请；所有权冲突不覆盖已有用户。

迁移由 `UserStore.EnsureSchema` 执行，使用 `ADD COLUMN IF NOT EXISTS`、`CREATE UNIQUE INDEX IF NOT EXISTS` 和幂等 `DROP NOT NULL`。空库、旧库升级及重复执行均有隔离 PostgreSQL 测试；本地 SQLite schema 版本仍为 5。本次变更不自动合并账号或同步本地笔记。

回退时必须使用兼容可空邮箱与密码的服务版本，不能把已存在纯华为用户的数据直接交给旧版非空 SQL 读取逻辑；不删除华为身份数据。

## 服务端好友与私聊（PostgreSQL，功能分支）

`internal/social/Store.EnsureSchema` 幂等新增 `users.friend_code`（12 位 Base32、非空唯一、首次读取时生成），以及申请额度字段 `social_request_day/social_requests_today`。后两者在用户行锁下计数，避免反复撤回申请绕过每日额度。

新增 `social_relationships`（规范排序用户对唯一、申请人/申请 ID、状态、版本）、`social_blocks`（定向屏蔽）、`direct_conversations`（固定两位参与者、last_seq 和双方 read_seq）与 `direct_messages`（文字、发送者/客户端 ID 唯一、会话内 seq 主键）。BIGINT 版本和游标在 JSON 中为十进制字符串。好友公开资料不包含邮箱、认证状态或华为标识，旧账号自动用邮箱作昵称时返回通用昵称。

设备与邀请迁移已实现：`users.social_keyset_version` 随设备登记/撤销单调递增，`social_devices` 保存不可覆盖的设备/密钥 ID、公钥、指纹、名称与撤销时间。每账号最多 5 台有效设备，每天最多登记 20 台；私钥不上服务器。

既有 `room_invites` 幂等扩展 `recipient_id/conversation_id/client_invite_id/status/version/accepted_at/joined_at/revoked_at/request_hash`，原无定向接收人的记录保留。发送者与 client ID 唯一，重试核对原请求摘要。`room_invite_envelopes` 按邀请/接收设备/密钥唯一，通过复合外键约束账号与设备归属；保存固定上下文、suite、enc 和 ciphertext，不含 roomKey/ownerKey。已加密信封不可覆盖，新设备通过补发追加。

`direct_messages` 支持 `kind=invitation` 与 `invite_id`；数据库 CHECK 保证文字与邀请载荷互斥，邀请及一张消息卡在同一事务落库，补发不重复插卡。接受、拒绝、撤销、房间结束/到期分别影响有效状态；joined 是成功加入后的客户端确认，并校验服务端成员记录，不授予角色。本地 SQLite 仍为 v5。
