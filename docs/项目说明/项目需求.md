# FlowMuse 需求文档

## 1. 产品定位

FlowMuse 是一款**跨平台协同白板（笔记）应用**，面向需要手写、绘图、多人协作的场景（教学、会议、设计草稿、个人笔记）。核心差异化：自研白板内核 + 多端原生体验 + 手写笔压感 + 实时协作。

## 2. 目标用户与场景

- **学生/研究者**：课堂笔记、公式推导、思维导图
- **团队**：会议白板、方案草稿、实时协同标注
- **个人**：手写日记、灵感速记

典型场景：一台平板用手写笔书写压感笔迹，其他成员通过手机/电脑实时查看与编辑同一白板。

| 对齐 | 多种对齐与分布 |

### 4.3 协作（实时多端）

| 需求 | 说明 |
|---|---|
| 房间 | 创建/加入协作房间 |

| 场景存储 | 服务端持久化白板场景 |
| 端到端加密 | 场景内容加密存储 |

**协作者归属聚焦**：协作中新建的元素记录不可变创建者（加密 presence 可选字段同步稳定 creatorKey，服务端零改动）。点击顶部协作者头像可聚焦该创建者的内容，也可从单选元素的属性面板进入"查看某某的内容/查看历史内容"；聚焦时其他普通元素按原层级顺序变淡（0.22）但保留空间上下文，PDF 底稿、分页纸张、网格、协作光标、选择框、本地活动笔迹与正在编辑的内容始终全亮。聚焦是纯本机视图状态：不改变文档、不写历史、不保存、不广播，也不限制编辑。外部导出文件不携带创建者信息；不提供隐藏/solo、图层排序、归属转移与最后编辑者语义。详见《2026-08-25-issue-8-collaboration-ownership-focus》与《2026-08-25-issue-8-implementation-details》。

#### 4.5.1 AI 笔记助手

| 需求 | 说明 |
|---|---|
| 自备模型 | 用户配置 OpenAI 兼容 API 地址、API Key 与模型名称 |
| 受限操作 | 仅允许重命名笔记、插入文本与生成思维导图，应用前必须预览确认 |
| 意图感知 | 自动区分"生成型"指令（总结/待办/大纲/思维导图/整理等）与"问答型"指令（解释/比较/点评等）：生成型产出内容并准备写入，确认后才应用到笔记；问答型只显示回复，不出现确认与应用操作 |
| 无内容防呆 | 指令要求生成内容但笔记/选区并无对应可生成材料（如无待办可提取）时，仅回复说明（如"当前没有可生成待办的内容"），不产生任何写入动作、不弹确认，避免把说明文案误写入笔记 |
| 大笔记上下文 | 最多读取 30000 字，超出时安全截取并提示用户 |
| 可控应用 | 支持常用快捷指令和逐项选择需要执行的动作 |
| 自适应落地 | AI 与语音长文本按当前页面或视口宽度换行，并优先放入空闲区域；AI 返回的常见 Markdown 会转为文本框可显示的纯文本结构 |
| 自由对话 | 空白笔记也可直接对话或生成文本；存在笔记文字时，AI 可按需读取上下文并调用受限工具 |
| 非阻塞交互 | AI 助手从白板右侧展开，不显示模态遮罩，使用者可在面板打开时继续操作画布 |
| 连续修改 | 支持基于上一轮候选结果追问，并在应用前直接编辑动作内容或取消生成 |
| 上下文范围 | 有文本选区时优先分析选区，否则分析整篇笔记；携带页面和坐标阅读顺序 |
| 自定义指令 | 支持保存、复用和删除最多 10 条本地常用指令 |
| 长文本分页 | 超高文本拆为多个文本框，分页空间不足时自动追加空白页，保持一次撤销 |
| 思维导图生成 | 根据当前笔记或文本选区生成最多 4 层、50 个节点的内容树，由客户端确定性布局并保持一次撤销 |
| 多模态视觉上下文 | 框选笔迹、图片或 PDF 页面时自动渲染选区截图（最长边 ≤2048）随请求发送；最多 3 张、单张 ≤4MiB；未选择视觉元素时不上传任何图片；发送前明确提示截图将发送至用户配置的模型服务 |

### 4.10 语音转文字

| 需求 | 说明 |
|---|---|
| 跨端语音输入 | Android 使用系统 SpeechRecognizer、鸿蒙使用 Core Speech Kit、Web 使用 Web Speech API |
| 实时预览 | 中间识别结果仅在本地浮层展示，不修改白板场景 |
| 标准文本落地 | 最终结果一次性创建普通 TextElement，复用撤销、保存、导出和协作 |
| 生命周期安全 | 取消、页面退出或应用退后台后立即释放麦克风，不提交临时文字 |
| 隐私 | 默认不保存、上传或同步录音；首次使用明确提示可能由平台识别服务处理 |
| 安全降级 | 权限拒绝、平台不支持和识别错误不影响白板继续使用 |

### 4.11 鸿蒙端特有

| 需求 | 说明 |
|---|---|
| 手写笔压感 | 华为手写笔的 force/pressure 驱动笔迹粗细 |
| 鸿蒙编译 | 通过 vendor code_assets 解决 ohos native-assets 兼容 |
| 原生 HTTP | Platform Channel → @ohos.net.http，绕过 dart:io socket 缺陷 |
| 原生文件选择 | Platform Channel → DocumentViewPicker，替代未注册的 file_picker 插件 |
| 原生文件保存 | Platform Channel → DocumentViewPicker(DOWNLOAD)，直存 Downloads 目录 |
| 原生 PDF 渲染 | Platform Channel → PDFKit，替代 pdfx 插件渲染 PDF 页面 |
| Pen Kit 全局取色 | 支持设备调用系统全局取色器；不支持时降级到画布取色，用户取消时保持原颜色 |
| 原生语音识别 | Platform Channel → Core Speech Kit，将普通话转换为标准白板文本元素 |

| 桌面服务卡片 | 鸿蒙桌面显示最近白板并一键继续创作；无最近白板时回到资料库 |

### 4.12 AI 视觉上下文

AI 助手可附带画布视觉内容（选区截图 / 当前 PDF 页），理解手写、图片与 PDF 页面。

| 需求 | 说明 |
|---|---|
| 附件来源 | 显式添加：**框选截图**（点「选区截图」进入截图模式，在画布上**手动拖动矩形**，矩形范围任意——可含未选中元素或空白背景；期间画布输入冻结；「✕/取消」静默退出不添加）；当前 PDF 页不变。打开面板时选区含非文本元素自动捕获一张；点击视觉快捷指令（解释这里/检查公式/整理文字/整理成导图）时刷新当前选区截图 |
| 活动选区槽 | 系统自动产生的选区附件在快捷指令时刻替换或移除，过期图不驻留；用户手动添加的附件永不被系统自动删除；满额（≤3 张）且槽空时仅提示不驱逐 |
| 数量与规格 | 任一来源混合计数 ≤3 张；单张 ≤4MiB；输出最长边 1568px |
| 知情确认 | 附件条常驻可见（发送前始终可见），缩略图可逐张移除；追问时附件随每次请求重发直到移除或清除对话 |
| 隐私边界 | 仅发送附件条中显示的图片，不自动上传附件之外的画布图像内容（文字上下文仍按既有规则发送）；附件仅存面板内存态，不入库不入会话历史不入日志 |
| 校验防线 | PNG 魔数 + 结构化 chunk 扫描（拒文本元数据 chunk 与畸形结构）；归一化维度护栏防解压炸弹 |
| 失败处理 | 捕获/归一化失败展示用户可读文案并不打断纯文本路径；模型不支持图片输入（400/415/422）或超出服务大小限制（413）时给专用引导文案 |

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 跨端一致性 | 一份 Dart 代码，各端行为一致；平台特有能力（压感）优雅降级 |
| 性能 | 笔迹低延迟跟手；大场景下滚动/缩放流畅 |
| 离线 | 单机可用（无服务端也能本地书写与存储）|
| 数据格式 | Excalidraw JSON 兼容（可导入/导出 Excalidraw）|
| 可部署 | 服务端 Docker 一站式部署 |

## 6. 当前状态与演进

项目按里程碑演进，关键节点：

1. **组件化框架** — Riverpod + go_router + feature 分层（已完成）
2. **markdraw 内核** — 自研 Excalidraw 风格白板（已完成）
3. **协作后端** — Go + Socket.IO + 房间/加密（已完成）
4. **鸿蒙适配** — ohos 端编译、原生 Platform Channel 桥接（HTTP/文件选择/PDF渲染）（已完成）
5. **手写笔压感** — PointerEvent.pressure + 多笔形独立状态管理（已完成）
6. **AI 手写识别** — 服务端识别流水线，自动/手动双模式（已完成）
7. **分页模式** — 分页视口、PDF 背景页、弹性添页交互（已完成）
8. **智能排版优化** — 自适应排版：AI 按内容自主判定四种风格（PPT 式 / 头脑风暴转思维导图 / 文章式阅读流 / 仅识别并转化手写字体），页面范围可选"全部页 / 选页 / 当前页"（选页支持缩略图勾选与 3-5,7 式页码输入）；逐页进入**草稿编辑态**：排版结果实时渲染、每个参与者显示选取框、可拖动微调（方案外元素不可动，红区标出），确认后一次性落地（一次撤销），或跳过本页/取消整流程（零残留）；识别失败可定位重试或删除未识别笔迹后继续；版式采用模板系统（结构层统一处理竖排识别保持、图文原稿几何配对、单元水平居中、标题置顶居中加大）；**视觉优先管线接管全部风格**：整页截图交服务端 VLM 一次完成认字 + 结构理解 + 图文配对 + 风格判定（含思维导图层级树），文字采用 VLM 整页转写单引擎（智能排版不使用 MyScript，其仅用于独立"手写字迹识别"入口；prompt 禁止参考照片内容猜测文字），元素级置信度自评贯穿到客户端——草稿态对低把握文本橙色虚线标注并支持"校对 N 处"就地改字，匹配层按中心点认领 + 二次合并扫描抗拆簇与框偏移，客户端匹配回原稿后由各风格模板精修落位，异常自动回退经典逐块识别管线；锁定元素不动、成组整体移动、绑定跟随、禁止跨页搬移（已完成）
9. **持续迭代** — UI 打磨、性能优化、协作稳定性

详细设计、计划与验收记录见 `docs/`。
