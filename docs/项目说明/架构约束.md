# 架构约束

## Excalidraw 对齐原则

FlowMuse 的绘画协作核心继续采用 Excalidraw 的方案。除手绘视觉风格外，后续实现应尽量与 Excalidraw 完全对齐。

- 数据模型、场景 JSON、元素字段、版本字段、顺序字段、删除保留策略优先与 Excalidraw 保持兼容。
- 画布交互语义、选择、编辑、拖拽、缩放、文本、图片、Frame、绑定箭头、分组等白板能力以 Excalidraw 为目标实现。
- 实时协作、端到端加密、房间链接、冲突合并、远端持久化、光标与在线状态同步优先参考 Excalidraw 的架构和算法。
- 导入导出优先兼容 Excalidraw 文件格式和场景恢复语义。
- 手绘风格不是强制目标，可以采用更符合 FlowMuse 产品定位的非手绘视觉渲染，但不得破坏 Excalidraw 数据与协作兼容性。

## 协作归属与聚焦硬约束

- 归属是**逻辑分组**，不是物理图层：所有元素继续共享一条全局 fractional-index z 序，聚焦不得重排元素、改变遮挡关系或修改 Scene。
- 普通元素创建时可写入 `customData.flowMuse.collaborationOwner`；创建者不可变，编辑者、最后修改者和权限主体不得与其混用。旧元素或缺少归属的元素统一视为“历史内容”。
- `creatorKey`、昵称和头像快照只用于显示与远端湿墨分类，客户端数据可伪造，禁止用于权限、锁定、鉴权或安全决策。
- 聚焦是页面本地视图状态，不进入 Scene、History、SQLite、快照或网络；变淡必须沿原 z 序单遍按连续区段合成，默认无聚焦路径不得增加额外图层。
- PDF/分页底图、网格、协作光标、选择框、本地活动笔迹和正在编辑的 overlay 在聚焦时保持全亮；绑定文字继承父元素归属。
- 内部 SQLite 和协作密文保留归属；`.markdraw`、`.excalidraw`、`.json`、PNG/SVG 和分享产物等外部出口必须剥离 `collaborationOwner`，但保留其他合法 `flowMuse` 键。
