# 自由书写第二轮：性能测量与完整工作流验收

起点：`feature/freehand-experience` / `58760b7`。用户要求继续执行下一步计划，需要本人参与的环节先记录，不中断自动工作。

## 目标与边界

1. 区分回放调度误差、输入分发成本和编辑器实际阻塞，保留完整原始报告。
2. 取得有效数据后，再对五笔、100/1000/5000 元素和连续短/长笔做至少五轮交替 A/B；任何无效或失败场景保留原始原因，不放宽 P95 4ms / max 16ms 注入门槛。
3. 补充完整 WhiteboardPage 的保存、底图、识别及协作自动回归；模拟外部服务的结果明确标识，不能替代真实网络或硬件验收。
4. 只有证据定位的热点才修改生产代码；输入样本、压力曲线、笔形、终笔提交和持久化可靠性继续受保护。分层渲染默认保持关闭，跨端证据不足时不全局启用。

沿用现有 runner、probe、汇总器和 fixture，不新增测试框架或第三方依赖。Android 使用保留数据安装及直接连接 driver，不使用卸载、清除数据或卸载重试。测试结束恢复正常应用包。

## 实施顺序

- [x] 增加 clock-only / empty-binding 校准，并逐样本记录同步输入分发耗时。
- [x] 在连接的 Android 平板运行校准，可靠取得 VM service 地址和报告，记录设备与构建身份。新增 v2 fixture 的 ARM/电脑 hash 校验通过。
- [x] 依据校准结果修正绘帧策略、shader 初始化及 fixture 精度，完成诊断 A/B；有效轮次 0/10，停止扩大无效矩阵，默认开关继续关闭。
- [x] 补齐能独立运行的完整白板工作流自动验收，保留真实与模拟边界。修复退出补存；既有协作撤销缺陷单独记录并保留失败复现，未计为通过。
- [x] 全量测试、静态检查、Android/Web release 构建，提交实现和证据；平板恢复正常 release 且测试笔记保留。全量 1809 通过、5 跳过（含本轮明确记录的 1 个既有协作撤销缺陷）。

## 暂存：需要用户参与的项目

这些项目不作为当前自动工作的前置问题，待用户方便时再统一处理。

| 项目 | 需要什么 | 验收内容 |
| --- | --- | --- |
| 真实触控笔手感 | 用户实际持笔，在当前/候选版写相同样本 | 小汉字、公式、快连笔、慢起笔、轻重提按、转折与收笔；记录设备和笔型号。 |
| 掌触与多指共存 | 持笔并实际落掌/缩放 | 误触、断笔、跳点、双指手势接管及返回书写。 |
