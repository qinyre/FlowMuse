# PDF 笔记本地书写停顿排查与修复

## 背景与边界

用户反馈一加 Pad Pro 在导入 PDF 上本地书写会偶发停顿，空白笔记正常，持续落笔和抬笔之间均可能发生。橡皮手感优化已独立推送并发布；本项在其后另建 `fix/pdf-local-writing-jank`，保留已发布的橡皮修改。提交本项 PR 前，#87 已合并至 main `fe679598`，本分支已同步主线。

## 已核实的路径

- `ImageElementCache.resolveVisible` 每次生成新 Map，`StaticCanvasPainter.shouldRepaint` 按 Map 身份比较。相同图片内容也导致静态画面与 Picture 缓存重复失效；无图片的空白笔记返回 null，避开该问题。
- 默认自动保存间隔 500 ms。保存同步调用 `serializeScene`，Excalidraw codec 对全部图片做 Base64 和 JSON 编码；原生 `File.writeAsString` 在异步写盘前还同步执行 UTF-8 编码。这些工作均可能挤占 UI 线程。
- 既有可见区域图片加载已有缓存和串行队列；不通过降低 PDF 清晰度或改动笔刷/压感来掩盖问题。

## 实施与验证

1. 为相同图片的新 Map、图片新增/替换/移除补重绘失效回归；用合成图片字节探针记录同步编码耗时，仅作为开发机对照，不能当成一加实机帧率。
2. 图片表按实际 key/图像实例比较，保留解码完成、滚动与替换图片的失效行为，以及原有绘制顺序、聚焦和叠色。
3. 大图片场景的本地草稿在捕获当前文档快照后，复用 Flutter compute 将 Base64/JSON 编码移至原生工作 isolate；小场景沿用轻量路径。保持完整 Excalidraw 正文与现有资料库 Repository。
4. 保存仍逐批有序，立即接管正文准备、前次保存和封面异常；正文失败保留未保存状态，封面失败不覆盖旧封面。原生大场景 UTF-8 编码同样移出 UI 线程，文件格式与路径不变。
5. 验证异步快照与后续编辑隔离、图片和中文完整往返、前后保存顺序、失败重试和原有协作/保存流程；相关与全量 Flutter 测试、分析及 release 构建。只用合成数据，不读取用户笔记正文或记录真实截图；实际一加手感仍需复测。

## 复现与初步回归

- 修复前，新图片表引用同一 ui.Image 的回归期望不重绘，实际返回 true，确认重复失效；修正后相同内容复用，替换、增删、清空仍失效。原静态缓存与直绘、聚焦、缩放、叠色的像素矩阵继续通过。
- 合成开发机探针：6 MiB 图片同步序列化约 43.5 ms，随后 UTF-8 编码约 19.6 ms；24 MiB 分别约 137.8 ms / 62.8 ms。改用后台序列化后，零延时事件循环探针等待分别约 4.7 ms / 9.2 ms，编码任务本身仍需约 46.7 ms / 142.6 ms。该数据只证明开发机 UI 隔离效果，不能作为一加帧率或端到端笔尖延迟。
- 13 项相关回归通过：异步大/小场景与原序列化内容一致（忽略既有 files.created 时间值），后续清空或控制器释放不改变已捕获快照；后一个正文先准备好仍按顺序保存；正文、封面、前次保存同时失败时接管异常；大场景含中文及非 BMP 字符完整落盘重开。
- 本地探针与日志在忽略目录 `FlowMuse-App/build/pdf-jank/`。未修改协作协议、数据库 schema、原图画质、笔刷渲染或压感参数；原生 UTF-8 文件内容与原 writeAsString 相同。Web 的 compute 不创建工作线程，本轮 Web 的直接收益来自静态层复用。
- 完整 Flutter 回归 **2059 项通过、5 项既有跳过**，静态分析无问题。随后补强快照回归的混合内容，覆盖 PDF 图片、v2 铅笔批注、压感点及中文文本，相关测试另行复跑。开发机探针不代替真实设备性能验收。
