# 智能排版 V3 独立识别链路改造计划

日期：2026-09-16。状态：待实施，本文不代表功能已经实现或效果已经验收。

代码基线：`d158d7c`，当前仓库 `2024-se-17`。后续执行若基线变化，先检查相关差异，不覆盖其他任务成果。

## 1. 目标与范围

### 1.1 本次要解决的问题

V3 已经有候选生成、约束校验、评分、预览和提交能力，但真实识别入口仍借用旧链路。即使候选得分最高，如果输入被错误分组、识别错字、丢失列表关系，最终排版也不会正确。

本次目标是给 V3 新建独立的“白板内容 → 识别结果 → 结构化文档”链路，让下游拿到可靠内容及结构，而不是再次全面重写排版系统。

用户截图中的“一个标题和连续的 1、2、3 列表”作为首个效果回归场景：识别后应保留一个标题和一个有序列表，三项连续、顺序正确，不能仅因页面宽而拆成左右两组。截图只能证明视觉问题，不能单凭 JPG 判断当时的源笔迹归属或具体运行分支。

### 1.2 不可变边界：V1 原样保留

**本文的 V1 指用户正在使用的旧识别与旧排版链路，包括源码、测试及历史文档中标为 v2 的旧模板功能。这个命名不等于 HTTP 协议版本。**

必须遵守：

1. 不改变 V1 识别、转写、分组、模板选择、排版、预览、取消和应用行为。
2. 不修改 V1 提示词、阈值、模型配置、请求协议及已有服务端处理逻辑。
3. V3 不再调用 `prepareSmartLayoutTemplates()`，也不调用 `cancelSmartLayoutPreparation()`。
4. V3 有自己的请求入口、DTO、识别状态、取消信号和模型配置。V3 失败时保留原内容或报错，不悄悄退回 V1。
5. 可以复用不改变行为的通用读取、渲染、HTTP、Scene 变换、撤销能力；这不等于复用 V1 识别编排器。
6. 以当前基线冻结旧行为，不回退基线里已经存在的修复。

### 1.3 交付与不做事项

交付：原生元素直接解析、手写区域高清识别、可控的疑难复核、标题/段落/列表/图文关系恢复、原始元素归属追踪、V3 独立接入，以及能验证真实效果的样例。

不做：V1 重构、AI 助手入口重构、新编辑器、新文件格式、训练自有大模型、独立任务平台、通用工作流框架、逐任务人工审批、每项强制子代理复审、恢复 153 项任务编排。公式和复杂表格不承诺全面可编辑重建，识别不可靠时保留原始内容。

## 2. 已核实的现状与根因

以下路径相对仓库根目录。为简洁，后文用 `SL` 表示 `FlowMuse-App/lib/features/whiteboard/smart_layout`，`SLT` 表示 `FlowMuse-App/test/features/whiteboard/smart_layout`；它们不是新增目录。

| 位置 | 当前事实 | 对方案的影响 |
| --- | --- | --- |
| `SL/session/smart_layout_real_wiring.dart` | `_analyzeWithVision` 调用旧 `prepareSmartLayoutTemplates()`；取消也转给旧控制器 | 必须替换 V3 入口与取消依赖，不能只换服务端提示词 |
| 同文件 `_adaptVisionPreparation` | 将旧结果适配为 V3 response，再补充转写、列表及噪声处理 | 新链路不能继续把这个旧结果适配器当识别核心 |
| `SL/snapshot/layout_page_snapshot.dart` | 已有对象、几何、原生文字、资产和覆盖账本；笔迹记录不含完整点序列 | 复用快照，同时从同一版 Scene 读取确有需要的笔迹数据 |
| `SL/segmentation/ink_region_segmenter.dart` | 已有尺度、倾斜、邻接和分区能力 | 在 V3 内扩展分区，不再另写一套聚类框架 |
| `SL/assets/smart_layout_asset_builder.dart` | 可从页面图裁剪、标注；裁剪清晰度受输入页面图限制 | 增加直接按区域高清渲染；放大低清缩略图不能提高识别信息量 |
| `SL/protocol/smart_layout_v3_response.dart` | 现有 response 主要表达区域和关系，没有识别正文 | 新建识别 DTO，不把 OCR 文本硬塞进旧协议 |
| `SL/semantics/semantic_document_assembler.dart` | 原生文字优先；转写放在 `extras['transcribedText']`；现有组装未完整消费 response 关系 | 新适配器必须把正文和结构真正送到下游，不能只返回漂亮 JSON |
| `SL/patch/candidate_patch_materializer.dart` | typed 只支持单个 TextElement；figure 只支持单个 ImageElement；table 不支持 | 不能把任意图形或表格标成 figure 就宣称完成转换 |
| `SL/geometry/smart_layout_scene_transformer.dart` | 已有元素变换及 group/frame/binding 闭包能力 | 原样移动图形组可复用，但必须检查变换闭包及重复变换 |

当前基线已经包含短内容候选约束、编号行聚合、单栏顶部留白等修复；本计划保留这些成果，不把它们列成从零开发任务。

真正需要补的是：让识别结果区分“文字是什么”“哪些内容属于一组”“哪些原件能替换”，并让这些信息在排版、校验、应用三个环节都生效。模型自报 confidence 或布局总分不能代替这些判断。

## 3. 总体设计：两条独立业务链路

```text
V1：原入口 → 原控制器准备/识别 → 原服务端接口 → 原模板排版 → 原应用流程
    本次保持不变

V3：现有 V3 入口
    → 捕获同一版 Scene + LayoutPageSnapshot
    → 原生内容提取 / 笔迹区域提议
    → 干净概览图 + 区域高清图
    → V3 识别接口：初读 → 必要时局部复核
    → 结构恢复：本地规则优先，复杂情况一次模型请求
    → 校验并生成 SemanticDocument + 源元素映射
    → 现有 V3 候选生成、约束、评分、预览、应用、撤销
```

这几个步骤是一个会话内的处理函数序列，不是几个独立服务，也不需要消息队列、数据库任务表或通用 DAG 调度器。

### 3.1 输入快照与唯一归属

- 一次操作捕获 `pageId`、`sceneRevision`、内容指纹以及同一版 Scene/快照；异步阶段不得重新拼接不同版本的元素。
- 页面背景、横线纸装饰、编辑器工具栏、选框不是待识别正文。OCR 资产不含 UI 和背景横线；原 Scene 的背景仍保留。
- 建立本次操作的源元素账本：每个源 ID 最终只能属于“原样保留”或“由一个输出单元消费”。不能同时删除两次、漏记或悄悄丢弃。
- 锁定对象、越界绑定、不可解析对象默认保留并作为障碍物。笔迹快照没有足够锁定/绑定信息时，从捕获的 Scene 校验，不能假设可移动。
- 只使用真实存在的笔迹点序列/压力/顺序信息；不能把对象更新时间冒充笔顺，也不为旧数据编造时间戳。
- 元素 ID 是本地事实，模型不得创建新的源 ID 或决定删除哪些原件。

### 3.2 原生元素绕过 OCR

| 输入 | V3 默认处理 | 替换边界 |
| --- | --- | --- |
| 原生 TextElement | 直接读取精确文字、样式和位置；参与结构判断 | 不重识别、不润色正文，遵循现有 V3 文本编辑策略 |
| ImageElement | 作为图片单元，保留 fileId、裁剪和原始图像 | 默认不把图片内部的文字拆出来替换 |
| 图形、箭头、图形组 | 按组及绑定闭包保留原生单元；可安全时整体移动 | 不通过 OCR 重画图形；不任意拆断连接 |
| 手写笔迹 | 区域分组后识别，满足替换条件才转为文本 | 不满足条件的原笔迹仍显示、可编辑 |
| 公式/复杂表格/混合涂画 | 可识别语义类别，但默认保留原件 | 不把近似的纯文本当作已完成数学/表格重建 |

原生文字与手写文字可以处于同一个逻辑列表，但必须是分别有源归属的文本单元，不能合并成一个“typed+ink”区域，让原生文字覆盖识别正文。

### 3.3 手写分区与高清资产

复用 `InkRegionSegmenter` 等 V3 模块，把几何分区作为候选，不直接视为最终文字块：

1. 根据局部字高、间距、倾斜和连通性提出行/段区域；字号变化不能直接等于标题或新列。
2. 独立保留句号、小数点、编号点、短横线等小笔迹的候选归属，禁止按面积小就删除。
3. 为区域生成 `regionId → sourceIds → pageBounds` 映射。模型只引用 `regionId`。
4. 概览图用于理解整体关系；OCR 从对应 Scene 子集直接高清渲染，不能仅放大已经生成的低清全页图。
5. 复用 `DraftSceneRenderer`，使用独立渲染实例或隔离生命周期，不取消正在使用的预览渲染。
6. 针对浅色铅笔，可在临时识别资产上做一次对比度增强；原始图和原笔迹样式不变。不要默认重复发送原图和增强图。
7. 保留完整的页面坐标/局部坐标/像素坐标变换，并测试旋转、缩放、负坐标、裁剪边缘及非零原点。
8. 多个区域复用的上下文边缘笔迹只作为上下文，不能被重复计为待消费 source。若不能可靠区分目标正文与上下文，应合并区域或保留，不强行拆分。

一个 FreeDraw 元素跨越多行时，不能伪造“每个字对应一组源元素”。可保留为一个多行文本单元一次性替换；如果无法确保正文完整，就保留整个原件。

### 3.4 识别与局部复核

初读提示词的任务只有忠实读取：输出可见文字、原换行、编号和标点；不得改写、补全、纠错成模型认为合理的内容。表达不通顺也不是自动润色的理由。

复核触发信号包括：看不清、疑似漏行、区域被判非文本但局部笔迹像文字、编号断裂且空间上有候选、初读结果与区域形态明显不匹配。confidence 仅是辅助信号，不可单独决定删除原件。

- 只复核有疑点的区域，第二次采用更清晰/更合适的裁剪，不默认整页识别两遍。
- 全操作最多一轮区域重分组和复核；先生成最终复核区域，再发请求，不无限递归。
- 可对明确相邻、属于同一句/同列表项的区域局部合并；合并后旧 regionId 作废，账本重新校验。
- 初读与复核冲突未解决时标为 uncertain，保留原件。错误自信和两次同样读错仍可能发生，因此必须用真实样例评估，不能把“双模型同意”当正确证明。
- 一块失败不拖垮其他块。资产生成若沿用现有 all-or-nothing builder，应按区域隔离调用/结果，而不是把整个批次失败误当所有区域都不可用。
- 未返回、超时或格式错误的区域要显式报状态，不使用空字符串冒充识别成功。

### 3.5 结构恢复，不重写正文

输入是固定下来的原生文字、识别正文、坐标、区域类别和概览图；输出是角色、阅读顺序、列表分组、缩进层级、图文归属。

简单的单栏标题+有序列表，本地即可确定，不额外调用模型。复杂图文、多组列表或多栏歧义时最多调用一次结构请求。

结构阶段约束：

- 只引用已有 region/unit ID，不返回新正文，不自行更正 OCR；给结构请求携带文本版本指纹，结果必须对应当前版本。
- 编号列表有 `listGroupId`、`level`、顺序和原始编号；连续编号是强证据，但单独的“1.2”不能无条件当作列表。
- 标题判断结合位置、内容和相邻段落，不只看笔迹粗细/框高度；不确定时使用普通正文。
- 图注必须有明确目标；有显式关系时不再被“就近前一个图”覆盖。
- reading order、列表父子关系必须无非法环和缺失引用。箭头图本来可以有环，不能沿用“所有关系一律无环”的规则误杀流程图。
- 结构验证失败时回退到本地保守结构或保留相关原件，不回调 V1。

接入 `SemanticDocument` 后，列表原子组、标题与正文的 keep-with、明确图注目标必须被 `LayoutBlockAssembler` 和候选校验消费。不能只存在于未读取的 extras 字段里。

对截图场景的硬条件是“一个列表，不被无理由拆列”；用最小的 V3 约束补齐即可，不再次重写所有模板或评分权重。

## 4. 接口与实现边界

### 4.1 新增一个专用接口

建议路由：`POST /api/ink/smart-layout/recognize/v3`。

一个接口通过 `stage: read | verify | structure` 区分请求体，不需要建三个微服务。新 DTO 使用 `schemaVersion: "recognition-v3/1"`，避免与现有 `protocolVersion: 3` 混淆。

| 层次 | 必要字段/约束 |
| --- | --- |
| 通用请求 | schemaVersion、stage、operationId、requestId、pageId、sceneRevision、contentFingerprint |
| read/verify 输入 | regionId、目标区域图、必要的上下文；verify 另含原结果和复核原因 |
| structure 输入 | 只读 unit/region 列表、正文版本、页内几何、可选概览图 |
| OCR 区域结果 | regionId、status（recognized/uncertain/unreadable/nonText）、text、可选 confidence、有限长度的诊断码 |
| structure 结果 | 引用已有 ID 的角色、readingOrder、listGroup/level、captionOf 等关系；不含可替代输入正文的字段 |
| 通用响应 | 服务端从请求回填请求身份和输入版本；区域结果/结构结果、有限 warnings、真实错误分类 |

识别状态与是否可以删除原件分开：`recognized` 不自动等于可替换。本地需再验证完整覆盖、文字非空、源类型允许、无冲突、结构与版本有效。

服务端和客户端分别校验：重复/陌生 ID、漏返回、非法状态、过长正文、坏枚举、非有限数、非法几何和关系引用。未知或重复 ID 的批次不直接应用；缺失 ID 对应区域明确保留。不要把数组截到上限后装作处理完毕。

模型输出不可信；输入版本由服务端外壳回填，不要求模型负责可靠回显。服务端应校验成功响应结构，客户端仍进行二次边界校验。

### 4.2 前后端落点

- 客户端新增 `SL/recognition/`：结果模型、输入/资产准备、repository、pipeline、语义适配。仅按职责必要拆文件，不为每一步创建一套 interface/factory/strategy。
- repository 使用现有 `SmartLayoutHttpGateway` 与 `NativeHttpClient`，不新引入 dio/http 包，不在功能层直接操作平台 channel。
- 服务端新增独立包 `FlowMuse-Server/internal/layoutrecognitionv3/`，包含 handler、DTO、provider 调用和提示词。复用已存在且无业务副作用的通用 HTTP/认证能力，不修改旧 `recognition` 包算法。
- 在 `cmd/flowmuse-collab-server/main.go` 仅做新依赖构造和新路由注册；旧 layouter 初始化与注册保持不变。认证方式沿用现有部署要求，不能为新路由绕过已有校验。
- `internal/recognition/smart_layout_v3*.go` 是旧实验/协议代码，不是新包 `internal/layoutrecognitionv3/` 所承载的本次生产识别实现；新包的模块说明应反向注明这一区别，不能因二者都叫 v3 而接错 handler、DTO 或提示词。旧文件保留现有用途，避免重复注册相同路由。

新增 V3 独立配置：`FLOWMUSE_LAYOUT_V3_BASE_URL`、`FLOWMUSE_LAYOUT_V3_API_KEY`、`FLOWMUSE_LAYOUT_V3_MODEL`、`FLOWMUSE_LAYOUT_V3_TIMEOUT_SECONDS`。这些变量只服务新包，不改写现有 `FLOWMUSE_AI_*`。

可以由部署者把两套变量配置成同一家服务，但代码不通过修改旧全局配置实现。首轮可显式配置当前已用的视觉模型作为 V3 基线，先检验高清裁剪和结构化链路的收益，不预设换模型就能解决问题；如果清晰区域仍大量读错，再通过同集对照选择另一款支持图像输入的模型，只改 V3 配置。服务是否支持某种结构化输出参数需实际验证，不假设所有兼容接口能力完全一致。

V3 配置缺失时明确 unavailable/503，原生内容可走不依赖模型的处理；手写保留并提示，不能返回伪造识别结果。不要把密钥写入仓库、客户端或证据文件。

### 4.3 V3 语义适配与原生单元应用

新识别结果直接适配到现有 V3 文档和块结构，不绕回 `_adaptVisionPreparation`。保持下游可用的 typed text 与 `extras['transcribedText']` 区分，必要时增加一个明确的 V3 工厂入口，不把网络 DTO 扩散到整个排版系统。

必须补齐三种应用路径：

1. **原生文本/图片**：沿用现有可验证的 V3 materializer，保留对象关联与资源引用。
2. **手写转文本**：只允许消费本次批准替换的 FreeDraw 源 ID；绝不把 typed、ImageElement 或未确认笔迹误列为删除对象。
3. **原样原生组合单元**：给 V3 materializer 增加有限的 source-preserving 分支，复用 `SmartLayoutSceneTransformer` 整体变换。验证 group/frame/binding 闭包不越出预期集合，同一组只变换一次；涉及锁定、跨页或不完整闭包则整组保留。

未识别/不支持的元素必须在文档或约束输入中具有原始 bounds 和不可覆盖的障碍物身份。仅在 ledger 中标记 preserved，而下游根本不知道它在哪里，是不够的。

默认不因模型说“噪声”就删除源笔迹。对正文附属的小点，应归属明确后随正文转换；无法确认的点保留。原始表格、图形或未识别笔迹保留也不能让新文本压在其上方。

#### 4.3.1 correction / rerun 兼容

复用现有 `correctionHandler → AffectedSourceSet → CorrectionRerunCoordinator → _rerunCandidateChain` 接口链，校正只改 V3 会话草稿，不调用旧识别，也不直接修改原 Scene。当前 wiring 只填 `strokeSourceIds`、其余三类 key 为空，且 rerun 复用 `_lastResponse`；新接线必须替换这两处占位行为。

- **regionId 稳定规则**：复用 `regionIdOf(strokeIds)` 当前的 `r:<最小笔迹源ID>` 规则，作用域限定当前 pageId；同成员重跑保持 ID，不随数组下标、阅读顺序或模型返回顺序重编号。合并/拆分可能复用同一最小 ID，所以不能只以 regionId 判断结果有效性：同时校验完整成员集合指纹、源内容指纹和分区 revision。§3.4 的“旧 regionId 作废”指旧版本区域记录及其关系失效，即使新记录的 ID 字符串相同也不可直接复用旧正文/资产。
- **账本重校验**：`correctionHandler` 先把 intent 中的 subjectIds 按实际类型解析成区域/源集合，通过现有 correction patch/applier 验证 revision 和成员快照，再在新草稿上校验合并/拆分前后源集合守恒、唯一归属、protected/preserved 状态及关系引用；通过后才发布新分区版本。不能把区域 ID 直接当作笔迹 ID。rerun 合并新旧识别事实后、生成候选前，再执行一次全页覆盖与无重复消费校验。

四类 key 都由客户端事实产生，不由模型猜测：

| `AffectedSourceSet` 字段 | 新 pipeline 中的产出层 | 重跑时的用途 |
| --- | --- | --- |
| `regionIds` | 分区/校正层，对比 patch 前后区域成员 | 受影响旧区域与新区域的并集；失效旧语义、正文和关系记录 |
| `strokeSourceIds` | 同一分区/校正层，根据上述区域的成员映射 | 受影响区域前后源笔迹的并集；定位重识别范围并复核账本 |
| `renderAssetKeys` | 资产准备层，维护 sourceId → 实际渲染资产的反向索引 | 刷新受影响图像；原生资产沿用 `fileId|ownerSourceId` 约定，临时区域图使用会话内 assetId，不向 Scene 注入假 fileId |
| `cropKeys` | 资产裁剪层，维护资产所有者 → 实际裁剪结果的索引 | 精确失效旧裁剪；沿用所有者/crop 键约定，并将裁剪几何、变换与渲染规格纳入资产指纹 |

四类集合都覆盖旧结果失效与新结果生成涉及的依赖；没有对应资产才可为空，不能因为 source 是 FreeDraw 就忽略为它生成的临时识别图。新资产尚未生成时先登记计划键，生成失败仍保留明确失效状态。

现有 coordinator 的 chain 参数只有 `affectedSourceIds`，因此 pipeline 在会话内保存同一校正版本的完整影响集和资产索引，`_rerunCandidateChain` 消费这份上下文而非丢弃另三类 key；裁剪单独变化也必须触发失效，不能被仅检查前三类集合的空集判断吞掉。所需调整限于现有 V3 correction/validation 接线，不另建纠错框架。

重跑先使旧候选全部失效，再重建受影响资产/识别结果及相关列表、图注、阅读顺序；未触区域只有在成员、源内容和识别配置指纹均一致时才能复用。首版可全量重建文档和候选，不必为局部排版优化增加复杂度，但不能拿旧 `_lastResponse` 冒充已重识别。新候选仍经过现有完整校验和评分。每轮增加校正代次，异步返回校验该代次及操作/Scene 版本；合并、拆分、逆 patch、连续纠错、取消及迟到响应都不能复活旧候选。失败区域保留原件，不退回失效候选。

#### 4.3.2 字号与行高：承接 #14

新适配器接管旧 `_textElementFromRecognizedBlock` 的转换职责，但不调用或修改该 V1 方法，也不复制 `_fontSizeForRecognizedBlock` 的“块高（或块高÷文本换行数）× 0.72”估算。

- V3 的字号/行高由现有 design tokens 的正文、标题层级和实际字体测量确定；源笔迹的可靠逐行高度只作受限尺度提示，排除裁剪留白、孤立高笔画和倾斜影响，不能拿整个多行块的外框高度代表字号。
- 新适配器传递角色和可信尺度信息，由 V3 块组装生成一份统一文本规格。复用 `TextMeasureAdapter`/`FontResolver` 在实际目标宽度下测量，取得真实行数和高度；换行后重新测量，不用 OCR 换行数反推字体大小。
- 行高沿用 V3 token 基线并以实际行度量校验；标题/正文层级和最小可读字号遵循已有设计约束。无法放下时让候选失败或保留原件，不通过无限缩小字体/裁字掩盖问题。预览、patch 和最终元素消费同一份字号、行高及测量结果。
- R6 补单行/多行、合并后行数变化、中英混排、超高离群笔画、同字号不同裁剪留白、不同缩放/DPI 的回归：同一文字的输出字号不因外框、截图倍率或区域合并而失控，列表同级样式一致，无裁字/重叠。

**#14 的 V3 修复归 R6，R9 实机复核后关闭其 V3 验收项，不另留悬空任务。** 若 #14 同时包含 V1 的旧估算缺陷，V1 部分作为冻结遗留移交后续 sunset 清理计划，不因关闭 V3 项而宣称 V1 已修复，也不在本轮修改 V1。

## 5. 性能、费用与状态管理

以下是首轮实现的预算初值，不是已测性能结论。集中在一个 V3 内部预算值对象中，测试可注入；不要把每个数字都暴露成用户设置。

| 项目 | 初值 | 达到上限时 |
| --- | --- | --- |
| 概览图 | 长边不超过 2048 px，保持纵横比 | 只影响上下文，不用它代替高清 OCR |
| 区域图 | 目标行高约 48–96 px；长边不超过 2048 px、像素不超过约 2MP | 超大区域先局部分区；不可安全拆分则保留 |
| 区域留白 | 约 0.3 倍局部行高，裁到有效范围 | 不跨入明显独立正文，必要上下文单独标记 |
| 单次 OCR 批量 | 最多 8 区域；请求 JSON 不超过 16MiB | 按实际编码大小提前拆批，不只计区域数 |
| 首轮区域数 | 最多 64 个待 OCR 区域 | 显示“部分处理”，其余原样保留，不宣称整页完成 |
| 疑难复核 | 最多 16 个最终区域、最多一轮局部重分组 | 剩余疑难原样保留 |
| 本地渲染并发 / 网络并发 | 1 / 2 | 排队且计入总时限；避免挤爆平板内存 |
| 模型调用预算 | 最多 16 次，包含字节拆批、重试、复核和结构请求 | 未处理部分保留，显示真实覆盖率 |
| 重试 | 每请求至多 1 次，仅网络瞬断或可重试状态 | 认证/配置/协议错误不重试；总预算优先 |
| 时限 | 整次 120 秒；单次最多 45 秒且不超过剩余时间 | 取消在途请求，已有安全结果可形成部分预览 |

常规调用数约为 `ceil(初读区域数/8) + ceil(复核区域数/8) + 结构请求(0或1)`；大图导致拆批时不保证这个数量，因此还需要全局预算。原生文字场景不调用 OCR；简单原生内容可全程零模型调用。

服务端另外限制解码后的图片尺寸、实际字节数和输出长度；取消通过请求 context 传到 provider。总时限用真实计时器约束，不能只在两次 await 之间检查一下。

会话内可缓存相同输入/资产/提示词版本/模型标识的结果，不新增持久化缓存服务。渲染 image、临时 asset、请求 token 在成功、失败、取消路径均释放。

### 5.1 独立取消与过期保护

- V3 pipeline 使用自己的 operationId、cancel token 和运行状态，不取得旧 `prepareSmartLayoutTemplates` 的锁。
- `SmartLayoutRealSessionScope` 的分析和取消回调改接 V3 pipeline；旧控制器锁与取消方法不动。
- 页面切换、关闭面板、再次发起、Scene 实质变更时，取消/废弃旧结果；不能把旧页结果回写新页。
- 每次异步结果回归、生成预览以及应用前都校验输入版本。operationId 不匹配的旧成功/旧错误也不得改变新会话状态。
- V1 操作可以通过正常编辑引发 Scene 变化，届时 V3 结果失效；不需要让 V3 控制 V1 的生命周期。
- V3 取消不取消 V1，V1 取消也不取消 V3；共享网络基础设施不共享业务取消 token。
- 现有 V3 预览/提交/撤销入口继续使用，拒绝增设绕过 Scene revision 检查的直接写画布通道。

## 7. 四阶段、九个可交付任务

任务按一个可验证工程结果分包，不按每个字段、文件或测试逐项拆票。工程量“中”约 1–2 人日，“大”约 2–4 人日，仅用于识别体量，不预测模型运行时长或制定比赛倒计时。

### 阶段一：独立契约与真实输入

**R1：固定边界、结果模型和失败语义。工程量：中。依赖：无。**

- 新增 recognition DTO、版本与状态定义、校验器；冻结 V1 行为基线。
- 增加协议样例：成功、部分失败、重复/陌生 ID、坏结构、缺配置、过期响应。
- 明确“模型读到了什么”与“本地允许替换什么”的不同类型/字段。
- 记录旧路由与配置基线，为新 pipeline 准备可观测请求/取消调用的测试替身。当前实际 V3 尚依赖旧控制器，全局隔离断言随 R7 接线落地，在 R8 完整验证，不要求 R1 提前完成接线，也不加入长期 skip 的假通过测试。
- 完成标准：两端使用同一组请求/响应样例；非法结果不能变为可应用结果；没有改旧协议。

**R2：原生提取、笔迹分区和高清资产。工程量：大。依赖：R1。**

- 复用 snapshot/Scene 提取原生文字、图片、图形组、笔迹与保护对象。

- 建立截图场景的可复现 Scene；没有原 .markdraw 时明确标注为人工重建，不伪称实际用户原数据。
- 完成标准：源账本覆盖完整；区域清晰度有可查看资产；纯原生文本没有 OCR 任务；小点不消失。

### 阶段二：真正独立的识别请求

**R3：服务端新接口与独立模型配置。工程量：中。依赖：R1，可与 R2 并行。**

- 实现输入/输出上限、批次 ID 校验、错误分类；测试用 provider 只能在测试注入。
- 追加启动注册，不修改旧初始化和路由；补新旧路由同时注册的测试，防止冲突。
- 完成标准：mock provider 的协议测试全过；配置缺失真实返回不可用；有真实配置时完成一次实际请求记录。没有真实配置只标记真实调用待验证，不阻塞后续本地实现。

**R4：客户端识别 pipeline、预算和独立取消。工程量：大。依赖：R2、R3 的契约。**

- repository 通过现有 HTTP gateway 请求新接口；取当前有效认证信息，不复用旧识别 repository。
- pipeline 完成初读、拆批、并发、时限、有限重试和每区域状态；提供可注入请求函数用于测试。
- 新取消状态独立于旧 controller；关闭、切页、改内容、重新运行均不接受旧结果。
- 完成标准：新 pipeline 不调用任何旧识别/取消入口；部分超时仍保留完整源内容；预算在极端情况下也不超限。实际面板入口的切换归 R7。

### 阶段三：识别质量与正确转换

**R5：疑难复核与语义结构恢复。工程量：大。依赖：R4。**

- 实现明确的复核触发条件、至多一轮局部重分组、至多一次结构请求和冲突保留。

- 原生文字不可改写；模型关系只引用已有 ID；编号、换行和标点进入对比测试。
- 完成标准：截图重建样例的结构输出为一标题一列表；复核不是所有区域无条件二次调用；结构结果具有可供 R6 消费的明确分组和关系，R6 再验证最终排版。

**R6：新识别结果接入 V3 文档和可逆应用。工程量：大。依赖：R5。**

### 阶段四：接线、回归与实机效果

**R9：真实样例对比与实机收口。工程量：大，约 3–5 人日（工具及回归 1–2 人日，20 页真值采集/人工核对与实机对照 2–3 人日；按样例复杂度调整）。依赖：R8；可提前采样。**

## 8. 验收：效果、完整性与真实运行

### 8.1 小而有效的样例集

首轮建立 24 个可复现 Scene 用例，覆盖至少：

- 标题+三项列表、字号不同的编号列表、嵌套列表、双栏但语义独立的段落。
- 浅色笔迹、大小字混排、倾斜文字、连续笔迹跨行、句号/小数点/编号点。
- 原生文字与手写混排、图片与图注、带标签的箭头/图形组、原始表格和公式。
- 锁定对象、跨组绑定、裁剪边缘、负坐标、区域部分失败、长页超预算。
- 取消、页面切换、修改后旧请求返回、应用/撤销/保存重开。

这些可以由执行代理构造，无需等待人工会议。它们证明工程约束，不证明真实手写识别率。

另外建立真实手写对照集，首轮建议至少 20 页，固定 12 页用于调试、8 页留作未参与调参的复验；一张截图的裁剪变体不算多份独立样本。若暂时只有少量真实页，继续开发，但报告样本不足，不能宣称已达泛化效果。

参考正文可先由 AI 草拟，再依据原图/已知书写内容核对；同一个识别模型的输出不能直接充当真值。确实无法确认的内容标注为不确定，并报告占比，不把这些难例悄悄删出数据集。

### 8.2 必过条件

| 维度 | 必须满足 |
| --- | --- |
| V1 保持不变 | 旧功能实现与配置含义未修改；旧回归通过；V3 不调用旧识别/取消 |
| 内容完整性 | 源元素覆盖率 100%；无重复消费、无未授权类型删除；未知内容保留且不被覆盖 |
| 原生文字 | 字符与标点不被模型改写；原生内容不走 OCR |
| 截图列表场景 | 标题和三项列表完整、顺序正确、同组连续，不因宽页面强拆列 |
| 状态隔离 | 取消与切页不回写旧结果；V3 不改变 V1 的进行中状态 |
| 可逆与兼容 | 预览/应用一致，撤销恢复，保存重开仍有效 |
| 真实链路 | V3 实际请求新服务端与真实 provider；缺配置明确失败，不以固定假结果代替 |

### 8.3 质量目标与防止虚假高分

首轮调优目标（待真实对照验证，不是当前实现承诺）：普通可辨识中文手写集总体字符错误率 CER 不高于 5%；当旧版 CER 已高于 5% 时，V3 同集目标至少相对下降 20%。两项同时报告，不通过择一展示掩盖不足。

- CER 按统一字符规范化计算，正文主指标保留标点；可以另列去标点结果，不能仅靠去标点美化数字。空参考正文单独计错，不做除零处理后丢弃。
- 关键数字、编号、列表项数、条目顺序另列精确匹配；截图回归样例必须全部正确。
- 同时报“可辨识手写区域成功转换覆盖率”，首轮目标不低于 90%，以及错误转换率、保留率、部分完成页数。全部保留原件不能算识别质量优秀。
- 对实际被转换的内容与全部可辨识内容分别统计；未识别不能从总体 CER 样本中消失。
- 记录端到端中位数/P95、区域数、模型调用数和峰值图像内存；样本太少不包装成稳定性能结论。
- 对同一批输入比较旧链路和新链路，使用同一份人工可核对参考；允许保存对照结果避免反复付费重跑。

阈值没有达到时输出具体失败样例和归因：分区/裁剪、文字识别、结构、布局或应用；不能笼统写“模型不稳定”，也不能只展示得分最高的成功页。

**评测基建归属 R9。** 常驻工具放在仓库根目录的 `scripts/smart-layout-v3/recognition_eval.dart`，使用 Dart 标准库实现离线 JSON 读取、字符编辑距离和汇总，不依赖 Flutter 渲染，不自动请求模型。样例索引/真值放在 `docs/研发记录/evidence/smart-layout-v3/recognition/cases.jsonl`，同目录保存 `predictions-v1.jsonl`、`predictions-v3.jsonl`，可复验的汇总写入 `results/`；原图/Scene 引用与样例一起管理，不使用临时绝对路径作为唯一来源。它是有固定入口和自检的工程工具，不属于 §9 第 5 条禁止的一次性 Temp 脚本。

真值记录至少含 caseId、固定调试/留出划分、输入引用/指纹、参考正文、核对状态及不确定范围；预测记录保存同一 caseId/输入指纹、版本/模型信息、实际识别正文和转换/保留状态。R9 负责采集、人工核对和疑难标注，并记录实际核对工作量；未经核对的 AI 草稿不能标成真值。数据未齐时工具仍可实现和自检，真实评测保持待完成，不阻塞其他实现。

R9 实现后的工具约定：从仓库根运行 `dart run scripts/smart-layout-v3/recognition_eval.dart --self-test` 验证全对、替换/插入/删除、空参考、Unicode 字符、缺预测和重复 ID；正常评测接受 `--truth`、`--v1`、`--v3`、`--out` 路径参数，分别传上述真值、两份预测与结果文件。CER 按整集编辑距离总和除以参考字符总数汇总，不平均页面百分比；缺失预测按空预测计删除并报告缺失，未核对范围单列数量/占比。退出码 0 表示已核对数据齐全且既定阈值通过，1 表示有效评测但未达阈值，2 表示输入非法/真值未齐等无法完成有效验收；不得过滤失败页凑 0。自检期望退出码为 0，评测报告同时保留逐页与汇总结果。

**V1 sunset 触发条件**：冻结版本在同一留出集连续两次独立复验的 CER 均优于 V1、满足本节既有质量目标，且实机观察期累计至少 20 次真实排版应用（覆盖撤销、保存重开、切页和取消）无内容丢失回归后，另立旧链路清理计划，盘点并删除不再被调用的旧控制器识别链、旧模板引擎和服务端旧实验/协议代码。条件满足只触发另立计划，不授权本轮自动删除；本计划的 V1 冻结边界不变。

### 8.4 实测证据与不阻塞原则

复用仓库现有测试数据/研发记录位置保存小型样例和结果；证据围绕实际输入与输出，不新增一套 receipt/manifest/Gate 平台。

外部服务不可用不阻止使用测试 provider 完成本地契约、UI 和保护逻辑。真实 provider、真机或原始用户 Scene 缺失时，仅对应验证项标记未完成，禁止伪造，但无需把整个工程变成 100 多项传递 blocked。

最终报告区分：**代码实现完成 / 自动回归通过 / 真实识别对照通过 / 实机通过**。前两项不能代替后两项，也不能声称“已提升识别效果”却没有真实对照。
