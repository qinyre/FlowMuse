# 快速长笔画的同步积压修复

## 现象与定位

快速画长笔时，对方在抬笔前就明显落后；慢速绘制可同步。1 MB 传输限制修复后的服务端没有异常，密文转发峰值仍可达一秒 1,183,047 字节。

默认 V1 每 50 ms 发送一次完整的活动笔画。`latestOnly` 只合并应用层等待的预览；Socket.IO 的普通 emit 立即完成 Future，旧预览仍会进入可靠网络队列。现有 volatile 通道已用于光标，双方与服务端都支持相同的加密 SCENE_UPDATE 格式。

## 实施与边界

1. 先用实际 Socket.IO send 和不可写 transport 重现：连续长笔预览被交给普通发送，最终笔画排在旧进度之后。
2. 仅让 `latestOnly` 非删除预览复用 volatile 通道，拥堵时不继续排旧进度。正式抬笔、取消墓碑和其他编辑继续可靠发送；临时预览不得更新可靠发送版本记录，防止后续正式补发被抑制。
3. 保留全部 points、pressures、customData、端到端加密和现有 LWW 规则。不开启尚未通过设备发布门禁的 V2 开关，不变更消息格式或服务端。
4. 验证预览不会积压，完整笔画和取消仍能送达，掉弃预览后的正式同版本补发有效；跑协作/画布工作流回归、全量 Flutter 测试、分析和发布构建。

## 验证边界

不可写传输测试证明排队行为，不代表真机帧率或所有网络条件的端到端延迟。完成软件验证后更新 Web 和已连接测试平板，确认快速长笔实际表现；不以降低最终笔画精度换取同步速度。

## 实施与验证结果

- 使用真实 Repository、JSON/AES 和 Socket.IO emit，仅替换连接建立及最终 wire write。原实现把 16 个持续增长的预览交给不可写网络；修复后为 0。随后相同版本的完整 4096 点及全部压力仍可靠发送，取消墓碑也可靠发送。
- 隔离后端真实 HTTP/WebSocket 联调：40 个增长预览在抬笔前可被原有 SCENE_UPDATE 接收协议解密，最终 8192 点/压力完整到达，取消到达，测试房间结束。仅使用合成数据。
- 协作、画布工作流和预览保真回归：132 通过、1 项既有跳过；全量 Flutter：1764 通过、6 项既有跳过。
- analyze 无 error、无新增告警；本地既有 `build/nav_compact_screenshot_test.dart:199` protected member warning 保持不变。`git diff --check` 通过。
- 本次仍发送完整 Excalidraw 预览，并非点增量或端到端 ACK；不把不可写传输测试外推为所有网络和笔刷的延迟保证。设备上的快速长笔表现需在更新客户端后确认。
