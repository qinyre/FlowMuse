# FlowMuse 决赛产品优化计划书

> 版本：v1.1（按协作笔记定位修订）
> 日期：2026-10-24
> 状态：F1 感知与视角协同已完成软件回归并发布正式 Web（功能分支尚未合并）；完整公网协作与真机待验证，权限和其余新增功能仍待实施。
> 勘察基线：`main/46ef595`，即第二轮界面优化 PR #79 合并后。
> 排序依据：协作笔记的真实需求优先，其次考虑决赛展示价值、鸿蒙特色、既有能力复用与可验证性；本轮不按开发工期取舍。
> 修订说明：v1.0 过度强调电脑/平板分工；v1.1 将核心改为多人共同记录、讨论与整理，个人跨设备接续列为后续可选探索。

## 1. Context：目标与依据

FlowMuse 的产品主线是以手写与画布为载体的跨平台协作笔记，覆盖个人记录、PDF 批注、多人共同编辑和内容整理。白板绘图是表达方式，教学、会议和设计讨论是使用场景。

决赛优化围绕“多人记录流畅、协作状态清楚、围绕内容讨论、共同整理成果”展开。鸿蒙笔交互、文件输入和系统入口服务这条主线。每位用户使用一台设备即可完成主要任务；不要求同时拥有电脑和平板，不按设备类型固定参与者职责。

此前的“双端工作台”指同一用户在电脑整理、平板书写并交接任务。这种个人多设备使用方式可作为后续探索，不再作为本轮核心功能，也不作为多人协作的必要条件。

| 条目 | 规程内容 | 对本计划的影响 |
| --- | --- | --- |

| 第 6 页，创新性 | 50 分，涉及鸿蒙技术、产品创意、交互与技术创新 | 多人共同记录与整理、笔交互、AI 来源与校对作为主要展示方向 |
| 第 6 页，完备度 | 20 分，功能完备、体验完整顺畅 | 保存、输入、同步、失败恢复作为基础门槛 |
| 第 6 页，前景评估 | 20 分，需求真实性、社会价值、落地价值 | 用真实任务和用户试用证明用途 |
| 第 6 页，规范性 | 10 分，文档与功能演示表达清晰 | 维护功能、鸿蒙能力、实测证据的对应关系 |

### 1.2 已核对的项目基础

- 自研 Markdraw、自然介质笔刷、分页/PDF、元素编辑、撤销和开放格式导入导出。
- 加密实时协作、成员与光标、远端视口数据、创建者归属聚焦、扫码及好友邀请。
- AI 视觉上下文、可编辑导图、确认后写入、V3 原稿对照和角色纠正。
- 鸿蒙原生 PDF、语音、华为账号、扫码、系统分享、Pen Kit 全局取色和最近白板服务卡片。
- 已完成资料库、新建笔记、批量操作与设置页的两轮界面优化。

以上表示源码入口与相关链路存在，不代表六个平台均已通过真机验收。现有能力应复用；本计划只描述需要补齐或增强的部分。

### 1.3 现场设备与待确认条件

用户预计现场有电脑、平板。电脑系统、平板系统与机型、系统版本、手写笔型号及原生能力支持情况尚未确认，不能默认是鸿蒙电脑或支持轻捏的手写笔。

| 设备组合 | 计划支持的方式 | 验收边界 |
| --- | --- | --- |
| Windows 电脑/Web + 鸿蒙平板 | 两位参与者共同编辑同一份笔记，使用各自适合的输入方式 | 验证多人协作，双方均可编辑和浏览；不依赖专门的双端界面 |
| 鸿蒙电脑 + 鸿蒙平板 | 同样验证多人记录、讨论与整理；可分别展示受支持的原生增强 | 核心协作不依赖同一华为账号；系统接续等另行立项和验收 |
| 无兼容手写笔或相关系统能力不可用 | 保留触控、鼠标和现有工具栏入口 | 原生增强不可用时仍能完成主要任务 |

### 1.4 功能取舍标准

1. 能否直接改善记录、批注、共同编辑、讨论、查找或整理笔记？
2. 是否解决当前流程的实际缺口，而非为展示鸿蒙 API 新增一种操作负担？
3. 一人一台设备、甚至同类型设备协作时，是否仍有价值？仅适合个人多设备的功能独立评估。
4. 是否能复用现有能力，且不破坏本地书写、同步、撤销与数据安全？

满足核心需要的功能进入主线；仅有舞台效果、缺少实际需求的功能先保留为候选。鸿蒙特性数量和现场设备组合不能替代产品需求判断。

| 编号 | 优先级 | 工作项 | 主要价值 | 当前状态 |
| --- | --- | --- | --- | --- |
| F0 | P0 | 稳定性、性能基线与真机验收 | 保证输入、保存、协作及失败恢复可靠 | 待专项复核 |
| F1 | P1 核心① | 多人协作感知、主动跟随与权限 | 知道谁在改哪里，能一起看同一区域，控制分享范围 | 感知与视角协同已发布正式 Web；权限独立设计，真机待验，见 [F1 专项计划](2026-10-24-f1-collaboration-awareness.md) |

| F3 | P1 核心③ | AI 来源定位、文字校对与共同整理 | 提升笔记整理可信度，避免应用旧结果覆盖新内容 | 待实施 |

| F9a | P2 鸿蒙入口 | 既有服务卡片升级 | 快速继续最近或固定的笔记 | 待实施 |

## 3. 实现方案与功能边界

### F0：稳定性、性能基线与真机验收

1. 专项复核已记录的 Web TextInput 配置、视口变化和焦点问题；保留旧版本对照，依据证据定位应用、SDK 或环境原因。
2. 检查连续书写、可靠终笔、断线重连、切房、退出/移出房间、协作撤销及本地保存恢复，避免新功能重新引入消息积压与旧会话污染。
3. 使用固定设备、网络和笔记样本，分别测量本地书写与远端可见延迟，记录 P50/P95、消息积压、终笔一致性和帧耗时。调度窗口不作为实测端到端延迟，CPU 占用不作为体验提升指标。
4. 覆盖空白笔记、大量笔迹、多页 PDF、连续协作和弱网恢复。先形成可复现基线，再为专项方案制定性能目标。

验收：故障步骤与恢复路径有记录；重新进入后内容完整；长笔无残留预览或重复终笔；受影响端输入、保存和协作通过实测。尚未解决的问题必须继续列明，不以单元测试或构建成功替代真机结论。

### F1：多人协作感知、主动跟随与权限

- 围绕两人或多人编辑同一份笔记设计流程。先核对已有光标、选中状态、头像、创建者聚焦和视口信息的展示，针对缺口增强，不重复实现已有功能。
- 清楚显示谁正在编辑哪个区域；多人操作同一内容时给出适度提示。编辑提示不等于元素锁，不擅自引入强制互斥或改变现有冲突规则。
- 提供“跟随某位协作者”和“一起看这里”：接收方选择是否跟随，手动浏览可暂停或退出；不强制拉动其他人的视角。
- 每位用户保留自己的工具、面板和阅读位置，按窗口尺寸和输入方式自适应，不固定电脑与平板的职责。
- 依据实际分享需求设计可编辑/只读角色。服务端检查各写入通路，不能仅禁用按钮，也不能使用元素创建者归属充当授权依据。

验收：不同账号和不同设备均能共同编辑；编辑感知与实际操作一致；跟随可退出且不改变正文；未授权写入被拒绝；加入和退出不影响其他成员。无需同一个人同时使用两台设备。

### F2：手写笔快捷交互

- 支持设备上提供双击切换书写/橡皮擦、轻捏打开快捷菜单；菜单包含常用笔、颜色、套索和撤销。
- 有选区时展示识别文字、智能排版、AI 解释与导图等相关操作，复用现有入口和确认流程。
- 菜单支持左右手及边缘避让，不遮挡笔尖与关键内容，不吞掉下一次点击；允许关闭快捷交互。
- 原生事件监听随前后台和页面生命周期注册、注销，防止重复回调；不可用时保留工具栏操作。
- 报点预测仅列为后续技术验证项：实测证明改善后再决定接入，预测点不得进入最终场景、保存或可靠协作。

验收：兼容笔型上手势可重复触发，单次手势不重复执行；切工具不误画、不丢笔；取消菜单保持原工具；不支持设备完成同等基础任务。

### F3：AI 来源定位、文字校对与共同整理

- 将候选结果关联到可靠的源元素、PDF 页或选区；点击来源时定位并高亮相应区域。沿用已有元素与页面标识，不依赖模型自由编造来源 ID。
- 区分来源依据与 AI 推断。来源链接只能证明引用位置，不能证明模型结论必然正确。
- 在现有 V3 角色纠正和保留原件基础上，补充逐字校对、固定内容块和受影响范围重新排版；先明确哪些调整可复用同轮识别、哪些需要重新分析。
- 展示位置整理、文字转写和新增生成的差别；原稿在确认前保持不变，一次应用可一次撤销。
- 源内容变更、删除或版本过期时提示失效，禁止把旧候选直接应用到新画布。新增来源信息的持久化、协作与导出范围需单独确定。
- AI 候选由发起者审阅；确认后的结果复用现有协作同步。其他成员在等待期间的新内容不能被覆盖，不强制其他成员进入 AI 面板或改变其视角。

验收：从结果定位回正确页和区域；校对后应用、保存、重开与撤销一致；取消无残留；过期结果不能覆盖新内容；陌生或失效来源有明确提示。

### F4a：编辑器 UI、状态反馈与轻量动画（P1）

- 按工具和选区呈现相关操作，减少常用动作的移动距离；保留用户习惯，单笔记菜单继续位于笔记名旁。
- 明确区分已保存本机、等待同步、正在重连与同步完成，状态必须对应实际事件。
- 动画用于解释资料插入、整理结果应用、评论定位与跟随状态；遵循 AppMotion 与减少动画设置，书写和远端墨迹保持直接响应。
- 横竖屏、分屏及输入方式切换保持当前编辑上下文，不借自适应之名增加必须学习的设备专属工作模式。

验收：键盘、触控、手写笔、分屏、大字号和深浅主题均可操作；布局切换保持输入与当前工作状态；状态提示准确且不会频繁打断书写。

### F4b：轻量讲解（P2 可选）

- 面向“讲清笔记中的这一段”，复用 F1 跟随、现有分页、激光笔与临时聚焦。
- 先验证是否需要全屏阅读、前后页切换等操作，再决定是否新增讲解路线或遥控能力。
- 不以幻灯片制作或专用演讲软件为目标，不要求平板控制电脑；任意成员都可以在需要时发起讲解。

验收：讲解不改原始内容，不写入文档撤销历史；其他成员可自由退出跟随，并继续编辑。

### F5：跨应用拖入资料与 OCR

- 接收文本、图片和 PDF，依据内容类型提供适当的插入或导入动作；保留现有文件选择入口。
- 图片/文本尽量落在拖入位置，PDF 复用分页导入；跨设备拖拽仅在实际支持的设备组合验证后开放。
- 对印刷体图片接入 Core Vision OCR，结果可预览和修正。原始手写继续复用现有手写识别，不能宣称通用 OCR 覆盖任意手写。
- 校验数据类型、大小、数量及 URI 访问权限；取消或失败不产生半成品，外部正文不默认上传模型服务。

验收：可从实际浏览器、图库/文件管理器完成输入；坐标、比例和页序正确；超限、权限失效及取消均可恢复。

### F6：全文搜索与位置定位

- 从目前标题/副标题检索扩展到白板文本、已识别文字和具备可靠文字来源的 PDF；未识别笔迹不伪装成可搜索文本。
- 结果展示命中片段、笔记与页/区域，点击定位并高亮。
- 优先本地索引，后台增量更新并支持重建；不在落笔或协作热路径中全量索引。
- 删除、恢复、文本修改和页面变化同步更新索引；全文内容不默认共享给系统搜索或云服务。

验收：修改、删除、恢复后命中正确；跳转不会落到错误页；大笔记更新索引不明显干扰书写；迁移与重建不影响原始数据。

### F7：专用公式识别入口

- 在选区识别中明确提供公式模式，复用现有服务端数学识别能力，核对客户端请求提示、返回结构与公式元素落地。
- 支持预览、LaTeX 编辑、取消和确认后单次撤销；不把 AI 视觉检查公式混称为专用数学识别。
- 错误或不支持结果保留原笔迹，并提供可操作提示。

验收：固定公式样本走数学请求链；结果可编辑、保存、导出和同步；识别失败原内容不变。

### F8a：围绕笔记内容的评论与讨论（P1）

- 对元素或区域添加评论、回复与解决状态，让问题和结论留在相关笔记旁边。
- 对象移动、删除或跨页后，明确跟随锚点和失效提示；评论不默认混入正文，不干扰正常书写。
- 房间成员权限、讨论内容加密、持久化和离线/重连行为需先定义，不直接复用普通私聊并假设两者安全边界相同。

验收：两人可针对同一段笔记讨论、定位与解决问题；对象变动不导致定位到无关内容；评论权限和保存行为与说明一致。

### F8b：关键版本与安全恢复（P2）

- 保存命名版本，先支持查看和比较；恢复前校验当前版本并保留恢复前备份，不静默覆盖协作者的新修改。
- 明确本地版本和房间版本的范围，恢复操作可追踪、可回退。

验收：版本与实际内容一致；并发编辑时不会错误覆盖新成果；恢复失败原笔记仍可访问。

### F8c：完整过程回看（P3）

- 确认复盘需求后，再考虑覆盖新增、修改、移动、删除、撤销与 AI 应用的完整回放，采用快照与操作记录控制体积。
- 现有输入录制器用于调试，不能直接视为产品回放。记录方式、保留期限、清理与加密边界须先明确。

验收：回放与真实内容变化一致，记录不会明显增加编辑延迟。该项不阻塞评论或关键版本功能交付。

### F9：服务卡片升级（P2）与系统意图入口（P3）

- F9a：扩展已有最近白板卡片，支持固定笔记、恢复阅读/编辑位置及快捷新建；正文预览由用户选择开启。
- F9b：在需求与能力条件确认后，将打开最近笔记、查找标题/标签等最小功能接入系统意图入口。
- 复用统一路由与现有卡片同步逻辑，兼顾冷启动与已运行状态；内容被删除时回到可恢复的正常入口。
- 不将房间密钥、未授权正文或完整协作链接写入卡片、系统索引与日志。

验收：真机冷/热启动定位正确；已删除目标可恢复；展示范围符合用户选择；系统入口不可用不影响应用内访问。

## 6. 开发、兼容与数据约束

1. 复用 Markdraw、Riverpod、资料库 Repository 和现有协作链路，不为单一增强重建编辑器或同步系统。
2. 平台差异收敛在适配层；共享业务不引入 `Platform.is*` 分支，缺少原生能力时提供可用回退。
3. 保持 Excalidraw 兼容。新增场景扩展字段、来源和讲解元数据时，先确定旧客户端、撤销、持久化与导出行为。
4. 协作实时消息及快照继续加密；鉴权、房主/观众权限由可信链路校验。创建者归属只用于显示，不用于授权。
5. 本地笔记不因登录同一账号自动视为已同步。当前主线通过经过校验的协作会话共同编辑；若将来单独立项设备接续，需明确内容和附件的传递，不能仅传本地 ID。
6. 索引、版本或来源等涉及数据库变化时，按现有幂等迁移规则验证新装、升级与重复打开。
7. 后续实现按独立功能分支、小批次提交与 PR 推进；每项完成后更新需求及相关接口/数据模型文档。
8. 开始实施、创建 PR、合并、部署分别记录状态。本计划存档不表示已执行这些操作，也不自动授权上线全部候选功能。

## 7. 验证方案与证据

| 验证层次 | 要求 |
| --- | --- |
| 逻辑与组件 | 先跑受影响既有测试；覆盖新增非平凡逻辑、关键交互、取消和过期处理 |

| 原生构建与真机 | 鸿蒙原生/通道改动按规范构建 HAP，再验证真实设备；安装包构建通过与原生交互行为通过分别记录 |
| UI 与输入 | 桌面、窄屏、分屏、横竖屏、大字号、主题、减少动画；覆盖键盘、鼠标、触控笔与软键盘 |
| 协作与恢复 | 双向连续书写、长笔、重连、切房、移出、撤销、附件与 AI 批量应用；核验最终内容一致 |

每个工作项保留构建 ID、设备/系统、样本、步骤、结果与截图或录像。原始包、完整日志等遵循现有忽略/归档规则；适合评审的脱敏证据放入 `docs/研发记录/evidence/`。

用户试用采用教学、会议或设计中的真实任务，记录操作步骤、误操作、来源查找与任务完成情况，不仅收集“看起来不错”的评价。

## 8. 决赛演示与交付

建议演示主线：

> 两位参与者进入同一份笔记 → 一人手写记录、另一人补充批注 → 针对某段内容评论并回复 → 自愿跟随查看同一区域 → 发起者校对并应用 AI 整理 → 双方看到结果并继续编辑。

支持手写笔的鸿蒙设备可在记录或整理步骤展示双击/轻捏；使用其他设备的成员通过正常工具栏完成相同任务。电脑和平板只是现场两位参与者的设备示例，双方可交换操作，不设置固定角色，不要求个人多设备接续。

使用能复现的样本，但流程执行真实识别、真实协作与真实确认；取消、撤销和恢复可现场展示。手机、智慧屏仅作为设备确认后的扩展，不进入当前必要设备清单。

交付包括：可安装的目标端版本、配套后端/Web 版本说明、设备兼容清单、操作脚本、测试与性能证据、已知限制、发布及回退记录。竞赛材料按官方模板与格式核对，展示视频按规程限制组织。

建立“功能 → 用户价值 → 鸿蒙能力 → 真机证据 → 评分对应”的材料表。项目内优先在鸿蒙发布某功能，不等于已经被认定为行业首创或赛事首发。
