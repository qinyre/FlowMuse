# 大 PDF 导入、频闪与滚动修复

## Context

用户反馈新建笔记导入大 PDF 后空白等待、灰色占位与页面循环闪烁、滚动卡顿。基于 main `271cb10` 排查：

- `PdfImporter` 等整份 PDF 渲染结束才插入场景，宿主没有导入状态。
- `importPdfPages` 再次逐页解码全部 PNG，未释放 Codec；`loadScene` 全量预热，`resolveImages` 每帧请求全部文件，超过 50 张 LRU 后不断互相驱逐。
- `StaticCanvasPainter` 虽裁剪普通元素，仍为全部页绘制阴影、纸张、模板，并构造全部页裁剪路径。

## 需求与边界

显示真实导入阶段；画面只请求可见区域及少量邻近图片；滚动不反复解码整份文档。保留原始图片字节、尺寸、分页、笔迹、撤销与 Excalidraw 格式，不降低画质，不改输入/压感管线，不安装设备。

## 实现方案与关键文件

1. `image_cache.dart` / `markdraw_controller.dart` / `editor_canvas.dart`：复用现有缓存与解码 Future；最新可见集合串行解码，快速滚动丢弃尚未启动的旧请求，可见图片不被后台回填驱逐；为非可见缓存增加字节预算。取消全文件预热与导入后的重复全量解码。导出按自己的区域预热，不能误用屏幕视口。
2. `static_canvas_painter.dart`：只给可见区域附近页面绘制底图、阴影、模板和裁剪；保留阴影边缘与跨页笔迹裁剪。
3. PDF 导入链与 `whiteboard_page.dart`：加载提示覆盖空白画布，渲染器支持时显示页数进度；保存和首屏就绪后再开放编辑。失败可见，退出后异步回调不可操作已释放的 controller/ref。
4. OHOS 原生渲染资源清理只使用本地官方文档/SDK 中已核实的 API；如修改通道，补 HAP 构建。

## 验证方案

- 大于缓存容量的合成 PDF/图片场景：首屏解码量、滚动后稳定、跳页过期请求、缓存预算、同 ID 复用、退出中断。
- 绘制指令和像素对比：多页与单页首屏一致，屏幕外页数不增加绘制调用；竖向与横向分页。
- 导入状态、失败、保存重开与封面/区域导出；既有 PDF、书写工作流、全量 Flutter 测试、analyze。
- 真机帧率、内存峰值和实际 PDF 等待时长留待设备可用后验证，不把单元测试结果称为实机性能结论。
