# 测试与 CI 执行优化

## Context

基于 main `3029a06f` 建立 `chore/test-ci-efficiency`。用户反馈 PR 等待约十几分钟，要求整体优化测试。基线包含 300 个 Flutter 测试文件；本地 machine 回归 2095 通过、5 跳过，耗时 132427ms。

已核对文档 PR #94：push 与 pull_request 各触发一次 Quality。PR Flutter job 耗时约 8 分钟，其中 pub get 85 秒、分析 40 秒、测试 330 秒；并非仅 SDK 克隆造成等待。

## 方案

1. Quality 在 PR、main push 及手动运行，取消功能分支 push 与 PR 双触发。始终回报原有 Flutter/Go 检查，路径判定失败须失败，不能把未执行当通过。
2. 只改普通文档时跑轻量策略检查，不安装 Flutter 或执行 Go。App/Server 独立选路；机读 docs、依赖、CI 和未知文件按保守规则扩大检查，支持删除/重命名。
3. 固定现有 OHOS Flutter 版本，统一缓存 SDK 与 Pub 依赖；不缓存测试通过结果或 `.dart_tool` 构建输出。Go 缓存明确指定服务端 go.sum。
4. App 变更保留完整回归，以 Flutter 原生两分片并行执行；全部分片与变更判定成功才能通过汇总检查。全项目分析只跑一次。
5. V3 的普通测试由完整分片覆盖；分片 1 保留严格局部分析，并追加确定性与 CI 工具自测，不降低旧矩阵的告警门禁。原完整矩阵保留手动诊断；平台矩阵在相关 main 更新/手动运行执行，不因每个分支 push 重复构建。
6. 仅移除确认无生产调用的 ThemeHero、专属 heroOverlay 配置与其测试。将依赖宿主墙钟的首页 3 秒断言改为真实首页可用性冒烟，保留业务验证；保存、撤销、加密、同步、兼容与 V3 契约回归不删。

## 验证

覆盖路径判定、普通文档与机读文档边界、未知路径、删除/重命名及无效 base；检查汇总门禁在判定失败、任一分片失败/取消/跳过时拒绝通过。验证工作流语法，运行本地分析、两分片完整回归和 V3 独立检查。更新开发约定与测试说明，记录实际运行条件；不预先承诺缓存冷启动或托管 runner 的提速数字。

## 实施与验证结果（2026-10-27）

- 已完成上述执行链路调整，选路与汇总只稀疏检出 `.github/scripts`，比较 base 时只取浅层元数据，避免额外下载文档视频/应用资源。工作流保留原有 Flutter/Go 状态名；选路失败、必选分片失败/取消/跳过均不能通过汇总。
- Node 策略自测 3 项通过，包含真实临时 Git 仓库的删除/跨目录重命名，以及浅克隆/稀疏检出后补取 base 的 CLI 路径；另实际检查 CLI 在失败/取消/无效 base 下非零退出。未引入新依赖。
- actionlint 1.7.12 检查全部 GitHub 工作流通过；YAML 结构解析通过。V3 CLI 将 report/workdir 从仓库根解析，artifact 保持根目录相对路径，并显式允许上传该精确路径内的隐藏文件。
- 分片 0：1125 通过、4 跳过，92919ms；分片 1：968 通过、1 跳过，103151ms。机器事件逐项比对确认无重叠，除删除的两个 ThemeHero 用例及替换的首页用例外，原用例全部保留。总计 2093 通过、5 个原有跳过。
- 本地分片依次执行，SDK/Pub 已就绪；上述时间不等于双 runner 并行实测，不能直接宣称 GitHub 提速比例。
- 全项目分析无问题，V3 严格局部分析无问题；V3 确定性两轮各 82 项通过、漂移 0，CI 工具自测 11 项通过。主题清理后追加相关 3 项回归与全项目分析，均通过。
- Go `test ./...`、`vet ./...` 通过；未配置的数据库集成与既有在线测试不作为新增实测证据。协议 fixture 也被 Go 测试直接消费，因此机读 docs 的选路同时包含前后端。
- AGENTS、开发约定和 README 已对齐风险分级，本地普通 UI 小提交不再要求反复跑整套；源码 PR 仍完整覆盖。GitLab 私有 runner 配方未改动，未运行六端构建/实机，未测量新 GitHub 工作流的冷/热缓存耗时。
