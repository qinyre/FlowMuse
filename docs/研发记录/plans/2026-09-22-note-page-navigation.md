# 笔记页码、多页预览与跳转计划

## Context 与结论

日期：2026-09-22。分析基线：本地 `fix/app-icons` 分支 `f67f518`。实现分支：`feature/note-page-navigation`。状态：**导航、预览与阅读恢复已实现，自动化正确性通过，实机性能待验收**。

用户希望 PDF 和多页笔记能够显示明确页码、浏览多页缩略图、直接跳到指定页；大文件不能靠长距离滑动定位。继续遵守此前的书写要求：笔迹效果、点触、压感、流畅度与实时性不得回退。

建议沿用现有单场景、连续分页画布，增加本机导航 UI。页码从已有页面顺序派生，跳转只改视口，缩略图按需生成。无需把每页拆成独立编辑器，无需新建页面数据库表、替换 PDF 插件或改协作协议。

首轮交付包含：页码、上一页/下一页、数字跳页、缩略图总览、回到跳转前位置、恢复阅读位置。页面删除/重排、书签、PDF 目录和印刷页码另列后续范围。

### 1.1 本轮诊断证据

在被 Git 忽略的 `FlowMuse-App/build/page-navigation-analysis/diagnostics_test.dart` 中运行了四个临时诊断，另运行大 PDF 与触摸添页既有测试，共 **11 项通过**。诊断断言记录的是当前行为，不表示缺陷已经修复。

1. **软删除页仍参与布局**：`Scene.elements` 包含 tombstone，`CanvasLayout.fromScene` 未检查 `isDeleted`；只有一个已删除页框时，活动元素为空而页面列表仍有一页。影响协作删除/历史恢复后的页数。
2. **混合尺寸页面添页会重叠**：构造两页，高度分别为 2000、1000，初始第二页顶部为 2096；调用 `insertBlankPage()` 后第二页顶部变成 1096，与第一页重叠。原因是重排按 `index × 本页高度` 计算，而非累计前页实际高度。
3. **当前页不一致**：同一文档在视口顶部 1000、高度 1600 时，中心法返回第 2 页，面积法返回第 1 页。
4. **跳页基础可复用**：`scrollToPage(1)` 保持同一个 Scene 对象，未创建撤销项，未触发场景变更监听。

日志：`FlowMuse-App/build/page-navigation-analysis/test.log`。这些本地诊断不是持久化回归资产；实施时将相关缺陷改为正式、预期正确行为的回归测试。

### 1.2 需要避免的直接搬用

- 不用 `loadScene`、`applyScene` 或 `closeTransientUiForSceneReplace` 实现翻页；它们有替换场景、处理文本或历史记录的副作用。
- 不为每张缩略图创建 `MarkdrawController/MarkdrawEditor`；否则会重复持有工具、场景、输入与缓存。
- 不对所有页面并行调用 `prewarmRegionImages + exportRegionPng`。预热使用正文缓存且暂停其解码完成通知，可能拖慢正文显图；预览应拥有自己的有界资源。
- 不直接使用智能排版的 `DraftSceneRenderer` 生成导航缩略图。它还会解码传入场景全部图片并采集排版证据，超出导航需要。
- 不认为 `async` 就等于不占主线程。图片输出缩小也不能证明解码瞬时内存等比例降低。

## 2. 功能范围与页面语义

### 2.1 页码定义

- 显示 **笔记物理页序**：`当前页 / 总页数`，从 1 开始。计数包含 PDF 页和追加的模板页。
- 页面引用使用稳定 `pageId`；显示数字使用有效页面列表的位置加一。不能从 `page-123` 截数字作为页码，也不能把可能不连续的持久化 `pageIndex` 原样展示。
- PDF 内印刷的 `i、ii、1` 或自定义 PageLabels 与物理页序是不同概念。首期显示“第 12 页”，不声称识别原文印刷页码。
- 页面顺序沿用布局顺序；古籍从右到左排列时，第 1、2、3 页仍按阅读顺序递增。
- 当前页定义：以实际可见区域内占用面积最大的页为主；面积相同选择顺序靠前者；视口位于间隔时取最近页。与现有 `pageForVisibleRect` 对齐。
- 主画布当前页和用户正在总览中浏览的页分别维护。滚动总览不会改变主画布页码，点击卡片才跳转。

### 2.2 文档类型

| 文档 | 首期处理 |
| --- | --- |
| 正常导入 PDF | 使用现有页框列表；底图、批注、混合尺寸都保留。 |
| 普通分页笔记 | 同一套导航，支持所有模板和现有末尾添页。 |
| 导入 `.excalidraw/.markdraw` 且有合法分页元数据 | 恢复原有页序后导航，无须用户重新分页。 |
| 无界笔记或无分页元数据的普通外部画板 | 保持无界。入口显示“画布总览/回到内容”，不根据笔迹包围盒强行切成若干页。 |
| 只有 PDF 底图、缺少页框的旧数据 | 在 P0 用真实样本检查；可靠的一图一页标记可形成只读导航描述，不能静默搬动内容或保存伪造页框。无法可靠恢复时保留原画布并说明缺少分页信息。 |
| 空笔记、损坏页框或重复标识 | 空分页笔记保留正常第一页；过滤 tombstone，校验有限正尺寸和可用标识。异常数据不得导致除零或跳页越界，也不自动重排用户内容。 |

### 2.3 首期界面

导航控制组示意：

```text
画布右上角：
[上一页]   [12 / 248]   [下一页]
[页面总览] [适合当前页] [返回位置]
               ↓ 点击页码
          跳到第 [  ] 页
            共 248 页
            [取消] [跳转]
```

1. 页码导航独立固定在画布右上角，使用两行紧凑布局，不跟随撤销/缩放控制组移动；宽屏时与顶部工具栏顶端对齐，使用原生 `NavigationToolbar` 为两者分配空间，窄屏保留上下避让；右侧工具栏、属性面板与预览面板避让其位置。第一页/末页分别禁用上一页/下一页，只读模式仍可导航。
2. 点击数字打开紧凑跳页输入。仅接受 `1..N` 的单个整数，支持数字键盘、回车和粘贴；非法内容原地解释，不能把 `9999` 悄悄夹到末页。
3. 点击总览按钮打开缩略图面板，首屏直接定位当前页所在行，不从第一页逐项滚过去。
4. 卡片包含实际页面比例的缩略图、数字页码和当前页标识；选中状态不只靠颜色。空白页仍绘制对应纸张模板。
5. 大屏采用可关闭的侧面板，宽约 260–320 逻辑像素；窄屏用可滚动底部面板/全屏总览。使用现有 compact 判定与主题，不按 Android/鸿蒙硬编码分支。
6. 卡片外框采用固定行高，内部 `contain` 保持页面比例，使横页、竖页和古籍页不会撑出不同的列表行高。窄屏可用双列，大屏按实际空间排布。
7. 点击卡片立即导航。窄屏随后关闭总览；宽屏允许保留面板连续浏览，但书写时停止更新预览。提供关闭按钮及“定位当前页”。
8. 文本输入栏在打开跳页时才获取焦点；关闭后恢复原编辑焦点。触控目标至少 44–48 逻辑像素，沿用 `HoverTooltip` 与 `Semantics`，保证手写笔单击可用。
9. 当前卡片进入视口即可停止自动滚动。用户手动浏览其他页时，总览不能被主画布的小幅滚动反复拉回。

宽屏面板的尺寸变化只在打开/关闭时发生，保持主画布的页面锚点和缩放，不能因缩略图陆续完成而重复改变画布大小。与素材库、属性面板、AI/排版面板避让，必要时互斥展示。

## 3. 导航行为与安全边界

### 3.1 跳转

- 统一经过一个页面导航入口，内部复用 `scrollToPage/setViewport`，按 `pageId` 在执行时重新解析当前位置。
- 默认保留当前缩放；一般定位目标页起始位置。若当前缩放可同时容纳多页，则让目标页居于视口中心；临近文档两端受边界约束时不伪造“当前页”，可短暂提示“已定位第 N 页”。
- “查看整页”是独立动作，复用 `ViewportState.fitToBounds` 与现有缩放上限；不改 `resetZoom` 和 PDF 默认初始适配语义。
- 从第 1 页到第 200 页直接切换目标视口，不动画经过中间 199 页，不触发中途图片解码。短距离也先采用即时定位，动画后续按性能证据决定。
- 保留一个“跳转前位置”，供“返回原位置”使用；不用撤销栈实现，也不增加复杂阅读历史。
- 导航不修改选择、笔型、粗细、压感、页归属、元素版本或内容；不触发自动保存整份 Scene，也不广播文档变更。原有可见区域 presence 仍按现有节流更新。

### 3.2 正在书写、拖拽或编辑时

- 手写笔未抬起、对象拖拽/变形、双指缩放或截图选区正在进行时，不立即执行翻页/开关侧栏；按钮给出不可用状态，快捷键也走同一检查。
- 不以切换到抓手、取消工具或清空 overlay 的方式“结束”活动笔迹。按正常 pointer-up/cancel 语义结束后，用户即可导航；不保留突然执行的远期跳页命令。
- 文本编辑先走现有 `commitTextEditing`，保留正常文本撤销语义，再进行导航。中文 IME 组合输入尚未完成时不抢焦点或提交半个词。
- 导入/打开未完成时暂不启用导航。智能排版草稿应用阶段沿用原输入冻结边界，不能在确认时跳去另一页导致作用范围混乱。
- 需要暴露活动交互状态时，只提供读取现有状态的 getter；不引入第二套 pointer 状态机。`EditorCanvas` 自己处理的触摸滚动也需计入调度暂停条件。

### 3.3 快捷键与进度条

- 保留 PgUp/PgDn 当前“一屏滚动”的行为；新增“上一页/下一页”按钮提供真正按页导航。
- 首期通过 Tab/Enter 可达的页码按钮与输入框提供键盘跳页；若增加直接跳页组合键，先核查框架、浏览器与其他面板。不能覆盖已有 Ctrl/Cmd+G 组合、Ctrl/Cmd+Shift+G 取消组合，也不占用浏览器控制台等保留键。
- 新增键盘处理仅在对应导航控件或画布取得焦点时响应；跳页输入、中文输入、AI 文本输入与只读导航均有独立回归。
- 首期保留现有非交互细进度条，靠明确页码与总览解决定位。拖动进度条快速翻页放在后续，避免本轮新增一套与书写竞争的手势。

## 4. 数据、状态与已有缺陷的最小修正

### 4.1 页目录与当前页

1. `CanvasLayout` 仍是分页数据真源；新增导航状态仅持有页面列表的派生引用、当前 `pageId`、显示序号和总数。
2. `fromScene` 排除已软删除页框。删除信息仍保留在 Scene/协作中，仅不进入有效页目录。
3. 重排坐标改为按前页实际宽高累计游标；覆盖纵向/从右到左、混合横竖页。只修正真正发生的添页/重排操作，打开文档不主动重排。
4. 页码 UI 与 AI 当前页使用相同的“最大可见面积”语义；本轮不顺带改变分页边界约束的手势物理行为。边界约束所用中心计算与用户所见当前页要区分命名，避免误用。
5. 按 `(layout, viewport, canvasSize)` 缓存当前页结果。笔迹更新而视口不变时直接返回；同一帧内页码与进度条重复读取也复用结果。
6. 对正常单轴有序页面可维护主轴边界数组，二分定位候选后只比较可见页；建立索引只发生在页结构变化时。异常重叠/乱序数据回退现有遍历。是否需要此步以 P0 的 1000 页测量为依据，不能为按钮引入新的每笔 O(P) 遍历。

不额外保存“当前第几页”到文档页元素，不为显示页码插入文本对象。页码不会出现在导出的 PDF 底图、PNG 或笔迹选择中。

### 4.2 阅读位置

复用 `LocalSettingsRepository`，使用单笔记 key，例如 `whiteboard.readingPosition.v1.<noteId>`，JSON 记录：

```text
version, pageId, fallbackOrdinal, zoom, pageRelativeAnchorX, pageRelativeAnchorY
```

- 优先用 `pageId` 恢复；页面不存在时使用限制在有效范围内的旧序号。锚点是页内比例位置，尺寸/方向变化后再次约束。
- 数据来自本机设置，仍校验版本、类型、有限数字、页范围与缩放上下限；坏记录直接忽略。
- 完成跳页、滚动停止约 500–800 ms、离开笔记或进入后台时保存；活动笔迹期间暂缓，不能每帧写库。
- 恢复顺序：场景加载 → 分页有效 → 实际画布尺寸确定 → 设置边界 → 应用阅读位置 → 请求目标首屏。避免先解码首页后马上丢弃。
- 初次导入从首页开始；用新文件替换同一笔记时清除旧记录；临时协作笔记不落阅读记录。
- 读取与打开流程并行发起。用户已开始交互后到达的迟到结果不得把视口拉回；使用现有打开代际/笔记 ID 检查。
- 不把视口写入 Excalidraw Scene、撤销或协作快照，不因阅读位置变化更新笔记内容时间与封面。

## 5. 多页缩略图实现

### 5.1 按需构建

使用 Flutter 自带 `GridView.builder/ListView.builder`，固定卡片行高，明确 `itemCount`，只为当前可见卡片及最多相邻一行请求预览。`cacheExtent` 要有边界，不能用全量 `Column` 或无界 `shrinkWrap` 展开所有页面。

这与 Flutter 官方建议的惰性构建及局部状态更新一致；`builder` 只解决 Widget 数量，图片解码和渲染任务仍需单独限制。[Flutter 性能建议](https://docs.flutter.dev/perf/best-practices)、[GridView.builder](https://api.flutter.dev/flutter/widgets/GridView/GridView.builder.html)。

### 5.2 独立、有限的预览资源

- 复用 `StaticCanvasPainter`、页面模板与笔刷渲染算法；单独使用预览适配器/缓存实例，防止预览挤掉主画布已生成的笔迹路径。
- 不改变正文 `ImageElementCache` 的文件标识、分辨率与可见集。缩略图使用单独的小尺寸解码结果与页预览 LRU，不能把小图写回正文同一 fileId。
- 初始预算：预览成品最长边约 384 像素，按实际卡片/DPR 调整，上限 512；最多 32 项且最多 16 MiB 的已解码预览，任一达到即淘汰离屏项。此为待测初值，不是实测内存结论。
- 同时只生成一页。临时源图、Codec、Picture、输出 Image 都明确所有权；完成/取消/离开时及时释放。临时源图也单独计入峰值，不把 16 MiB 成品缓存当作进程总上限。
- 本地 SDK 已核实支持 `instantiateImageCodec(targetWidth/targetHeight, allowUpscaling: false)`；只指定一个维度时保持比例。但目标尺寸限定的是输出，并不保证解码内部不出现原尺寸内存峰值，Android/鸿蒙仍需测量。[官方 API 说明](https://api.flutter.dev/flutter/dart-ui/instantiateImageCodec.html)。
- 首期仅内存缓存，不把数百张缩略图写进 Scene、数据库或备份；原图字节仍由现有 Scene.files 持有，不在导航层再复制整份文档。
- 单次生成任务可以持有场景快照，完成后释放引用；缓存条目只留位图与版本标识，不能每个条目各保留一份历史 Scene，形成隐蔽的多版本内存增长。
- PDF 仍使用已导入的图片，不重新打开 PDFKit/pdfx 逐页渲染，也不增加平台通道。

### 5.3 页面内容正确性

- 缩略图包含底图、已提交的手写、文本、图片、图形和模板；不展示本地未提交湿墨、光标、选择框与拖拽手柄。
- 沿原 z 序和原页面裁剪绘制。候选内容依据**真实可见边界与页框相交**，不能只筛 `element.pageId`，否则旧笔记缺归属、跨页对象与旋转对象会丢失。
- 对绑定文本、Frame 子项和箭头标签保留必要依赖；不得借用智能排版的“可移动参与者”筛选规则，因为导航也必须看到锁定内容。
- 页面预览始终显示完整已提交内容，不随协作者归属聚焦变淡。
- 当前 `exportRegionPng` 设置 `skipMathText: true`，公式由画布 `_MathTextOverlay` 单独显示。完整预览必须复用现有 `Math.tex` 呈现补上公式，而非遗漏或显示原始 LaTeX。仅对可见卡片构建必要公式层；复杂页的光栅化放在无交互时执行并单独验收。
- 不通过移动主画布再截图来生成缩略图。若抽取共用公式呈现，需要冻结现有画布公式像素/布局，只搬公共组件，不改样式算法。
- 坏图单页提示“预览暂不可用，点击仍可跳转”，不阻塞其他页，也不替换或删除原文件。

### 5.4 调度、失效与取消

1. 面板关闭时不创建缩略图任务、解码器或后台定时刷新。
2. 快速滚动总览时取消尚未启动的旧请求；已开始且底层无法取消的解码结束后检查代际，释放结果。禁止迟到结果回填另一个笔记/另一版本。
3. 每页请求绑定 `note/session generation + pageId + content revision + output size + theme/template`。缓存命中时复用；页码变化只更新标签，身份仍以 pageId 为准。
4. 优先级：活动输入与正文可见页 > 正文目标页准备 > 可见缩略图 > 邻行预览。正文缺图时预览队列不继续开新任务。
5. 活动书写、拖拽、缩放、主画布滚动或总览快速滚动时暂停生成；交互结束并空闲约 200–300 ms 后按需恢复。每个 await 返回后再次检查状态。
6. 普通内容变更先做轻量失效标记，空闲时处理。结合 `lastChangedElements`、已有缓存的页范围及旧/新可见边界，失效受影响页；移出某页的元素也要让旧页失效。
7. undo/redo、远端全量替换或无法确认变化范围时作废缓存代际，只重建可见页；不立即扫全书重画。
8. 缩略图卡片自己刷新，不能每完成一张就调用主 `MarkdrawController.notifyListeners()`，以免重建主编辑器。总览面板保持稳定子树，只有导航状态/可见窗口变化才更新；不能因为父编辑器已有的高频 `setState` 而让全部页卡跟着每笔重建。`RepaintBoundary` 只隔离绘制，不代替这一层构建隔离。
9. 所有生成请求都绑定不可变 Scene/布局快照；若生成期间页面改变，成品先校验版本再发布，旧图可短暂保留但不能标成最新内容。

首期优先复用绘制器和已有裁剪，不先建设全书空间索引。如果重内容页的同步绘制超过预算，先保留已有预览/页号并推迟到纯总览交互结束后，再按测量结果分块生成静态 Picture。不能用“缩略图异步”掩盖主线程长任务。

## 6. 书写与大文件的验收门槛

“不影响书写”必须作为合入门槛；代码结构能限制风险，但仅靠设计或单元测试不能证明 Android/鸿蒙实机延迟完全不变。

| 维度 | 必须满足 |
| --- | --- |
| 内容正确性 | 同一输入回放的最终笔迹数据及冻结像素不变；点触不消失，抬笔不漏末点。 |
| 输入热路径 | 每次 pointer move 不增加文件/数据库访问、缩略图生成或全场景遍历；页码在视口不变时不重算。 |
| 面板关闭 | 新增缩略图解码、渲染与后台轮询数为 0；仅保留小型导航状态。 |
| 面板打开时书写 | 冻结预览更新，只保留已缓存卡片；输入响应优先，不因刷新卡片产生主画布全量刷新。 |
| 跳页 | 修改视口，不产生 Scene 更改、历史项、文档保存或内容广播；目标卡片无预览也能跳。 |
| 大 PDF 解码 | 继续只请求正文可见页与既有少量邻近页；1→200 不遍历加载中间页；原 200 页缓存稳定测试保持通过。 |
| 缩略图规模 | 活跃卡片、排队任务与解码成品受可见窗口及预算限制，不能随全书页数无界增长。 |
| 退出/快速切笔记 | 过期任务不写入新笔记；Codec/Picture/Image 与监听器释放，反复开关后无持续内存增长。 |
| 性能证据 | 同设备/同刷新率/同文件/同输入回放做基线与新版本 A/B，交错运行至少 5 轮；比较输入到首次绘制及连续绘制 p50/p95/p99、丢帧和峰值内存。 |

性能使用已有 `integration_test/whiteboard_writing_perf_test.dart`、`ActivePreviewMetricsProbe` 与 `WritingPerformanceReport`，扩展 PDF 场景及“导航关闭/打开/正在更新”状态，不另造一套测量口径。

可把“UI/raster p95 增加超过 1 ms 或输入到绘制 p95 增加超过 5%”作为初始调查触发线，**不是允许回退的指标**。必须结合重复实验的自然波动检查 p99、点触和突发长帧；确认有新增回退则暂停预览更新或修正原因后再合入。新功能的交互目标：页码反馈一个正常帧内完成、总览骨架/页号约 100 ms 内出现；目标页高清图耗时另测，不能拿骨架出现时间代替加载时间。
