# 协作房间二维码分享与扫码加入

## 需求与范围

- 用户明确本轮覆盖安卓 App 和 Web；系统相机扫码默认直接打开 Web，评委无需加好友或安装应用。
- 同一个 HTTPS 房间邀请二维码支持：安卓 App 内扫码、Web 页面内扫码、手机系统相机识别链接进入 Web。
- 复用现有访客入房、`CollaborationRoom.parse`、`#room=` 邀请和临时协作页面。不新增房间协议、好友关系、登录要求或数据库字段。
- 鸿蒙原生扫码、系统相机唤起已安装 App、人数限制与移出成员不在本轮范围。其他端仍可复制/粘贴邀请及生成二维码。

## 实现方案

1. 房间分享面板用纯 Flutter QR 编码组件展示已有完整 HTTPS 邀请；保留复制链接、系统分享和邀请好友。已创建房间可再次打开分享面板。
2. 共用“加入房间”对话框添加扫码按钮。扫码成功仅解析 FlowMuse 房间数据并复用原有加入路径，不执行扫描所得外部 URL。无效二维码给出提示且可继续扫描；取消、拒绝相机权限或无摄像头时保留粘贴入口。
3. 扫码通过平台适配分发：Android 和 Web 使用 mobile_scanner；其他原生端不展示尚未支持的内置扫码入口。相机仅在扫码界面运行，关闭、切后台和销毁时释放。
4. Web 扫码解码资源随站点部署，避免现场依赖第三方 CDN。二维码始终保持黑白对比与留白，不叠加标志；窄屏可滚动或约束预览高度。

## 涉及位置

- collaboration/widgets：分享二维码、扫码对话框、已有 JoinRoomDialog。
- collaboration/services：平台适配及 Web 扫码配置。
- views/whiteboard_page.dart：已有分享面板和菜单回调。
- pubspec 与 Android 相机声明；Web 解码资源和第三方许可。
- 相应模型、widget、路由测试与需求、接口文档。

## 验证

- QR 数据为当前房间完整邀请；从系统相机取得的 HTTPS 链接可直接路由到访客协作页。
- 无效/空二维码、重复扫描、取消、无摄像头及权限拒绝；不打印房间密钥和扫码原文。
- 从资料库和白板两个加入入口都可扫码；房主可重复打开二维码面板，窄屏布局不溢出。
- 相关测试后跑全量 Flutter 测试与 analyze；编译 Web release 和 Android ARM64，核对新增依赖与原生库架构。没有实机扫码证据时明确保留待验收项。
