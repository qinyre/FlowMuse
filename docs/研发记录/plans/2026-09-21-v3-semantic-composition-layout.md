# V3 智能排版效果提升：语义成组与整页构图实施计划

> 日期：2026-09-21。状态：实施中，阶段状态见 §14。
> 代码基线：`main @ 3356c9abaf81be920df941038ee9f8dbac085498`（PR #38 已合并）。
> 实施分支：`feature/v3-semantic-composition`。本轮不推送、不部署、不操作测试笔记。

## 1. 要解决的问题与最终目标

当前 V3 已能识别手写、分析整页概览、返回部分图文关系、生成可应用和可撤销的候选。但“内容识别出来并移动到页面里”不等于“排版效果良好”。这次工作的交付物是**默认推荐就能把一页笔记整理成有内容关系、阅读顺序、字号层级和留白节奏的版面**。

具体目标：

1. 当前页应处理的文字和图片进入同一分析范围，不出现“账本通过，但某张可见图片根本没参与分析”的误导。
2. 先判断标题、章节、正文、列表以及图文归属，再决定位置；相关图片和文字作为一个内容组参与整页布局。
3. 同时具备图上文下、图文并排、同级图文组并列和普通正文流式布局，能够按内容选择，而不是仅换一个单栏/双栏名称。
4. 字号、图片尺寸、行长和间距按同一个页面尺度协调，内容少不压成角落里的小字，也不为了填满页面把图片无限放大。
5. 排名基于最终可见结果：拆散图文、阅读顺序错误、样式在应用时变化的结果不能成为高分推荐。
6. 原文、图片资产、裁剪、保留元素和撤销能力不退化；保留现有可编辑元素，不把整页拍平成图片。

**不以新增模板数量、分数超过某个值、测试数量或任务完成数量作为效果完成标准。**

## 2. 已确认的现状及尚待查明的问题

### 2.1 本次实测事实

测试笔记含一个标题、狗图及说明、猫图及说明。用户确认猫图仍在，但与对应文字分离，整页位置显得随意。

| 观察 | 结论及边界 |
| --- | --- |
| 候选里猫图仍可见，但位置不合理 | 不能将这次问题描述为“猫图被删除” |
| 内容块列表只有标题、正文、图片、正文四块 | 与预期的两张图片不一致，需要追踪图片进入分析的全过程 |
| 详情显示 128 个源全部已消费 | 只能证明已纳入账本的源已处理，不能证明页面范围选择完整 |
| “保守重排”和“单栏阅读”都为 0.936，视觉近似 | 候选差异和评分并未充分反映实际版面质量 |
| 预览黑色文字，应用后出现红色文字 | 存在创建工具默认样式覆盖排版结果的接线风险，代码已核实 |
| 原笔记可通过撤销、重新打开恢复 | 沿用既有事务与历史机制，无需重建撤销系统 |

本地证据位于 `FlowMuse-App/build/`：`flowmuse-v3-result.png`、`flowmuse-v3-single.png`、`flowmuse-v3-details.xml`、`flowmuse-v3-block-options.xml`、`flowmuse-v3-applied-zoom.png`、`flowmuse-v3-reopened-original.png`。这些是当前机器的排障证据，不是已经入库的可移植 Scene fixture。

此前单次运行约 20 秒，主要耗时为识别与 structure 两次模型调用，本地候选生成约 0.43 秒。它只是一个样本，不代表 p50/p95 或稳定性能指标。本计划不通过增加逐图、逐候选模型调用来换效果。

**待查明：**猫图究竟因 `pageId`、源过滤、语义保留、原生组合闭包还是别的原因没有成为可排图片块。当前代码存在按 `pageId` 精确过滤的路径，但未取得该笔记原始元素元数据，不能把它写成已证实的唯一根因。

## 4. 整体设计：AI 判关系，本地负责排得好看

处理顺序固定为：

1. **统一页面捕获**：得到同一代次、同一范围的源元素、图片资产和页面坐标。
2. **识别及语义恢复**：原生文字直接读取，手写沿用 V3 OCR；一次 structure 判断角色、阅读序、章节和图文关系。
3. **内容组构建**：普通正文、列表、图片及对应说明、受保护原生组合成为可布局的节点。
4. **组内排版**：用真实文本测量决定图上文下或图文并排，并得出整个组的宽高。
5. **整页构图**：标题、章节、内容组按阅读顺序流式安放；同级短组可并列，长正文保持连续。
6. **物化与验证**：沿用 patch/reducer/renderer，从最终场景检查完整性、阅读关系、样式和几何。
7. **去重与推荐**：淘汰不合格候选，再按实际质量排序；可以推荐“保留当前布局”。

这不是新增一条 V4，也不是在现有候选后追加一个大模型“美化”请求。主要改动集中在现有 V3 的块装配、放置、评分和校验消费端。

### 4.1 唯一真值与最少新增数据

| 数据 | 归属与约束 |
| --- | --- |
| 原始 Scene、图片资产、原生文字 | 当前编辑器快照为权威；分析期间只读 |
| OCR 原始结果、区域源归属 | 现有识别结果和识别账本为准；不被构图器改写 |
| 角色、阅读序、关联 | 同一 `SemanticDocument` 为权威；纠错更新这里 |
| `ResolvedPageScope`（新增轻量值对象） | 目标页、纳入源 ID、背景 ID、归属异常 ID；由一次捕获产生，不持久化新 Scene |
| `ContentGroup`（新增组描述） | 只引用已有 blockId；类型、成员顺序和关系来源，不再次拥有 sourceIds |
| `PageCompositionPlan`（新增派生产物） | 组树、版式选择、测量结果和预期关系；由语义文档和页面约束确定性生成，不成为可独立修改的第二语义文档 |
| `DisplayTextProjection`（新增轻量值对象） | 原文指纹、已批准的软换行位置、显示文本；不是另一份 OCR 真值 |
| block → output 映射 | 由 materializer 在创建/变换元素时产出，校验层据此定位真实元素 |

优先在现有模块补值对象与纯函数，不为每个名词各建服务、接口或工厂。语义扩展放入现有 `SemanticDocument.extras` 的版本化 `composition` 字段，并提供集中解析/校验，禁止各层随意读取散落的字符串键。

### 4.2 三条不可破坏的约束

- **源不重领**：每个源仍只有一个 consumed/preserved 终态。章节和内容组只引用块；一段说明对应多张图时显示一次，不复制正文来“配齐”。
- **关系不混用**：章节归属不意味着整章不可拆；标题只需与首个正文/内容组保持邻接；图文组有组内布局；已有原生 group/frame/binding 闭包按既有变换契约处理。
- **最终真值可追踪**：每个应当消费的语义块必须映射到实际输出元素；不得只证明旧笔迹被删除，却不证明替代文字或图片存在。保留源必须仍在且未改写。

## 5. 第一件事：统一页面范围，解决“看得见但没排进去”

### 5.1 一次解析，多处共享

在 V3 捕获入口解析范围，SnapshotExtractor、RecognitionCapture、overview、语义装配和候选验证使用相同的源集合。完整 base Scene 继续用于物化和应用，不能为了范围一致把其他页面从原笔记删掉。

范围规则：

1. 正常且明确属于目标页的活动元素纳入；页面框/PDF 底图单独记为背景，不送去识别成正文。
2. 无 `pageId` 的历史元素，仅当保守视觉包围盒完整位于唯一目标页面内，且其 group/frame/binding 闭包没有跨页冲突时，允许在本次 V3 内临时归入。其他情况保留并说明，不猜所属页。
3. 明确属于其他有效页的元素，不因视觉相交而抢入当前页。指向已不存在页面的元数据按异常归属处理，须结合唯一页面包含关系判断；不能直接等价为当前页。
4. 同一原生闭包不能只纳入一半。锁定、缺图、跨页闭包或不支持元素成为固定保留对象，构图须避让。
5. 不修改原始 pageId，不修改共享编辑器的页面归属规则。V3 的 snapshot 接受本轮已解析范围；旧调用不传时保留原行为。
6. 对页面内可见但未纳入的非背景元素记录数量和原因。存在这类异常时显示“部分整理”，不能仍宣称整页全部完成。

最终页界/覆盖验证也使用同一 scope：其他页完整保留，但不因其他页元素处在当前页框外就拒绝候选。进入当前页视觉范围的未选中元素仍作为固定上下文，不能被新布局覆盖。闭包与变换代码如需有效页归属，读取本轮解析结果，不偷偷回写原始元数据。

没有明确页面框的无限画布，本轮使用既有可确认的页面/选择范围，不用整个无限画布包围盒猜测多个笔记区域。无法确定时保留现有范围并报告局限。

### 5.2 本次猫图的排查与完成口径

按“原始元素 → scope → snapshot → recognition unit → semantic block → group → placed block → patch → reduced Scene”检查两张图片的 ID 和状态，只在开发诊断里输出计数、状态和不可逆标识，不打印整页正文/凭据。

取得原始 Scene 后，新增对应的最小回归 fixture；未取得时用“缺 pageId、有效他页归属、无效旧页归属、原生闭包”控制样例验证范围规则，明确真实案例根因仍待复现。不得写死猫/狗关键词、128 个源或某张图片 ID 作为产品逻辑。

## 6. 语义分析：从成对连线升级为内容组织

### 6.1 先消费现有能力，再扩展协议

A、B 包使用已有 roles、readingOrder、listGroups、captions、figureTextLinks 就能完成双图双说明场景，不依赖后端先升级。C 包只补当前协议无法明确表达的章节和多图共同说明。

既有关联的模型 confidence 不是准确率。沿用当前 `>= 0.8` 作为初始准入阈值，同时检查端点、角色、冲突及可见资产；以固定样例评估误配/漏配后再调整。低置信和冲突关系不强配，不用“最近的一张图”伪装语义匹配。

### 6.2 C 包的最小结构扩展

继续使用 `/api/ink/smart-layout/recognize/v3`、`schemaVersion: recognition-v3/1` 和既有 structure 阶段，新增请求能力 `includeCompositionHints: true`，只在协商时返回 `compositionHints`。不增加 endpoint/provider。

新增响应对象的初始字段：

| 字段 | 约定 |
| --- | --- |
| `version` | 固定 `composition-hints/1` |
| `pageIntent` | `reading / comparison / mixed / unknown`；只用于候选优先级，不控制几何 |
| `sections` | `[{sectionId, headingUnitId, memberUnitIds}]`；第一版仅一层章节，成员有序、章节不交叉，页总标题可不属于章节 |
| `mediaGroups` | `[{groupId, figureUnitIds, textUnitIds, confidence}]`；至少一图一文，文字仅 body/listItem；一块最多属于一个 mediaGroup；多图共用说明只出现一次 |
| `softLineBreaks` | `[{unitId, newlineIndexes, confidence}]`；仅 OCR 文字中的换行编号，从 0 开始；只提示可重排的软换行，不返回正文 |

已有 roles/listGroups/captions/readingOrder 仍必须按原协议完整返回。图注关系继续由 captions 表达，装配时并入对应图文组；不能在 mediaGroups 中把 caption 重新当正文。所有层级成员都必须来自同一次请求，不能跨页引用。

section 的 headingUnitId 必须为 title 角色，不重复列入自己的 memberUnitIds；页标题与章节标题由这个归属区分，不新增冲突的 role 枚举。mediaGroup 及其图注必须能在阅读序中连续展开，列表按完整子树处理。组成员跨章节、交错且无法保持正文顺序时，拒绝该结构结果或保留受影响组件，不靠静默改写阅读序让校验通过。

为避免两套图文关系成为双真值：新模式与 `includeFigureTextLinks` 互斥，新客户端只请求 composition 模式；服务器在新模式不输出旧 figureTextLinks。旧客户端仍按旧能力收到原键集。新客户端接收旧模式或本地回退时，将已有 links 一次性转为相同的客户端组表示；进入语义文档后不保留两套可独立编辑的关系。

Dart/Go DTO、严格字段解析、模型提示、服务端响应序列化和客户端校验一起修改。数组空值规则、非法 ID、重复成员、跨组冲突、正文偷渡和无穷/NaN 数值均要测试。新能力依赖服务端先发布；遇到旧服务端拒绝未知能力时，本轮明确降级到已有本地结构，不自动再发一轮模型请求。

### 6.3 结构合并与降级

- 页意图未知：本地默认阅读型，不影响有效图文关系。
- 没有真实概览：可判断文字结构，不自动新增依赖图片内容的 mediaGroup。
- 协议非法：沿用现有结构失败路径，不接收半合法模型 JSON。有效响应与本地锁定/保留规则发生冲突时，仅降级受影响组，其他独立组继续。
- 模型返回章节层次不能拆分一个 OCR unit。块内混合标题/正文的细粒度识别不在本轮伪造；保留或按较保守角色展示，并记录限制。
- 较长说明与多个图有关时先支持“同组多图 + 一次正文”，不做任意多对多交叉连线求解。

## 7. 内容组排版与页面尺度

### 7.1 四种排版原语

| 原语 | 适用条件 | 内部约束 |
| --- | --- | --- |
| 正文流 `textFlow` | 标题后的正文、章节、列表 | 保留段落/列表层次；标题与首项邻接，正文可按既有能力换栏 |
| 纵向图文 `mediaStack` | 窄页面、较长说明、图像需要较宽空间 | 图片与对应说明同组；图注贴图；不把另一个组插进来 |
| 横向图文 `mediaSide` | 空间足够，说明短到中等 | 图文左右并排，组高为两侧实测最大值；正文不能缩成窄条 |
| 同级组并列 `peerGrid` | 2–4 个同级短组，比较/示例意图明确 | 每行最多两组，组内各自完整；较长组自动转纵向，不拼成杂乱瀑布流 |

“纵向/横向/并列”是组内及同级组关系，不是新的用户模板库。不让模型指定 x/y；本地根据空间与测量选择。

### 7.2 两级放置算法

1. 从语义关系构造组：先处理原生闭包，再构造 mediaGroup，再设置章节及标题邻接。闭包合并产生的 block 别名必须同步到关系、阅读序和 output 映射。
2. 每个组在给定宽度下最多测量两种内部形式：stack 与 side。纯文字沿用真实排版测量，已测结果按文本指纹、字体、宽度与策略版本复用。
3. 横排预筛：可用正文宽度至少容纳约 12 个当前字号的全宽汉字；图片不能低于该组可辨认下限；不满足则直接 stack。最后以 TextMeasureAdapter 的实际结果决定可行性。
4. 外层流式放置组盒子：组内坐标转成同一页面坐标，再交给现有 materializer；不是先放文字再把图片就近塞空洞。
5. 标题与首个组保持邻接；章节只限制阅读连续性，不能借 union-find 把整页变成一个巨型不可拆组。
6. 保留对象、锁定对象和原生图形组合按真实边界作为固定障碍。对无法安全绕开的关系组件整体保留，不仅留下图片却把其强关联说明搬走。
7. 放不下时按顺序尝试：减少可压缩空隙 → 改组内形式/从并列改单列 → 在下限内统一缩一级 → 安全保留受影响组件。禁止裁字、丢图、只移动半个原子组或新增隐藏分页。

超长单个文本块本轮不新增“一个源拆成多个可编辑框”的复杂机制；已有能力不能容纳时保留该块及必要依附对象，并给出明确原因。

### 7.3 协调字号、图片与留白

以下是待样例校准的**第一版工程初值**，不是已经证明最佳的美学常数。集中于一个 V3 composition policy；保留旧 `SmartLayoutDesignTokens.v1` 的值和指纹，不把其名字里的 v1 误认为可以改动旧 V1 功能。

以明确页面框宽度为 1024 的归一化坐标工作，最终再映射回世界坐标。没有页面框时使用已确定的布局区域，不取屏幕缩放值。相同页面在不同 zoom 下必须产生相同结果。

| 参数 | 初值及限制 |
| --- | --- |
| 页面横向边距 | 48；页面内部仍须尊重固定障碍 |
| 正文 / 页标题 / 章节标题 | 24 / 36 / 30；允许统一紧凑档 22 / 33 / 28，不逐块随意缩小 |
| 图注 | 20；图注角色不能为缩小正文而伪造 |
| 行高 | 正文 1.35；标题 1.2；测量与最终元素取值一致 |
| 组内图文间距 / 组间距 / 章节间距 | 16 / 32 / 48；同一关系级别统一；紧凑档不小于 12 / 24 / 36 |
| 横排图片占组宽 | 先试 40%，正文过窄则回退 stack；不枚举十几个比例 |
| 图上文下的图片宽度 | 单组先试组宽的 60%，按比例、可用高度与资产清晰度收缩 |
| 正文行长 | 优先约 18–32 个全宽汉字的宽度；最终以实际测量为准，短说明不拉满整页 |
| 页总标题对齐 | 默认跟内容轴左对齐；不新增随机居中、装饰线或大面积主题色块 |

同级图片使用一致的槽位和间距，按 contain 放入，允许不同纵横比产生自然留白；不改 crop，不拉伸。放大依据有效裁剪区域的像素尺寸，而非仅依据元素原显示宽度：归一化显示尺寸原则上不超过有效像素尺寸；未知内在分辨率时不放大。小图达不到同级槽位时保留清晰度并反映在质量判断中，不能靠改 crop 或模糊拉伸凑齐。

上述策略只覆盖被确认可排的标题/正文/图片。原有受保护图形、公式、表格、强调色和图片资产不统一洗成新样式。新增 OCR 文字使用稳定的候选文字样式，应用时不得被当前画笔颜色覆盖；不额外引入整页配色重构。

### 7.4 手写物理换行与逻辑段落

“这是躺着的 / 小猫”不应因为原手写分行就永久变成两段。但不能直接删除所有 `\n`。

- 原始 OCR text 和 textFingerprint 不变；原生键入文字的手工换行默认不变。
- B 包实现显示投影机制，默认没有已批准的软换行则保持原文；C 包在同一次 structure 中提供 softLineBreaks，无额外网络请求。
- 只允许对角色明确为标题/普通正文的 OCR unit 使用高置信提示（初值 `>= 0.9`）。空行分段、列表、代码、公式、诗歌/不确定块不自动合并。
- 索引用原文中换行符的编号，不用 UTF-16 字符偏移猜测。文本被纠错后旧索引全部失效。
- 合并 CJK 软换行不插空格；拉丁词边界必要时补一个空格；不修拼写、不去连字符、不改标点。非空白字符序列必须保持，未批准的换行必须保持。
- 预览、测量和最终 TextElement 都使用同一 displayText。原文及变换列表在当前语义结果中可核对，撤销仍恢复源笔迹；不得仅预览合并而提交时恢复碎行。
- 新增文本内容检查以“rawText 经明确批准投影得到 displayText”为依据；没有投影时必须原文一致，有投影时逐个验证允许的换行变化。不得把既有准入/ReplacementGuard 改成只比较删除源集合，也不得用忽略全部空白的比较掩盖未授权变化。
- 若角色/上下文不能确认换行是软换行，保留分行。该限制不能被包装成所有手写段落重排已解决。

## 8. 候选与评分：不再让错误版面拿高分

### 8.1 有限候选，不做组合爆炸

- 初始候选家族为单列阅读、横向图文、同级组并列、保守整理，按页面内容先筛选适用家族。
- 每个家族最多两个页面级变体，总计最多 6 个完整候选；局部 group 的 stack/side 选择按确定性规则完成，不把每组选择做全笛卡尔积。
- 先做几何可行性检查，再物化、渲染；页面很简单时只有 1 个候选也正常。
- 跨骨架名称去重：签名以组成员、组内方向、组间位置关系、有效字号档为主，忽略候选名称和无意义小偏移。复用并扩展现有 `LayoutStructureSignature`/deduplicator，不另建第二套排名器。
- UI 最多保留 3 个真正不同的候选，不为凑数保留几乎相同的版式。

### 8.2 硬约束先于软评分

以下失败直接拒绝该候选，不能用其他高分抵消：

1. 应参与源缺失、重复消费、保留源被修改，或替代元素映射不完整。
2. 必须可见的图片缺失/错误裁剪，文字实际溢出/裁切，非设计重叠遮挡。
3. 已确认图文关系被拆开、穿插了无关组，或组内排列与声明的 layout intent 不符。
4. 组间/栏间阅读顺序逆转，章节成员交叉，标题孤立到错误章节。
5. 样式或坐标在实际应用时与验证候选不同；旧代次、旧场景的候选继续应用。

对不支持/已保留源的原有问题不制造“原稿也不合格，因此无法打开预览”的死局：硬检查区分本轮改写范围、固定障碍与原有场景；不能新增冲突，也不能把原有异常算作本轮改善。

### 8.3 必须补齐最终场景校验接线

`CandidateGateInput` 增加该候选需要满足的组/阅读关系；materializer 的成功产物增加 block 到实际 output element 的确定性映射。不要在校验层根据文本相同或 ID 前缀猜对应元素。

`ValidatedCandidatePipeline` 将期望映射到真实元素后传入提取器。提取器从 reduced Scene 和 render snapshot 取真实框，分别检查：

- stack：图文间距在容差内，有预期的水平对齐/重叠，不被其他组插入。
- side：左右关系正确，存在足够纵向重叠，间距在容差内；不能继续要求“文字必须在图片下方”。
- peerGrid：成员组保持完整，按行/列声明顺序阅读；不使用全局按 y 排序代替列/组阅读序。
- heading-next：标题与对应首项相邻；不是无限制 keepWith 传递。
- fixed/native：已有组合闭包保持；语义组不能迫使其内部变形。

期望数量和被实际检查数量必须相等。缺少应有的映射/期望记为失败，不再因空数组得到“关系满足率 1”。候选的语义 revision、scope、策略版本、映射及关系摘要绑定在同一验证结果中，commit 前沿用现有新鲜度检查。

控制器的 `applyDefaultStyle: false` 修复限于 V3 gateway。补“画笔激活/文本工具激活/选择工具激活”三种状态下的实际应用测试，比较文本、字体、字号、颜色、坐标、图片裁剪，并验证 undo/redo；不是只比较预览 patch 的两个副本。

### 8.4 软评分的第一版取舍

继续使用现有评分框架，修正维度定义和输入事实，不引入第二个 AI 打分调用。几何、可见性、实际字号/行高与文本框信息取自同一 reduced Scene 和 render snapshot；placement 只提供意图及溯源，不能用计划位置替代最终结果。先采用以下权重作为校准起点：

| 维度 | 初值 | 要测的实际效果 |
| --- | --- | --- |
| 图文组织 | 0.25 | 已确认关联的组内距离、形态、共同说明只出现一次 |
| 阅读顺序 | 0.20 | 组/章节/列表连续性，实际坐标下的阅读路径 |
| 层级与可读性 | 0.20 | 标题正文层级、最终字号、行长、软换行后的实测结果 |
| 对齐与节奏 | 0.15 | 共享轴线、同级组一致性、组内/组间间距区别 |
| 留白与视觉平衡 | 0.15 | 内容盒二维分布、组之间的空洞、页面重心；非最下方元素位置 |
| 修改成本 | 0.05 | 保守程度作为接近时的偏好，不能压倒明确的组织改善 |

维度必须区分 `evaluated / notApplicable / unavailable`。纯文字没有图文关系属于不适用，参与权重重归一；页面有图文却没有可用关系，不能假装不适用给出满分，须报告分析不足并限制为保守推荐。关键语义/渲染指标不可用时不授予“智能推荐”状态。

适用性由同一输入语义文档及分析状态决定，不能由各候选自行删去难满足的关系再重新计算分母。原稿与候选只在共同可比较维度上比较，并单列缺测项。

不使用统一“占满 60% 才好”的目标惩罚短笔记。留白评价以可读尺度、内容类型和组间节奏为前提；不可通过把一个块挪到页底提高密度。

新分数是候选之间的相对排序，不是准确率或用户满意度。详情展示简短理由，如“两组图文各自相邻、字号统一”；不把 0.99 包装成效果保证。

### 8.5 原稿基线与无须调整

原稿作为只读比较基线，不伪装成一个修改 patch，也不参与“新增候选数”。现有 no-op veto 仍可排除无意义修改候选；如果没有候选相对原稿产生明确改善，复用面板增加“当前布局已较合理，可保留原样”的状态。

原稿比较用相同的可适用视觉指标和源映射；旧手写与新文字的表示不同，不能单凭文字层缺失判原稿不合格。完整可比较时，初始采用 0.05 的归一化质量改善作为推荐阈值；不可比较时不编造差值，显示可预览候选但不给“优于原稿”结论。阈值只在开发样例统一校准，禁止按样例 ID 特调。

## 9. 纠错、重跑与失败行为

- 角色、顺序、图文关系纠错继续更新 `SemanticDocument`，通过现有 `runFromSemanticAssembly` 重建组与候选；不重新 OCR，不伪造识别 response。
- 新 mediaGroup 的关系编辑在现有 set-relations 语义中一次性更新整个关系组件，完成校验后再替换文档；不能只改 legacy relatedFigure 而留下 composition 副本。
- “保留原件”影响整块/必要闭包。其所在 mediaGroup 重新评估：可将全组保留，或取消仅属建议的关联；不能搬走文字却仍声明与原位图片成组。
- `AffectedSourceSet` 保留 regionIds/strokeSourceIds/renderAssetKeys/cropKeys 契约；纯语义纠错不使未变化图片资产失效，但使受影响组、章节布局、关系检查及候选失效。
- regionId/unitId 的既有生成规则不改。新 groupId 从排序后的成员 ID 和类型确定性派生，成员不变可保持身份；语义 revision 单独绑定，改变顺序/角色仍使旧布局失效。局部 ID 不能跨新代次盲用。
- 缓存键至少包括原文/资产指纹、语义 revision、可用宽度、字体/字号/行高、composition policy 版本；不引入新常驻缓存服务。
- 显式重新分析才捕获新场景、生成新代次；切换候选和纯排版重算零模型调用。迟到响应不能覆盖已纠错关系。
- 页面编辑、取消、离页、应用/撤销后释放旧渲染资源。放不下、缺资产、模型失败仅影响相应范围，其他安全组件可以给出“部分整理”候选；没有安全改善则保留原样。

## 10. 四个实施任务包

任务包内部按自然修复点分批提交，不建立逐项机器 manifest，不为每个子步骤派审核代理。建议实现分支 `feature/v3-semantic-composition`，执行前重新核对 main 和工作树，不打断其他任务。

工程量用相对大小表示：A 中、B 大、C 中大、D 中；B 是主工程，不能把它当成调整几个权重。以下子步骤是一个任务内的检查清单，不是额外独立任务。

### A. 页面范围、最终验证与应用一致性

**依赖：**当前 main 即可。**成果：**排进去的对象可解释，错误关系不再静默通过，预览与应用一致。

实施：

1. 追踪本次猫图；实现 §5 的统一 scope 和异常范围说明，补对应回归。
2. materializer 产出 block-output 映射；wiring 把关系/阅读期望接入最终场景校验。先覆盖现有纵向布局，B 再加入新的 layout intent。
3. 修复 V3 gateway 默认样式覆盖；验证创建工具状态不污染候选。
4. 保持识别账本准入权威、patch 账本物化真值和 ReplacementGuard；验证状态一致，而非仅比较源集合相等。

主要修改：`snapshot/`、`session/smart_layout_real_wiring.dart`、`patch/candidate_patch_materializer.dart`、`validation/`、`gateways/smart_layout_editor_gateway.dart`，及相应测试。

完成标准：两图控制样例全部进入同一范围；有效他页元素不被侵入；缺映射、远距离伪 keepWith、应用变色均有失败测试；实际应用与预览属性一致、撤销可恢复。真实猫图未复现时如实标记，不能据控制样例宣告其根因已修复。

建议自然提交：范围闭环一批；最终校验及应用一致性一批。这个检查点可安全暂停或换上下文。

### B. 让“双图双说明”真正排得好看

**依赖：**A。**成果：**不新增模型调用，现有图文关联直接获得有组织的构图。

实施：

1. 分离 mediaGroup、章节/标题依附和原生闭包，不再把所有关系合成同一种大原子组。
2. 实现 stack/side 两种组内测量与放置，接入既有流式外层；短同级双组可并列。
3. 接入统一尺度、图片槽位、间距梯度和字体策略；所有结果用真实测量物化。
4. 实现显示文本投影边界和测试，默认保留没有批准提示的原始换行。
5. 扩展渲染关系检查与跨名称去重；候选总量限制为 6，面板最多 3 个。
6. 当部分元素保留时，以其原位作为障碍和关系上下文；不输出“说明搬走，图片不动”的伪完整结果。

主要修改：`composition/layout_block.dart`、`composition/layout_block_assembler.dart`、`composition/layout_composition_planner.dart`、`placement/`、`design/`、`metrics/layout_structure_signature.dart`、`patch/` 及 wiring。

完成标准：猫狗等价控制页必须产生“标题 + 两个完整图文组”的实际可编辑场景；两组同级、图文邻接、字号可读、图片保留比例和裁剪、无重复正文。窄页回落 stack；长说明不挤成窄列；相同画面不同 zoom 不改变结果。须查看渲染图，不仅断言几何坐标。

建议自然提交：组内布局一批；尺度/文本投影/候选接线一批。**A+B 是第一轮可交付试用范围**，可先验证视觉收益再做 C，但不能宣称全部计划完成。

### C. 章节、多图共同说明与同轮语义扩展

**依赖：**B 的组表示稳定。**成果：**从双图示例拓展到日常混合笔记，不靠硬编码特例。

实施：

1. 按 §6.2 双端增加 composition 能力，旧客户端响应键集不变；新模式只有一个图文关系权威。
2. 章节一层归属、页面意图、多图共同说明映射到既有 SemanticDocument；列表仍用已有 listGroups。
3. 接入软换行提示：检查原文指纹、角色、编号和字符守恒，将同一 displayText 用于测量/预览/应用。
4. 完成 2–4 个同级组、长短混排、图片与列表说明的确定性布局，复杂或不确定内容保持保守。
5. 补关系纠错、保留原件、重跑、取消、缓存失效及模型不可用的闭环。

主要修改：客户端 `recognition/`、`semantics/`、`correction/`、`composition/`、wiring；服务端 `internal/layoutrecognitionv3/{dto,validate,prompts,provider,handler}.go` 按实际依赖修改，不为凑文件全部改一遍。

完成标准：一段正文对应多图只出现一次；章节不交叉、标题不孤立；低置信/冲突不强配；结构输出不能夹带正文；旧客户端/新服务端兼容，新客户端/旧服务端明确降级；纯语义纠错不新增网络请求，旧代次结果不能覆盖新状态。

建议自然提交：协议及兼容一批；章节/共同说明/换行/纠错消费一批。此处可作为第二个换上下文检查点。

### 11.2 三层验收，不能互相冒充

**第一层：离线确定性与内容安全（必须全通过）**

- 每个 fixture 的源范围、保留/消费终态和输出映射正确；文字未丢、图片未丢、正文不重复。
- 高置信关系在最终渲染坐标下全部满足；故意破坏位置/映射的负例确实被拒。
- 同一输入重复运行得到相同组、放置与 patch；不同 zoom 下结果一致。
- 新旧协议、默认样式、取消、纠错、undo/redo 和 V1 隔离测试通过。

**第二层：实际版面效果（渲染看图，不以自身分数作答案）**

逐页比较当前基线与新默认第一候选，记录五项：图文归属清楚、阅读路径自然、字号可读且有层级、同级对齐与间距、内容与留白比例。每项用差/可用/好简记，并给一句最主要原因。

初始收口要求：核心双图页五项全部达到“好”；8 个开发页中至少 6 页相对旧版明显改善，其余不退化；4 个留出页至少 2 页明显改善，其余不退化。“已排好”的页保留原样可计不退化。任何漏内容、明显误配或应用变样都不能被平均分冲淡。执行代理可以做这轮看图，不要求新增人工小组；有分歧保留对照，不伪造一致意见。

**第三层：真实模型与实机（分别记录，不混入假模型测试统计）**

- 用真实图片及原始手写跑当前 provider；逐条检查关联是否正确，报告正确/错误/未关联的实际分母。没有输出关联也计漏配，不能从分母剔除。
- 至少覆盖核心双图、交叉摆放、多图共说明三个独立页面；核心页重复 3 次，期望 3 次均正确。全部页汇总关系 precision/recall 初始目标均不低于 90%，报告样本数；小样本达标不等于普遍准确率承诺。
- 平板至少检查双图页、长文图文页、已排好页：预览可读、默认候选组织合理、应用一致、撤销/重开正确；记录字体、设备、客户端提交和后端提交。
- 缺模型访问或设备时仅该项标记未执行。用离线 fixture 继续开发，禁止伪造实机截图、真实模型响应或验收通过记录。

## 13. 性能预算和成本约束

| 项目 | 本轮要求 |
| --- | --- |
| OCR | 沿用现有分区/批次；不因布局候选增多重识别 |
| structure | 每次分析至多一个逻辑 structure 请求；新增提示放同一次请求 |
| 总调用预算 | 保留 `RecognitionBudget` 当前上限 16、180 秒总时限及现有重试规则；这是保护上限，不是目标调用次数/目标延迟 |
| 典型短手写图文页 | 目标仍为 read + structure 两次调用；原生文字页可无需 read |
| 图像与结构上限 | 保持当前概览长边 2048、2MP、3MiB base64 预算及 128 units/每 unit 2000 runes 上限；超限不静默截断正文 |
| 本地候选 | 最多 6 个；只渲染通过快速可行性检查者，尽早释放淘汰项 |
| 本地耗时 | 在同机同字体和固定样例上测量；初始目标普通页 p95 ≤ 1 秒、最大样例 ≤ 2 秒，不用额外模型审美循环弥补算法缺陷 |
| 重排/切候选/语义纠错 | 复用识别结果，零额外 OCR/structure；显式重新分析除外 |

性能对比必须先测当前基线，再测新实现，固定页面与设备、至少 10 次本地候选运行，报告中位数及最大值；不足以可靠估计 p95 时不要声称达成 p95。线上模型耗时另列，不把波动都算到布局算法。

不默认接入在线视觉评审器。若本地评分在留出页持续无法预测明显坏布局，先记录失败模式修正评价事实；只有确认一次额外视觉调用有稳定收益且用户接受延迟后，另立小项评估，不作为本计划前置。
