# 源码授权范围与第三方许可核对

> 当前方案：用户后续选择采用官方 PolyForm Noncommercial 1.0.0，接受不一概禁止非商业参赛。下述初版定制许可的实施记录属于变更历史，以文末的现成许可调整记录和当前根 `LICENSE` 为准。

## Context

用户希望限制未经授权的商业二次利用及直接作为他人参赛作品提交，并已要求检查、分析后修改。基于合并 PR #95 后的 main `1b955b32` 创建 `docs/source-license-policy`，不混入 CI 优化分支。

当前根目录未设置统一 LICENSE；产品用户协议不等同于源码许可证。编辑器包含上游 markdraw 代码，另有 vendor、Go 本地替换、字体、扫码库及演示素材的原始授权，不能整仓覆盖为自有代码。

## 实施方案

1. 核对 Git 历史、现有授权文件、锁定依赖、直接引入的代码与素材；按已验证事实记录来源和限制，不将作者列表作为完整权属证明。
2. 为有权许可的原创部分添加受限源码许可，允许约定的学习/非商业开发，普通应用使用及用户内容不受源码限制；商业二次利用和作为参赛作品提交需书面授权。
3. 排除第三方材料和既有许可；保留法定例外、既有授权、用户内容和赛事正常评审。明确源码可见不等同于 OSI 开源，不使用 MIT/AGPL 等标识冒充新许可。
4. 补齐第三方来源与发布注意事项，衔接 README、文档入口、用户协议和维护约定；不擅自升级依赖、修改核心功能或追溯变更历史版本。

## 验证

本轮以授权文本、实际来源、依赖清单、链接/路径、保留的上游许可及 diff 核对为主。仅增加文档或声明不跑 Flutter 全量测试，不把检查等同于律师意见、全量发行包审计或新增实机/发布证据。记录无法从仓库证明的权属与外部材料边界，完成后提交可审阅的变更。

- 新增根 `THIRD_PARTY_NOTICES.md` 和日期化依赖清单，核对 186 个 Dart/SDK 包、43 个 Go 声明依赖的许可文本；Linux 服务入口实际使用其中 39 个 Go 模块。Go 完整模块图另有 213 个未缓存的开发/测试工具依赖未逐项核查，不计入已核对范围。
- Git 记录确认内置 markdraw 来源，保留 MIT 原文，纠正当前 README、架构与需求文档中“完全自研”的误导描述。引入记录不等于上游精确版本或所有贡献者的版权转让证明。
- 新增 App/Server `NOTICES`，收录原创许可及相应第三方完整通知；保留字体原始元数据中的许可及 KaTeX 字体单独的 MIT 文本。Go 标准库、本地替换子组件也单列保留。两份通知固定 LF，避免破坏 Flutter 的多组件解析。

- 未修改或删除上游许可证、vendor 实现、锁文件、字体、模型及原生二进制，未升级依赖、改动协作功能或触发部署。

### 未消除的权属与来源问题

1. 鸿蒙 `libsqlite3.so` 仅确认仓库引入记录和版本字符串；维护者记忆为“可能来自 SDK”，仍没有可复核的供应/构建记录。本次排除在根许可之外，保留原文件，下次再分发前补证或从可信来源重建。
2. Android Zipformer 模型有上游下载说明及声明 Apache-2.0 的模型卡，但本地权重尚未逐文件匹配上游校验和，未恢复原下载包的随附授权；SDK 的 Apache 许可不能替代权重核查。
3. 未建立全部贡献者、学校/单位的完整权属链或商业转授权协议。新的限制不能套给上游 MIT/OFL 等材料，正式发布与对外商业/参赛授权前应核对团队授权能力并安排法律审阅。

以上声明用于如实记录许可边界，不宣称仓库全部权属或发行合规问题均已解决。
