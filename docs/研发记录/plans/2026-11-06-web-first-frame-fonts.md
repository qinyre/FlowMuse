# Web 首帧字体优化

线上冷启动瀑布显示 Flutter 在首帧前等待所有字体。FlowMuse Sans 的 400、600 和 700 字重各占约 1.5 MB 压缩流量，最后一份在约 31 秒时才下载完。

Web 发布包首帧仅注册 400 字重。首帧光栅化后，再补齐 600 和 700 字重。三个字重的原始文件仍随包发布，普通构建和原生端沿用现有字体声明。

Chrome 限速对照发现，提前请求常规字体会延后主脚本和 CanvasKit 的下载。CanvasKit 还会等待 Google Fonts CDN 的 Roboto 回退字体，一次未成功的请求耗时约 10.6 秒。发布包把 Roboto 放在本站，并在字体清单声明它。

## 验证结果

使用同一份 Web 发布构建，通过本地 gzip 静态服务器访问 `/library`。每次用全新的 Chrome 配置，模拟约 5.2 Mbps 下载带宽和 80 ms 延迟。

| 测试场景 | 原清单 | 优化清单 |
| --- | ---: | ---: |
| Roboto CDN 正常响应 | 19.7 秒 | 16.2 秒 |
| 模拟 Roboto CDN 请求等待 17 秒后超时 | 27.1 秒 | 16.0 秒 |

首帧前 FlowMuse Sans 的压缩下载量从 4.46 MB 降至 1.47 MB。优化版两个场景都没有请求外部 Roboto，半粗和粗体都在首帧后下载完成。Web 发布构建、启动和打包脚本测试、Dart 入口静态分析均通过。
