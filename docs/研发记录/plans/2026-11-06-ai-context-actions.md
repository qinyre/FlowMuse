# AI 笔记助手选区与页面入口

## 背景

当前助手发送时重新读取文字选区，仅选中手写时会回退整篇文字。PDF 页附件仅包含底图。此次实现 P0 第一项，统一界面来源和实际请求内容。

## 方案

1. 从属性工具进入「解释这段」和「整理为笔记」，从页导航进入「问这一页」。沿用助手面板，由用户确认后发送。
2. 明确区分选区、当前页、整篇文字和无笔记来源。选择时锁定文字和图片范围，重新选择可刷新。手写截图限于所选元素，当前 PDF 页截图包含已提交批注。保留手动框选作为补充来源。
3. 切换或移除范围时清除旧请求历史和待应用结果。截图失败显示原因，用户可重新选取来源或手动框选。请求准备与书写输入解耦，沿用现有取消、附件预算与动作确认。
4. 复用区域渲染、编辑器属性工具、页导航及现有 HTTP 通道。来源定位与可点击引用留给 P0 第二项。

## 验证

- 纯手写选区不会带入未选中的文字，选区快照在切页或更换选区后仍一致。
- PDF 页截图包含批注，页外文字不进入请求。
- 切换、移除和截图失败不会让旧来源进入新请求。运行助手和导航定向测试及静态检查。

## 实现记录

- 手写和 PDF 图像沿用已配置模型的视觉输入。文字选区和整篇文字可直接发送文本。
- `dart analyze lib test` 通过。Flutter 全量回归通过 2129 项，跳过 5 项。Web、平板和真实模型服务待实测。
