# 协作房间反复断开排查与修复

## 现象与证据

- Android 和 Web 协作状态在失败、连接、重连、快照恢复之间循环，随后无法实时同步。
- 生产服务没有重启；最近 20 分钟出现 184 次 WebSocket 连接记录、54 次快照 PUT 409。
- 最近活跃白板的密文快照为 1,156,131 字节；线上 Engine.IO 握手公布的 `maxPayload` 仍为默认 1,000,000 字节。
- 服务端已有协作帧和快照请求大小限制为 8 MiB，但启动 Socket.IO 时没有配置传输层大小上限。整场景重发可能在进入协作处理器前关闭连接。

## 实施

1. 复用生产 Socket.IO 配置，增加真实 WebSocket 回归：发送超过 1 MB 的二进制消息后仍可继续通信；超出 8 MiB 的消息仍应拒绝。
2. 先确认旧配置复现断线，再显式将传输层上限设置为 8 MiB，保留原 CORS、心跳及业务帧校验。
3. 跑 Go 全量测试及 vet，构建后端，保留旧镜像与配置后更新应用容器。
4. 核对公网握手上限，使用独立测试连接验证大帧和后续消息；不读取白板明文或更改已有房间内容。

## 范围

只修复后端传输层配置，不修改 LWW、加密格式、数据库、快照冲突合并和客户端状态显示。先消除重连循环，再观察快照冲突和状态变化是否仍异常。
