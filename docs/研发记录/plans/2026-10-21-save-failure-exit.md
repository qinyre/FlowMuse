# 鸿蒙白板保存失败与退出受阻排查

## Context

起点：`main` / `cbeca2cb`；分支：`codex/fix-save-failure-exit`。
鸿蒙平板手写后持续显示保存失败，重试无效，返回也被阻止。USB 真机日志确认保存链路抛出 `ParallelWaitError`；现有日志仅打印聚合错误类型，无法区分场景写入与封面生成失败。用户确认当前测试笔迹无需保留，允许更新诊断版本重启应用。已有平台插件注册生成文件改动不属于本任务。

## 需求

- 定位真正失败的保存阶段，避免凭截图认定数据库或渲染故障。
- 场景保存成功不应因辅助封面失败误报丢失；真正写盘失败仍须保护草稿。
- 保存恢复后返回可离开页面，不绕过未保存内容保护。
- 不新增依赖，不修改 Excalidraw 格式、协作协议或数据库 schema。

## 实现方案与关键文件

1. 在 `whiteboard_page.dart` 拆解聚合保存错误，日志仅输出阶段、异常类型、SQLite 错误码和调用栈，不记录 SQL 参数、笔迹或密钥。
2. 真机复现确认失败阶段后，在实际责任模块修复；复用现有 SceneRepository、LibraryRepository 和文件导出能力。
3. 在对应测试目录补充失败与恢复回归，检查串行保存、最新修订状态与真实路由返回。

## 验证方案

- 修改前真实页面工作流测试：13 项通过。
- 修改后运行相关测试、`flutter analyze --no-pub`、全量 `flutter test --no-pub`、`flutter build hap --no-pub`。
- 真机确认书写、重试、返回和重开；自动化与真机证据分别记录。

勘察 → 脱敏诊断 → 真机定位 → 最小修复 → 回归与文档同步。

## 排查结论与实现

- 旧版本真机日志重复报告 `ParallelWaitError<(void, Uint8List?), (AsyncError?, AsyncError?)>`，证明场景/封面并行步骤至少一项失败；原日志没有内部异常，不能据此宣称数据库损坏、磁盘不足或某个具体笔刷故障。
- 仅增加诊断后重新安装，用户反馈重新书写可以自动保存，原始触发条件未再次复现。重启后的恢复不能作为根因已修复的证据。
- 将自动保存中的正文持久化编排移入 `view_models/local_draft_persistence.dart`，沿用两个现有 Repository。立即接管封面 Future 的错误，前次失败不阻塞后次重试；正文失败保留原始异常，避免聚合异常掩盖阶段。
- 正文写入为关键步骤，封面/封面元数据为辅助步骤；渲染异常不清空旧封面。读取刷新结果使用 `asData?.value`，避免列表查询错误把正文成功误判为保存失败。
- 保存/退出错误提示共用本页一个通知，重试成功关闭旧提示；通知自然关闭或被用户操作关闭后清除句柄，避免再次关闭失效通知。
- 未改变场景 JSON、数据库 schema、协作协议、平台分发或原生代码。相同保存策略适用于所有端；其他端未做真机验收。
