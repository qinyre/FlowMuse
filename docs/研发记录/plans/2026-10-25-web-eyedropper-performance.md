# Web 取色笔持续卡顿修复

## 背景与已确认路径

用户反馈 Web 点击取色笔后，进入取色模式持续卡顿。基于最新 main `efa1637`，在 `fix/web-eyedropper-performance` 修复。

当前 `ColorPaletteOverlay._onPointerMove()` 对每次悬停、移动或按下异步调用 `MarkdrawController.sampleColorFromImage()`；后者每次执行整张截图的 `toByteData(rawRgba)`。1920×1080 图像每次读取约 7.9 MiB，快速移动还会并发读取，旧结果可能覆盖新预览。截图虽已缓存，像素读取并未缓存。

## 最小实现与范围

- 沿用当前画布截图、调色板与画布坐标换算。每次进入取色只读取一次 RGBA，随后在像素缓冲中同步查色；移除仅此入口使用的异步采样回调及控制器方法。
- 像素缓冲由弹层会话持有，图像在读取完成后释放；退出、取消或销毁后释放缓冲。代次隔离迟到的截图/像素结果，防止重新激活后被旧会话覆盖。
- 按抬起位置确认颜色，画布外不沿用旧预览。准备期间可取消；读取失败恢复普通调色板，保持原颜色。
- 检查桌面/紧凑工具栏、属性面板、背景色选择器、鸿蒙 Pen Kit 降级调用与测试。原生全局取色、后端、Scene/History、加密与数据库均不变，无新增依赖。

## 验证

- 用可计数的图像验证连续悬停/拖动只读取一次；验证正确色值、画布偏移、边界、抬起位置及重入后刷新快照。
- 覆盖准备中取消/销毁、读取失败和旧会话迟到，检查图像释放及不误选色。
- 运行相关及完整 Flutter 回归、静态检查、Web release 构建；在独立浏览器的合成画布上验证持续移动取色，不读取用户笔记。
- 软件测试不能替代用户原浏览器、原笔记的最终体验确认；本轮不更新平板。

## 实施与验证回执

- 调色板每次进入取色只读取一次 RGBA，同步查像素；原图在准备结束的 `finally` 释放，退出/销毁时清空缓冲。准备中的重复激活被阻止；取消、重入及销毁按代次丢弃迟到结果。
- 抬起按最终位置查色，画布外不选旧预览；边缘像素用所属格而非四舍五入。准备期间的快速点击在像素就绪后确认，取消会清除待选位置。截图/读取失败保持原颜色并回到可操作的普通调色板。
- 初始 5 项回归在未修改实现时均失败：连续悬停/拖动发生 201 次整图读取，抬起位置误取旧颜色，画布外抬起仍选色，取消及销毁时迟到图像未释放。修复后通过，进一步补充至 13 项，覆盖失败、快速点击、重入及异步资源释放；加上原生取色 channel 的 4 项，共 17 项通过。
- 完整 `flutter test --no-pub --reporter expanded`：1990 项通过，5 项原有跳过。之后仅整理多余 import 与花括号，相关 17 项复跑通过；最终 `flutter analyze --no-pub` 无问题，`git diff --check` 通过。
- 使用正式相同的服务地址、湿墨分层与实时墨迹 V2 开关，`flutter build web --release --no-pub --base-href / --pwa-strategy=none --no-web-resources-cdn` 构建成功。

### Chrome release 对照

独立临时浏览器、本地静态服务器和合成笔记，不读取用户配置或已有笔记，不连接生产协作房间。旧包主脚本 SHA-256 为 `557d1a720cda7fa5f4300443a9ae8fc2c0a8fe3815f074565ed9ee90c26c4ff6`，对应已发布的 `b500c60`；新版是本次修复后的 release 构建。

| --- | --- | --- |

| 含准备阶段的整张截图读取 | 121 | 2 |

当前 Flutter CanvasKit 的 `Picture.toImage()` 内部有一次整图读取，新版另一次为一次性 RGBA 转换；这两次均在准备阶段。308×408 自动封面另计，不计入取色截图。读像素次数减少不等同于帧率按相同比例提升；浏览器使用 SwiftShader，本记录不代替真实设备体验验收。

开启可访问性并创建合成笔记时，两个版本均记录到一条已有 Web 文本输入路径的初始化异常；本次不声称修复该问题。调色板十六进制文本的可访问性 DOM value 为空，但画面正常显示色值；选色成功通过点击后弹层退出验证，具体像素颜色由 widget 回归覆盖。
