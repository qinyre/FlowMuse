## v2 修订引入的新问题（对抗复核）

### [Critical] N1：§1.2.3 null 分支自相矛盾——纯文本选区点视觉快捷指令时，驻留旧选区截图仍随"解释这里"发送
- 证据：hybrid v2 §1.2.3（L42："选区为纯文本或无选区时回调返回 null，快捷指令按纯文本上下文执行（不补图）"）× §1.1（L33：`_generate` 从 `_attachments` 取值）× §1.4（L54：附件驻留跨追问）；替换规则前置条件是"当前选区含视觉元素"（L42），不含"清掉过期选区附件"。
- 问题：时序：开面板时选区 A（视觉）被自动捕获驻留 → 用户改选纯文本选区 B（hasSelection 仍真，chips 仍显示四件套）→ 点"解释这里" → 回调返回 null → 无替换、无移除 → 请求携带 A 的截图 + 指令"解释这里的内容"。这与 R1-C1 是同一缺陷经另一分支复发，且"按纯文本上下文执行"一句在附件条非空时根本无法成立——规则集在该分支自相矛盾，实现者无论怎么写都违反方案某一句。
- 建议：null 分支补一条明确规则：点击视觉快捷指令且回调返回 null 时，**同时移除（或标记过期）附件条中 kind==selection 的附件**，使"按纯文本上下文执行"为真；或在方案中声明该分支保留驻留附件并删除"纯文本上下文执行"措辞、改为"不刷新附件"。二选一，必须写死。

### [Important] N2：替换规则会无确认销毁用户手动积累的多张选区截图
- 证据：§1.2.3（L42："**替换**附件条中已有的选区来源附件"——未区分手动/自动来源）；手动「选区截图」chip 沿用 B 线 T6 追加语义（execution.md T6 `_addAttachment` L616-634 为 append；§4.1 未改此点；§4.1-4 L127 证实该 chip 存在）；`kind` 字段仅 `{selection, pdfPage}` 二值（§2 L88），无法区分手动/自动。
- 问题：合法用法"选 A 区点添加、选 B 区点添加"积累 2-3 张选区截图（比较两处公式的真实场景），之后任意一次视觉快捷指令点击把全部选区附件替换为当前选区 1 张——用户按的是"解释这里"，不是"删除我添加的截图"，属未经确认的用户内容销毁。
- 建议：为附件增加来源细分（自动/快捷指令/手动，可在 `kind` 上加 origin），替换仅作用于"自动或上次快捷指令产生的过期选区附件"，手动添加的选区附件只提示过期、不静默删除；或替换发生时在附件条给出可见的变更反馈。

### [Important] N3：附件条满额（3 张 PDF）时快捷指令刷新的配额行为未定义
- 证据：§1.1（L31）"达上限后添加入口禁用并提示"仅约束添加 chips；§1.2.3（L42）"无则加入"无配额前置检查；§1.1（L33）快捷指令仅受 `_loading/_applying/_capturing` 门控，不受配额门控。
- 问题：条内 3 张 PDF 页 + 当前选区含视觉元素 + 点"解释这里" → 刷新要加入第 4 张：拒绝则"解释这里"无当前选区图（R1-I2 的 scope 错位在满额场景复发，且此时连"补充捕获失败"的错误都不会出现，用户无任何提示）；驱逐则又落入 N2 的未经确认删除。两条路都未定义。
- 建议：明确满额时快捷指令刷新的策略与提示（建议：替换一张 PDF 之外优先提示"附件已满，移除一张以附带当前选区"，由用户决策）。

### [Important] N4：null 契约与 §1.6 总则、execution.md 验收用例三处残留冲突
- 证据：hybrid §1.6（L68）："捕获/归一化失败**不再静默返回 null**：业务失败抛 `StateError`"——与 §1.2 契约（L38"返回 null 表示……静默跳过，不展示任何错误"）字面相反；execution.md §3.4 用例 5（L818）仍期望"controller 无选中 → `captureSelectionAttachment` 抛 StateError('请先在画布选中要发送的内容')"，而 §4.1-4（L127）已把该守卫改为返回 null，§4.1 未列对该用例的修订；execution.md §3.5 用例 2（L832）断言旧文案子串"仅发送你添加的 1 张图片"、T6 代码块（L729）内嵌旧隐私文案，§4.1-5（L128）仅有笼统优先级、未枚举这两处测试期望的改写（对照：T1'/T2' 行 L112-113 都逐文件列了存量测试改写）。
- 问题：同一份方案书内 §1.2 与 §1.6 给出相反指令；execution.md 名义上是"验收清单继续有效"（L7），但其失败分支与文案断言已被 §4.1 掏空而未同步——执行者按验收清单跑测试会撞墙，或按 L68 把 null 守卫写回抛错、复活 R1-C3。
- 建议：L68 补例外（"无视觉选区的守卫 null 除外，见 §1.2 契约"）；§4.1 增补两条：execution §3.4 用例 5 改"无选中 → 返回 null、无消息"，§3.5 用例 2/T6 文案块的期望子串随 §1.5 v2 改写。

### [Minor] N5：粘性标记在 v2 规则集中不可达，成为死状态
- 证据：§1.2.1（L40）被动捕获仅在开面板触发一次；§1.2.2（L41）粘性抑制"开面板路径的被动捕获"，但同句又规定"关闭面板重开视为新会话"；会话内无任何其他被动再触发路径（1.2.3 为主动且明确不受抑制，T5' 已移除 `_generate` 内联重捕获）。
- 问题：开面板捕获每会话只发生一次，粘性标记所能抑制的事件在置位之后不存在——规则无可达效果，却要求"面板记录其引用"（L41）的额外状态。要么删掉简化，要么说明它防御的是哪个未来触发点。
- 建议：删除粘性标记与相关面板状态（1.2.4 的"移除后自由提问"承诺并不依赖它），或在方案中补出它实际抑制的再触发场景。

### [Minor] N6：§4.1-4 含未写完句，且兜底提示文案归属含糊
- 证据：§4.1-4（L127）："（该文案保留给**……**无选区路径不再可达，主动添加 chip 的失败兜底由 T6' 以空附件+提示呈现）"——省略号显示编辑残留；§1.6（L76）又把"请先在画布选中要发送的内容"标注为"选区路径，主动添加时"的文案。
- 问题：修订指令本身有残句；且手动 chip 在纯文本选区下返回 null 后展示"请先在画布选中要发送的内容"对已选中（纯文本）的用户是错误指控（用户确实选了内容，只是无视觉元素）。
- 建议：补全残句；null 兜底提示改为"当前选区没有可截图的视觉内容"一类如实文案，并同步 §1.6 行 76 的归属说明。

### [Minor] N7：T6' 新增测试用例与 §1.1 门控规则矛盾
- 证据：§1.1（L33）"`_capturing` 期间……快捷指令均禁用"；T6'（L117）"§3.5 增用例：**捕获在途点快捷指令**→发送带 1 张附件"。
- 问题：捕获在途时快捷指令已禁用，该用例按字面不可执行；实际想验证的应是 §1.2.5（点快捷指令启动捕获 → 捕获在途时点发送 → await 后带 1 张附件发出）。
- 建议：用例描述改为"快捷指令捕获在途时点发送→请求 await 后携带 1 张附件"。

### [Minor] N8：`showAiAgentDialog` 的 `hasSelection` 参数删除超出 R1-I4 裁决范围
- 证据：§1.1（L34）："……与 `showAiAgentDialog` 的 `attachments`/**hasSelection** 参数在 T5' 删除"。R1-I4 只针对快照 `attachments` 字段与附件双源；`hasSelection` 与附件事实源无关。AiAgentPanel 自身保留 `hasSelection` 参数（T5' L116 初始传参依赖它）。
- 问题：包装函数删参后 dialog 路径永远 hasSelection=false，视觉快捷指令经 `showAiAgentDialog` 不可达（该函数现仅测试使用，test/ai_agent_dialog_test.dart:426），快捷指令类 widget 测试被迫绕行直构 AiAgentPanel；且"删 showAiAgentDialog 的 hasSelection"易被实现者顺势扩大为删 AiAgentPanel 的同名参数，恰好破坏 T5' 的初始传参修复。
