## 二、v4 改动对抗检查（推演记录）

1. **第①点"无"定义闭环**：占位仅插入"无表条目且不在 `_cache`/`_failed`"的 id——已缓存 id 不再有陈旧占位；曾占位后解码完成的 id 由 `_decode` finally 清条目、逐出后 `getImage` 无条目可挡、正常重解码。三条流（loadScene 全量占位→串行取所有权、区域预热×loadScene 交错、重绘真在途×后续 markDecoding）在 v4 定义下重演全部通过；`image_cache_prewarm_test.dart` 两既有用例不受影响。
2. **T3 用例②可实现**：控制器级经 applyResult 注入 51 张小 PNG（>maxSize=50）触发逐出（沿用 §3.3 构造范式，不经 loadScene 避开自动预热竞态），或缓存级直测 `ImageElementCache` + `putImage` 逐出（先例：image_cache_prewarm_test.dart:53 独立构造缓存）。两者均无注入障碍。
3. **IEND 残余拒绝**：两条自产路径（引擎 toByteData、归一化重编码）无尾部字节，严格化无误伤；PDF 页原始字节来自平台渲染器，理论上若其输出带尾部会误拒合法页——概率可忽略且失败可见（明确文案），安全取舍正确。（信息性备注：正文称"两条生产路径"，严格数有三条——选区渲染/平台 PDF 导入/重编码，不影响结论。）
4. **overlaps 判定**：`Rect.overlaps` 为非零面积重叠，页边相切判"不在页内"语义正确；与 §1.3 成功路径（best-overlap 选页）组合后视口跨两页时取面积大者，合理。
5. **T5'/C3 提交边界收窄**（v4 新增，R2-X1 裁决吸收）：C3 不触 dialog——快照 `attachments` 字段恒空保留至 C4 一并删除，`_openDialog:432` 传参点与 :338/:386 断言改写同在 C4，C2→C3→C4 全链编译连贯（C2 已把存量构造点改三参直构，C3 删 `buildAiVisualAttachment` 时其 3 个行为用例同步迁 §3.4，无悬空引用）。
6. **§1.2.2 替换计数中性**（v4 新增）：移除旧槽+加入新槽保持总数 ≤3，与 §1.1 上限不变量一致；满额×槽占用不再阻塞刷新，消除"过期槽图随指令发送"的另一种形态。

## 三、新发现

### [Minor] M1. 快捷指令捕获失败路径的活动槽处置未定义——与 §1.6"本次发送将以文字上下文为主"文案存在口径差

- 证据：v4 §1.2 表（:45）快捷指令失败分支仅"`_error` 展示 + 追加后果说明"；§1.6（:82）该文案承诺"本次发送将以文字上下文为主"；§1.2.5（:58）发送以当前 `_attachments` 继续。三处组合：捕获失败时活动槽旧图**未清除**（无任何条款要求清除），随后的发送将携带该过期截图而非纯文字。
- 问题：行为（发送含过期槽图）与文案（"以文字上下文为主"）不一致。缓解因素：附件条常驻可见 N=1、可手动移除，用户有最后一次知情机会，且"为主"措辞含糊——故仅 Minor。
