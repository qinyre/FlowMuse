# R1 产品交互审查（第一轮）

审查对象：`docs/研发记录/plans/2026-08-21-ai-visual-attachment-hybrid.md`
对照材料：A 线 phase1/phase2、B 线总体方案与 execution T6、`ai_agent_dialog.dart`、`whiteboard_page.dart` 现行代码。

核对说明：§2 声称保留的 A 线壳（阶段态 preparing/generating、异步 contextProvider、选区快捷指令、平板 420 宽面板）经代码核对属实（ai_agent_dialog.dart:28/25/504-517，whiteboard_page.dart:612-614）。

## 结论：可行但需修订

## 发现清单

### [Critical] 选区变化后驻留附件过期，快捷指令"空条才补充"导致"解释这里"携带旧图发送
- 证据：hybrid §1.2.3（L38："若附件条为空且当前选区含视觉元素 → 即时捕获加入"）× §1.4（L47：附件驻留跨追问复用）；§6 风险表（L108）缓解措施"快捷指令才强制补充"；ai_agent_dialog.dart:504-524（chips 仅 `_fillInstruction` 填文案，不触发任何附件刷新）。
- 问题：面板是画布上的 Overlay，用户可在面板开着时改选区。时序：开面板时选区 A 被自动捕获驻留 → 用户改选 B → 点"解释这里" → 附件条非空故 1.2.3 不触发 → 请求携带 A 的截图 + sourceLabel"当前选区" + 指令"解释这里的内容"，AI 解释的是 A 不是 B，且标签向用户谎称这是"当前选区"。唯一刷新手段只剩用户手动移除后再点快捷指令。§6 的缓解表述（"快捷指令才强制补充"）与 1.2.3 的空条前置条件自相矛盾——快捷指令恰恰在条非空时最需要补充/刷新却不动作。
- 建议：定义附件与选区的失效语义。三选一：(a) 视觉快捷指令点击时对"选区来源"的驻留附件执行"替换/刷新"而非仅空条补充；(b) 选区变化时（contextProvider 可感知）给选区来源附件打"已过期"角标并在发送前提示；(c) 至少把 1.2.3 改为"若附件条中无**当前选区**的附件则补充"，并同步修正 §6 缓解措辞。融合时未考虑的第三选项——附件条内嵌"实时镜像当前选区"chip（随选区更新、不可手动删除只可整体关掉）——比"开面板一次性快照 + 驻留"更贴合 A 线"选中即意图"的哲学，建议一并评估。

### [Critical] 粘性移除（1.2.2）与快捷指令强制补充（1.2.3）组合成"打地鼠"，"删不掉"体验在 flagship 流程中复活
- 证据：hybrid §1.2.2（L37："用户手动移除自动加入的附件后，本次面板会话内不再自动重新加入（避免'删不掉'的体验）"）；§1.2.3（L38："点击视觉类快捷指令……即时捕获加入"——无粘性豁免、无前置排除）；§1.2.4（L39："用户可一次性移除后自由提问"）。
- 问题：用户删掉自动附件（明确表达不发图）后点"整理文字"，截图被"强制"加回；再删、再点另一个 chip，再加回——无限循环。两条规则对同一状态（用户已移除）给出相反裁决，方案未定义优先级。1.2.4"一次性移除后自由提问"的承诺只对自由输入成立，对四个快捷指令全部失效；而快捷指令恰是 A 线胜出的核心理由。两个实现者会做出相反行为（查/不查粘性标记），用户侧则重演 1.2.2 要避免的体验。
- 建议：明确粘性标记对 1.2.3 的抑制关系（建议：粘性命中时快捷指令不再补充，同时指令文案自动降级为纯文本变体，或 chip 点击时弹出"是否附带选区截图"二选一）；若坚持"点击即同意"，则必须把 1.2.2 改写为"不再**被动**重新加入"并披露快捷指令例外，且补充"再次移除后同一会话内不再由快捷指令加回"的二次粘性规则。

### [Critical] §1.2.1 自动捕获前置条件在"面板驱动捕获 + 回调契约"下不可表达，字面实施会在纯文本/无选区开面板时弹出错误横幅
- 证据：hybrid §1.2.1（L36：条件是"选区过滤 !isDeleted 后**含非文本元素**"）；§2 whiteboard_page 行（L66：只传 `onCaptureSelection`/`onCaptureCurrentPdfPage` 两个捕获回调，"捕获时机由面板驱动"）；B 线 execution T6（L605-606：回调签名 `Future<AiVisualAttachment> Function()?`，非空返回）；B 线总体 §2（L70：捕获失败"一律抛 StateError"）；hybrid §1.6（L55：业务失败抛 StateError 写入 `_error` 展示）。
- 问题：面板不知道选区构成。按方案给定的契约，面板开面板即调 `onCaptureSelection`，对纯文本选区/无选区的用户，回调只能以抛错表达"没有可捕获内容"，而 §1.6 规定错误必须展示——结果是每次纯文本开面板先看到"请先在画布选中要发送的内容"横幅。要实现 1.2.1 的"含非文本元素才捕获、否则静默不动作"，必须修改回调契约，但方案未定义任何"无可捕获内容→静默跳过"的信号通道（异常被 1.6 征用为用户可见错误）。
- 建议：为自动捕获增加独立的前置查询（如 `Future<bool> hasVisualSelection()`）或让捕获回调返回可空/结构化结果（null = 无视觉选区静默跳过；StateError = 真失败）；并明确"自动捕获路径的跳过不展示错误，仅真失败展示"。

### [Important] 打开面板时自动捕获的生命周期未定义：失败展示、粘性置位、捕获中占位、与用户抢先发送的竞态
- 证据：hybrid §1.2.1（L36）、§1.1（L32：仅规定 `_loading || _applying || _capturing` 期间**添加/移除**禁用）、§1.6（L55）；ai_agent_dialog.dart:246-262（`_generate` 无 `_capturing` 检查）、:522-524（快捷指令 chips 仅 `_loading || _applying` 门控）。
- 问题：(a) 开面板自动捕获失败（如"图片解码失败，请重新打开笔记后重试"）时错误横幅是否在用户未做任何操作前弹出？弹出则体验敌意，不弹则静默降级经后门回归、与 §1.6"反转静默降级"冲突。(b) 自动捕获失败后粘性标记是否置位？置位则后续快捷指令补充是否被抑制，未定义。(c) 捕获进行中附件条是否显示占位、发送按钮是否阻塞未定义——用户开面板即打字点发送，请求先于捕获完成发出（不带图），随后附件才出现，"发送前始终可见"的知情承诺在该窗口落空。(d) `_capturing` 期间快捷指令 chips 未禁用，chip 触发的补充捕获与开面板自动捕获并发，同一选区可能重复占两个附件位。
- 建议：定义自动捕获为面板打开的显式阶段（占位 UI + 发送禁用或排队）；失败时以附件条内联提示（非全局错误横幅）呈现；明确失败不置粘性、留待快捷指令重试。

### [Important] 快捷指令补充捕获失败后，已填入的视觉指令仍可发送，降级上下文是"整篇笔记文本"，AI 答非所问
- 证据：hybrid §1.2.3（L38）、§1.6（L55："不打断纯文本路径"）；whiteboard_page.dart:658-663（无选中文本时 texts 回退**整篇笔记**文本元素）。
- 问题：用户选纯手写内容点"解释这里"→ 补充捕获失败（错误横幅）→ 指令框已填"解释这里的内容"→ 用户点发送 → 无附件、texts 回退整篇笔记 → 模型对整篇笔记做"解释这里"。scope 完全错位，且用户无从察觉错在没图。方案只规定"错误不打断纯文本路径"，未规定视觉指令在图缺失时是否可发、如何提示。
- 建议：补充捕获失败时对该次发送给出明确选择（阻断并引导重试/移除指令，或显著提示"将以文字上下文发送，可能无法针对选区回答"），至少在错误文案中追加后果说明。

### [Important] 隐私文案"仅发送你添加的 N 张图片"与自动捕获/强制补充行为不符；B 线定稿文案未针对新交互模型复审
- 证据：hybrid §1.5（L51："仅发送你添加的 N 张图片"）、§1.1（L31："发送前始终可见……隐式路线获得隐私正当性的关键改造"）、§1.2.1/§1.2.3（系统自动/强制加入，非用户添加）；B 线总体 §5（L96，该文案三轮审查针对**显式添加**模型定稿）；execution T6（L726-734，文案常驻渲染）。
- 问题：自动捕获与快捷指令补充的附件都不是"你添加的"，是系统加的。文案逐句核对中此句与实际行为对不上，直接削弱 §1.1 引以为据的知情同意论证。B 线三轮审查的有效性边界止于显式模型，融合方案把文案当作"已审定资产"继承，跳过了对新增自动路径的复审。另注：§5.2"不加首次引导、附件条常驻已充分"的结论以文案如实为前提，此项不阻塞的成立依赖本条修复。
- 建议：文案改为如"仅发送附件条中展示的 N 张图片（其中选区截图可能在打开面板或点击指令时自动加入）"之类的如实表述；§5.2 的"倾向不加引导"结论在文案修复后重新确认。

### [Important] 快照 record 的 `attachments` 字段与附件条"单一事实源"并存，双源冲突未处置
- 证据：hybrid §1.1 标题（L25"单一事实源"）、§2 面板行（L65："`_generate` 改从附件条状态取值"）、T4'/T5'（L89-90：contextProvider 不再内联捕获）；ai_agent_dialog.dart:16-23（typedef 含 attachments 字段）、:263-281（`_generate` 经 `_context` 取 attachments 发送）、:591-597 与 :610-611（隐私提示行、loading 文案均读 `_context.attachments`）；A 线 phase1 测试断言 `1 张选区截图`（phase1 L652）、phase2 断言 `正在结合选区图像`（phase2 L57）。
- 问题：T5' 之后 contextProvider 返回的 attachments 恒为空，快照字段成为死数据；但面板三处 UI 与 A 线既有测试仍读它。若实现者保留双轨（_context.attachments 与 _attachments 并存），发送取哪份、隐私行/文案绑定哪份将各执一词，与"单一事实源"直接冲突。
- 建议：T6' 明确删除快照 record 的 attachments 字段（或显式声明废弃、禁止读取），并把隐私提示行、loading 文案、A 线两处测试断言的迁移列入任务。

### [Important] 现行 A 线接线缺陷被掩盖：OverlayEntry 路径未传入初始 attachments/hasSelection，视觉快捷指令与附件提示开面板时不显示
- 证据：whiteboard_page.dart:601（`await _currentAiAgentContext()` 计算了含附件与 hasSelection 的初始快照）与 :628-639（构造 `AiAgentPanel` 时只传 noteTitle/texts/truncated/label/contextProvider，**丢弃** attachments 与 hasSelection）；ai_agent_dialog.dart:123-132（initState 用 widget 默认值 attachments=[]、hasSelection=false 初始化 `_context`）、:504（chips 按 `_context.hasSelection` 切换）。
- 问题：生产路径是 OverlayEntry 直构 AiAgentPanel，不走 `showAiAgentDialog`（仅测试调用，test/ai_agent_dialog_test.dart:426）。现状：开面板时自动捕获的附件不可见、"将随请求发送 N 张选区截图"提示与视觉快捷指令在**首次发送完成后**才出现——知情提示晚于发送，恰是 §1.1 声称要修复的隐私漏洞，而它在 A 线合入代码中已经存在。融合方案 §0 把 A 线缺陷清单限于工程项（resolvedImages/泄漏/静默降级），未识别此产品可见缺陷；T5'/T6' 改造点也未包含初始 hasSelection 传参。§0"A 线交互方向胜出"的评审结论建立在一个未被发现有此缺陷的版本认知上。
- 建议：T5'/T6' 显式加入"初始快照完整传入面板（含 hasSelection）或开面板即刷新 `_context`"，并在 §0 补记该已掩盖缺陷。

### [Minor] "图片过大，请缩小选区后重试"用于 PDF 页路径时指引不可执行
- 证据：hybrid §1.6（L55：该文案通用于归一化失败）、§1.3（L43：PDF 页为整页原始位图）。
- 问题：PDF 页无法"缩小选区"，用户收到无法执行的指引。
- 建议：PDF 路径分支使用独立文案（如"该 PDF 页面图片过大，无法作为附件发送"）。

### [Minor] 0 附件时常驻隐私段落渲染"仅发送你添加的 0 张图片"，对纯文本用户是噪音
- 证据：execution T6（L726-734：文案在 `_hasAttachmentSources` 为真时常驻渲染、计数模板化；测试用例 5"隐私文案计数归 0"）；hybrid §1.1 沿用 T6；A 线 phase2 全局约束（L17："纯文本/无选区路径的现有行为与文案保持不变"）。
- 问题：纯文本用户开面板看到一段关于选区截图/PDF 页且计数为 0 的密集小字，语句本身（"仅发送你添加的 0 张图片"）不通顺；同时突破 phase2"纯文本文案不变"约束（融合后该约束理应失效，但方案未声明）。
- 建议：0 附件时折叠为一句摘要（如"发送内容以文字上下文为主"）或仅在有附件时展开全文。

### [Minor] "当前笔记没有 PDF 页面"在"笔记有 PDF 页但视口停在无限画布区"时文案不实
- 证据：hybrid §1.3（L43）；B 线总体 §2（L73：该文案对应 `pageForVisibleRect` 返回 null，即无限画布无页面，而非笔记无 PDF）。
- 问题：判定条件是"当前视口不在任何页"，不是"笔记没有 PDF"；笔记含 PDF 但用户平移到空白区时收到错误事实陈述。
- 建议：改为"当前视图不在 PDF 页面内，请先滚动到 PDF 页"。

### [Minor] `_capturing` 门控遗漏清除对话与快捷指令入口
- 证据：hybrid §1.1（L32：仅"添加/移除禁用"）；ai_agent_dialog.dart:467-469（清除对话现仅 `_loading || _applying` 门控）、:522-524（chips 同）。
- 问题：捕获进行中可点"清除对话"清掉附件（清空动作与在途捕获竞争）；chips 可点触发并发补充捕获（与 Important 第 1 条 (d) 相关，此处为门控规格遗漏）。
- 建议：§1.1 的禁用清单扩为"添加/移除/清除对话/快捷指令"。

### [Minor] 视觉快捷指令在纯文本选区下显示但点击不补充附件，预期错位
- 证据：ai_agent_dialog.dart:504-517 与 whiteboard_page.dart:713（hasSelection = 选中文本 **或** 视觉元素，纯文本选区也显示"解释这里"四件套）；hybrid §1.2.3（L38：仅"当前选区含视觉元素"才捕获）。
- 问题：行为上有兜底（纯文本选区点 chip 不加图），但方案未声明该组合态，用户可能预期"解释这里"必然带图。
- 建议：在方案中显式声明"纯文本选区下视觉快捷指令按纯文本上下文执行"，或对纯文本选区隐藏视觉指令组。
