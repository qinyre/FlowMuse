# 协作连接复用旧登录凭据

## 现象与定位

双开关 Web 测试版创建协作房间时报 `Socket.IO connect failed: unauthorized`。同一账号的多个登录会话原本允许并存；本轮没有更改后端鉴权或登录规则。

使用项目锁定的 `socket_io_client 3.1.6` 可独立复现：以旧身份创建并 dispose 根命名空间连接，再用同一无尾斜杠服务器 URL 和新身份调用 `io.io`，会拿到原 Socket，`auth` 仍是旧值。库以空路径判断命名空间缓存，但实际 Socket 位于 `/`，而 dispose 不会清除全局 Manager 缓存。

因此登录更新或退出后，后续协作连接可能继续使用旧凭据。该缺陷已复现；用户截图是否还有其他鉴权原因，仍需更新后的账号实测确认。

## 修复范围

- 沿用项目社交连接已使用的 `enableForceNew()`，每次新建协作连接时使用当前身份。
- 已连接 Socket 在同一 transport 内的换房复用与自动重连保持既有流程。
- 测试通过构造器注入 Socket 工厂，替代修改库全局缓存的旧 fixture；鉴权回归仍调用真实 `io.io` 验证缓存行为。
- 不修改服务端、协议、加密、本地数据库或持久化凭据；湿墨分层与实时墨迹 V2 的默认值保持关闭，测试构建显式开启。
