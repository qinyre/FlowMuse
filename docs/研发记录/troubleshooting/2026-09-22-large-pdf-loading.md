# 大 PDF 空白等待、频闪与滚动卡顿

用户确认 Android 与 OHOS 均可复现。修复分支：`fix/pdf-large-document`，基线 `271cb10`。

## 根因和修复

1. **导入反馈缺失**：新建笔记跳转后，渲染器先处理整份 PDF，宿主没有呈现等待状态。现在先绘制加载界面，Android/pdfx 与 OHOS/PDF Kit 均回报已处理页数，之后显示保存阶段；首屏图片预热、场景保存结束后撤去覆盖层。支持取消，失败显示提示，过期回调不能再修改已退出的页面。暂存导入绑定 noteId，避免被其他笔记误消费。
2. **缓存循环换图**：旧 `resolveImages` 每帧请求全部文件，`loadScene` 全量预热；超过 50 张后，离屏页持续挤掉可见页，重绘又请求刚被驱逐的图片。现在只请求当前视口及 200 屏幕像素的邻近范围，串行解码；跳页会替换尚未开始的请求。保留当前请求集合内的图片，不因旧请求完成而驱逐它们。可见集合与场景/视口一起复用，不在每次落笔通知中重新筛选整份图片列表。
3. **不必要的工作与资源占用**：导入阶段取消重复解码全部 PNG，保留原始字节和尺寸，只预热首屏；删除原先遗漏释放 Codec 的整份预解码路径。OHOS 每页释放 PixelMap/ImagePacker，最终释放 PDF 文档并删除本次写入的临时 PDF。静态 painter 只绘制附近页面的纸张、阴影、模板及裁剪路径，保留阴影外缘。

没有修改笔刷、压感、输入采样、PDF 图片质量、Excalidraw 格式或数据库 schema。现有 PDF 笔记重开后同样走按视口加载。

## 资源与导出边界

- 图片缓存沿用 50 项限制，增加约 96 MiB 的解码像素软预算（width × height × 4）；当前可见及邻近图片受保护，极端情况下该集合本身可超过预算。此数值不是进程内存上限，也不包含原始 PDF、压缩 PNG、序列化副本及 GPU 额外开销。
- 本轮仍逐页完成整份 PDF 的初次转换并嵌入既有场景格式，不承诺超大文件瞬时导入，也未引入原始 PDF 按页持久化的新格式。
- 封面按封面区域预热，区域导出按目标区域预热，不沿用屏幕视口作为导出范围。预热最后复核缓存，超过容量导致缺图时返回失败数，避免把灰色占位当作成功导出。既有超大区域一次性导出仍受缓存容量限制。
- 图片相交判断复用 `AlignmentUtils.visualBounds`，包含旋转外扩；既有智能排版几何冻结门禁保持不变。

## 待设备可用后验证（本轮不安装）

Android 与 OHOS 各使用实际出问题的 PDF，另选约 50 页、200 页的扫描版与文字版文档：

1. 首次导入时能持续看到页数与保存状态；尝试中途取消，再次导入可以完成。
2. 连续上下滚动、快速跳到后部再返回，静止页面不与灰框反复切换；初次进入未缓存页允许短暂加载。
3. 缩放后书写、点触、荧光笔、撤销/重做和快速退出重开，核对页数、笔迹与背景没有缺失。
4. 记录首次导入耗时、滚动 UI/raster 帧耗时和进程内存峰值；设备数据取得前，不声称已保证某个 FPS 或输入延迟。
